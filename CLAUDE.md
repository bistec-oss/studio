- **✅ 2026-08-03 — the model's chat preamble was being PAINTED onto exported posts.** Reported as "unnecessary text is printed on top" on a prod regenerate; the exported PNG carried a caption across its top edge reading _"The file write wasn't permitted, so here's the complete HTML document directly:"_ — the design model's own prose.
  - **Root cause — the reply was trusted to arrive clean.** CLI-mode design is a single-shot: every prompt says "Output ONLY … No markdown code fences, no commentary" (`prompts/shared.ts` `outputProtocol`, `prompts/refine.ts`). That run reached for a `Write` tool it was never granted (the design call passes **no** `allowedTools`), was denied, and narrated the fallback before printing the document. Nothing downstream removed it: **`stripCodeFences` is anchored** (`/^```[a-zA-Z]*\s*\n([\s\S]*?)\n```$/`) so it only strips when the _entire_ reply is one fenced block and returns the whole string otherwise, and the sanity check merely asked whether `<!doctype` appeared **anywhere** — a preamble sailed through both.
  - **What Chromium then did with it (measured, real Chrome).** `page.setContent(preamble + doc)` → the prose is parsed as a text node, **hoisted into `<body>`, and painted**; the doctype is no longer first so the document also drops to **quirks mode** (`compatMode: 'BackCompat'`); and the 1080px root is pushed to `top: 18px` in a 1098px body, so the **bottom 18 CSS px (36px at 2× export) is cropped** — which is why the footer tagline was sliced in half. After the fix: `CSS1Compat`, no stray node, root at 0, body exactly 1080.
  - **Fix.** New pure module **`src/lib/agent/htmlDocument.ts`** (`extractHtmlDocument`, 12 unit cases, no I/O): **cut** the document from the first `<!doctype`/`<html` to the **last** `</html>` instead of testing that one is present, return the surrounding text as `discarded`, and return null only when there is no document at all. `designAgentCli.ts` uses it and **logs** what it discarded (a narrating model is worth seeing); it supersedes `stripCodeFences` for HTML replies, since a fenced document falls out of the same cut. `brandkit/templateFromImage.ts` gets the same cut and now **throws** rather than saving prose as a template — a preamble stored in a Path A template would be painted onto every post generated from it, not just once. Indices are found by regex, never `indexOf` on a `toLowerCase()` copy: lowercasing can change string **length** (Turkish `İ`) and would cut the document short on non-Latin replies.
  - **Scope: this was never regenerate-specific.** `regenerate-design` → `runPathBDesign` → `runDesignAgentCli` is the same path as first generation, and **refine** calls `runDesignAgentCli` directly — one fix covers all three. Regenerate is just where the dice landed. It does make it worse though: the corrupted HTML is written to `Draft.htmlContent` **and appended as a revision**, so it survives an Undo back to that version and any later refine starts from it.
  - **🧠 Lesson: a prompt rule is not an invariant.** "No commentary" is a request; the parse boundary is the only place that can enforce it. Validate model output by **extracting what you need**, not by asserting that it's in there somewhere. Also note the mock E2E suite is structurally blind to this class of bug — `MOCK_AI` returns clean HTML and `MOCK_PUPPETEER` never rasterizes, so nothing between the model and the pixels is exercised.

- **✅ 2026-07-28 (later) — editing the copy silently broke the whole draft: one status write, five symptoms.** Reported as "delete the copy completely and the Refine design option disappears; regenerate the copy afterwards and some posts say draft not ready — fix it so we don't have to regenerate every time it breaks."
  - **Root cause — a single line.** `PATCH /api/drafts/[id]` (the copy editor's save) flipped an `EXPORTED` draft to **`IN_PROGRESS`** on any copy edit, to mean "the export is now stale". But `IN_PROGRESS` in this codebase means **"generation is running right now"**, and every consumer read it that way. One write, five downstream failures: the draft **dropped out of the library** (it filters on `EXPORTED`), **Refine design + Edit inline vanished** (both gate on `ready = EXPORTED || PUBLISHED`), **Regenerate copy answered 409 `'Draft is not ready for copy regeneration'`** — the reported "draft not ready" — clearing the copy entirely left the page on an **eternal "Writing the copy…" skeleton** with no field to type into (`copyPending = isGenerating && !copyText`), and **15 minutes later the lazy sweep marked the draft `FAILED`** with "Generation was interrupted". Nothing was ever generating, so the only escape was regenerating the whole post.
  - **Fix, three parts.** (1) The PATCH **no longer touches `status`** — copy and design are independent artifacts (the copy is the post caption, the export is the rendered image); `regenerate-copy` already left status alone (§Q TC-ASYNC-02), so this handler was the straggler. A "your export predates this copy" nudge belongs in the UI, not in the status field. (2) `copyPending` also requires **no `htmlContent`** — generation writes copy _before_ the design exists, so empty copy on a draft that already **has** a design is a deliberate deletion and must render the editable field, never an uneditable skeleton. (3) Already-stranded drafts are **healed, not abandoned**: new pure planner **`src/lib/drafts/recovery.ts`** (`planDraftRecovery`, unit-tested without a DB — same split as `inlineEdit.ts`) restores them to `EXPORTED` on read, and migration **`20260728120000_heal_copy_edit_clobbered_drafts`** repairs them in bulk because a draft missing from the library can't be opened, so the read-time heal would never fire for it.
  - **Why the heal is safe, and why it isn't time-gated.** `exportUrl` is only ever written **together with** `status: 'EXPORTED'` and `currentRevisionNumber` in one transaction (`finalizeDraftV1`, `/api/generate/export`, `commitDraftRevision`, revision restore — verified). So a draft carrying export + html + revision pointer had **finished** generating: it's a live post with a clobbered status, not a broken run. A genuinely interrupted generation has `exportUrl` NULL and is left alone. The heal therefore needs no 15-min wait (there is no run to wait for) and it **suppresses** the generation sweep — a clobbered status must be restored, never failed. Every write guards on the observed value, so a concurrent transition always wins, and no branch touches draft **content**.
  - **🧠 Lesson: don't overload a state field with a second meaning.** `status` answers "is a generation running"; "is the export stale relative to the copy" is a _different_ question and needed its own answer. Reusing the enum made five unrelated consumers wrong at once, and each looked like its own bug. Watch for this wherever one field is written to signal something it doesn't name.

## What this project is

A Next.js 14 + TypeScript web app that turns a brief into a finished, on-brand, ready-to-publish social media post (Instagram + LinkedIn). Two generation paths:

- **Path A** — HTML/CSS brand template (stored in DB), Claude agent fills it → Puppeteer renders PNG
- **Path B** — Claude agent generates freeform HTML/CSS design → Puppeteer renders PNG

Stack: Next.js 14, TypeScript, Prisma, PostgreSQL, MinIO, better-auth (self-hosted), Docker Compose. Puppeteer (headless Chromium) for HTML→PNG rendering. Claude agent harness (Anthropic SDK tool-use loop) drives design generation.

## Architecture decisions to remember

- All AI calls are **server-side only** — the browser never calls an AI API or Puppeteer directly
- **Roles are hierarchical:** `SUPER_ADMIN > ADMIN > EDITOR`; every check goes through `hasRole()` (`src/lib/roles.ts`) — never compare role strings directly. Super-admins pass every admin gate. User management (`/admin/users`) is super-admin-only; "delete" = deactivate (`User.disabled`, sessions revoked, sign-in blocked).
- **Sign-in is by username** (better-auth `username()` plugin); email exists internally only (`<username>@users.bistec.internal` synthesized for admin-created accounts). Seeded dev admin: `adminBTG`.
- **Brand kit precedence:** Explicit brief kit (`Brief.brandKitId`) → Campaign kit → Project default → system default (`BrandKit.isDefault = true`)
- **Post size:** chosen per brief (`Brief.aspectRatio`: `SQUARE`=1080×1080, `PORTRAIT`=1080×1350); a brand template declares the size it was designed for (`BrandKitTemplate.aspectRatio`). Dimensions resolve through `src/lib/aspectRatio.ts` — the only place pixel sizes are defined.
- **AI provider resolution order:** Brief's chosen key → `AvailableProvider.isDefault` → env var fallback
- **API keys** stored AES-256-GCM encrypted; only `keyPrefix` shown in UI after registration; full key never returned
- **MinIO** served to browser via pre-signed URLs only — MinIO port never publicly exposed
- **Claude design agent** runs as a tool-use agent loop — tools: `generateImage`, `renderHtml`, `getBrandKitContext`
- **AGUI refinement:** natural language → Claude updates HTML → Puppeteer re-renders → `DraftRevision(htmlSnapshot)`
- **Brand kit structured data** (colors, fonts, logoUrl) is stored in the DB and passed to Claude as CSS variable definitions
