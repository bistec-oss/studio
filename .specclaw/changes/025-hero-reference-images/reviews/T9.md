## Findings

### [NOTE] src/lib/drafts/revisions.ts (`recordRejectedRender`, `renderDraftHtml` call) - FR-16 wording

A placement failure while rendering a _rejected_ refine is swallowed as a normal render failure. The row is kept with no export and the refine settles "not applied". FR-16 says a placement failure fails the action with the named text. No export is left behind, and the failure only occurs on an already-rejected refine, so this is acceptable. A rejected `DraftRevision` row is still written (not a chain row).

### [NOTE] src/lib/composite/insert.ts `hasScreenshotUrl` / `canonicalCompositeHtml` - classic drafts

The NFR-05 throw also runs for classic stamps. Any user-pasted `https://.../screenshots/...` URL in an inline edit would now be a 500 with nothing saved, where before it was saved. This is very unlikely. If it matters, restrict the throw to the preview route plus composite stamps.

### [NOTE] tests/unit/compositeCanonical.test.ts - NFR-05 guard strength

The guard checks the writer set and that `revisions.ts` calls the canonical function. Generation and regenerate writers (`generateDraft.ts`, `regenerate-design`) are only allow-listed by a comment, not asserted token-only. The E2E token checks cover them at runtime.

The editor change (label, not editable, preview URL) is checked only through the unit tests of the pure parts. Nothing exercises the iframe in a browser. Please eyeball it once in a real run. The CSS is injected into the iframe, so there is no design-system conflict and no new `ui-exception`.
