## Spec compliance

`detectScreenRect` implements every A1 rule: the 5% x 5% seed (blank, median is L0), five scans per axis at -30/-15/0/15/30% with medians, the edge as the last screen sample (no bezel), a scan reaching the grid edge fails (`edge-at-window`), the 3% interior inset, 16:10 within 5%, area >= 0.6 of the region, and no text-region intersection. The constants are correct (12, 0.10, 0.6, existing `BLANK_STDDEV_MAX` 0.04) and the fail order is sensible. NaN is never screen and never blank. A bad grid shape and an unreadable seed fail. `runHeroCheck` (`src/lib/renderer/heroCheck.ts`) is the single check: `background.ts` and `recheck.ts` both call it, text regions go first and are unchanged, and any throw, timeout or null grid becomes `check-error` or `region-invalid`, never a pass. The released contracts, hashes, `BUSY_STDDEV_MAX`, `BLANK_STDDEV_MAX` and the device-screen rows are untouched. The `settleComposition` fail-closed rule works (kept composite with no rect is `check-error`; the T1 no-third-argument rule stands). The stamp has the three rect invariants, each tested on its own bad stamp. The probe adds `rect`. `--recheck` is dispatched before any ledger or network code in `runProbe` and the tsx entry writes only `results.json` and `recheck.html`. The 028 runner path and the NFR-10 paths are untouched. Of the six removed `it(` lines, five were replaced with coverage that preserves the assertions: the 0.039/0.041 boundary moved to `screenDetect.test.ts` (seed and interior), and the "kept stamp" test was reworked to carry the rect. ## Findings

### [WARN] scripts/look-check/recheck.ts:1 and src/lib/renderer/puppeteer.ts (sampleLuminanceGrid MOCK_PUPPETEER branch) — Correctness / fail-closed

**Problem:** `recheck.ts` calls the shipped `runHeroCheck`. If it is run in a shell where `MOCK_PUPPETEER` is on (for example under `dotenv -e .env.test`), `sampleLuminanceGrid` returns the synthetic flat-screen grid (`if (MOCK_PUPPETEER) { return opts.seamRegion ? syntheticScreenGrid(...) }`), so every render "keeps the look" at the contract region and the result is written into `results.json`. That tool's verdict decides the OP-025 pass rule, so a mock env gives a silent false pass.
**Fix:** at the top of `recheck.ts`, exit with an error when `MOCK_PUPPETEER` or `MOCK_AI` is truthy. One line.

### [NOTE] src/lib/designData/evaluate.ts:88 — Design (judgement call 2)

**Problem:** `if (region.purpose === 'composite') continue` means `evaluateRegions` now silently passes any composite region (the rewritten test asserts a 0.041 composite "passes"). The only caller filters composites out, so it is safe today. The invalid rule (`minAreaPct`) is also no longer applied to the composite region in the real path; only a null grid gives `region-invalid`. Under cover-fit the image always covers the canvas, so this is benign. I accept call 2, but the doc comment is the only guard. A future caller that passes a composite region gets a fail-open pass.
**Suggestion:** return `region-invalid` instead of `continue` for a composite region, since no caller should hand one over. That fails closed and costs no test except the one rewritten case.

### [NOTE] src/lib/designData/composite.ts (final return) and stamp.ts — Correctness

**Problem:** the detector checks 16:10 and text overlap on the unrounded rect, but the stamp validates the two-decimal rounded rect. A rect within about 1e-4 of the 5% aspect boundary, or touching a text band by under 0.005, could pass the check and then fail the stamp parse at write. The odds are tiny.
**Suggestion:** validate the rounded rect in the detector (build the rounded rect first, then run `isScreenAspect` and `rectsIntersect` on it).

### [NOTE] tests/unit/screenDetect.test.ts — Test quality

**Problem:** nothing proves the median over five scans is what rejects an outlier (one corrupted scan line should not move the rect). Offset-screen exactness and each fail rule are covered.
**Suggestion:** add one case where a single scan row or column is blocked or extended, and expect the unchanged rect.

### [NOTE] src/lib/renderer/puppeteer.ts (`sampleLuminanceGrid` opts.seamRegion) and scripts/look-check/run-look-check.mjs — YAGNI / hygiene

**Problem:** (a) `seamRegion` is a production-signature parameter that exists only for the mock grid (judgement call 4); acceptable but worth knowing. (b) `spawnSync('npx', [..., args.out], { shell: true })` passes `--out` unquoted through a shell, so an `--out` path with spaces breaks. The default path is safe.
**Suggestion:** drop `shell: true` and use `npx.cmd` on win32, or quote the argument.
