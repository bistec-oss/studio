## What changed, per file

- `src/lib/composite/render.ts`: `COMPOSITE_PLACEMENT_ERROR` (the spec text, verbatim) and `CompositePlacementError` (its message is that text; `detail` keeps the render failure for logs).
- `src/lib/composite/insert.ts` (pure):
  - `canonicalCompositeHtml(html, stamp, canvas)`: the document a writer stores. A stamp with `composites` gets the one canonical element at the stamped rect (`insertComposite`); any other stamp gets `stripComposite`. It throws if the result holds a screenshot URL (NFR-05).
  - `hasScreenshotUrl(html)`: the preview route `/api/briefs/screenshots` or an `http(s)` URL with a `/screenshots/` path.
  - `withDetectedScreen(size, rect)`: moved here from `pathB.ts` (which now imports it) so the refine prompt can use it.
- `src/lib/composite/assets.ts`: `compositeRenderForCanvas(stamp, teamId, canvas)`; `compositeRenderFor(stamp, teamId, size)` now delegates to it.
- `src/lib/composite/editor.ts` (new, pure): `editorSrcDoc` (the token shown as the preview-route URL, display only), `compositePreviewUrl`, `COMPOSITE_EDITOR_LABEL` ("Product screenshot (placed automatically)") and `COMPOSITE_EDITOR_CSS` (outline plus the label as a `::after`, not selectable).
- `src/lib/drafts/revisions.ts`:
  - `compositeRenderForDraft` (reads the draft's team once, builds the render argument; a failure is a `CompositePlacementError`) and `renderDraftHtml` (renders with the stamp's composite; a `CompositeRenderError` becomes a `CompositePlacementError`).
  - `commitDraftRevision` stores `canonicalCompositeHtml(args.html, stamp.composition, canvas)` in both `htmlSnapshot` and `htmlContent`, and renders through `renderDraftHtml`. The check runs before the upload, so a failed placement writes no row and uploads nothing. An adopt uses the rejected row's own stamp (as before).
  - `recordRejectedRender` does the same (canonical document, stamp-driven render). A failed placement there is recorded without an export, like any render failure, and the refine settles cleanly as not applied.
- `src/app/api/drafts/[id]/refine/route.ts`: the model sees `extractInlineAssets(stripComposite(draft.htmlContent))`; the stamped contract text names the stamped screen (`withDetectedScreen`) and gets `canvas` (T1 note c), so the pixel sentence is present. The commit and the rejected render pass the stamp (kept) or `refineReplacedStamp` (a replaced image: classic, `refine-replaced-image`, no composites, so no element). The Override commit maps `CompositePlacementError` to 422 `{ error, code: 'composite-not-placed' }`. In the background run the error propagates, and `startDraftAction` records its message as `pendingActionError`.
- `src/app/api/drafts/[id]/inline-edit/route.ts`: whole-document and element modes map `CompositePlacementError` to 422 with the same body. The writer rebuilds the element, so whatever the editor sends (deleted, moved, with the preview URL) is saved canonical.
- `src/app/api/drafts/[id]/revisions/[rev]/restore/route.ts` (the legacy re-render branch) and `src/app/api/generate/export/route.ts`: render through `renderDraftHtml` with the revision's / the draft's stamp; a placement failure is 422 and writes nothing.
- `src/lib/renderer/layoutFacts.ts`: the observation skips text and images inside `[data-composite]`. `src/lib/renderer/domFacts.ts`: skips elements inside `[data-composite]` (so the data: URI never enters the facts).
- `src/lib/agent/prompts/refine.ts` and the route: `compositionContract` gains an optional `canvas`.
- `src/components/drafts/InlineEditModal.tsx` and `src/app/(app)/drafts/[id]/page.tsx`: new optional `compositeKey` prop (the stamped key; refreshed from `d.composition` on every own read). The iframe `srcDoc` shows the preview URL; whole-document mode marks `[data-composite]` `contenteditable=false`, adds no Replace-photo control to its image and shows the label; element mode adds the label and `pointer-events:none` so the element cannot be selected. Existing tokens and components only; no new `// ui-exception` (the CSS lives in the injected iframe style, in `editor.ts`).

## Judgement calls

1. **The writer canonicalizes, not each route.** `commitDraftRevision` and `recordRejectedRender` are the one place a caller's document becomes a stored document, so a route cannot forget it. This also covers adopt and the element edit, with no per-route code.
2. **Refine does not insert the element before verification.** The verifier compares the stripped before document with the model's after document (like for like); the element is put back by the writer, and the composite check runs in that render.
3. **teamId is read inside the writer** (`prisma.draft.findUnique({ select: { teamId } })`, only for a composite stamp), so `CommitRevisionArgs` did not change and no caller gained an argument.
4. **`compositeRenderForCanvas`** was added because the writers hold the canvas (`width`, `height`), not an `AspectRatio`.
5. **The NFR-05 throw is on the app preview route and on http URLs with `/screenshots/`**, not on any mention of "screenshots", so an ordinary page that happens to say it cannot fail an action.
6. **Element mode cannot select the element** (`pointer-events:none`); a click goes to what is behind it.
7. A failed placement in a **refine** surfaces as the draft's `pendingActionError`; in the synchronous **Override, inline edit, restore and export** it is a 422 with `code: composite-not-placed`.
