# T10 report: the wizard (implementer)

## What changed

- `src/lib/brief/wizardStyleState.ts`: `styleAfterInputChange(imageStyle, size, looks?, { hasCompositeSource })` generalises `styleAfterSizeChange`, which stays as a thin wrapper (no screenshot held). `WizardStyleInput` gains optional `hasCompositeSource`, passed to `resolvePostStyle` instead of the hard-coded `false`. New pure `screenshotWillLetterbox(size, {width,height})`: true when the screenshot's aspect differs from the `device-screen` composite region (canvas px, read from the dataset) by more than 10%.
- `src/components/brief/useBriefWizard.ts`: `compositeSource`, `screenshotUploading`, `screenshotError`, `screenshotInputRef`, `onScreenshotPicked` (multipart `POST /api/briefs/screenshots`, server message shown on refusal), `removeScreenshot` (drops a picked `requires` look). Size change uses `styleAfterInputChange` with the held flag. `setDesignMode('TEMPLATE')` clears the screenshot. Autosave payload carries `compositeSource` (Path B only). Resume restores it (`parseCompositeSource`) and keeps `device-screen` only if it came back. Submit body carries it only when the sent `imageStyle` is a look with `requires`.
- `src/components/brief/SizeDesignStep.tsx`: new "Product screenshot" section (Path B only), outside `image-style-section`; card enablement via `imageStyleOptions(size, undefined, { hasCompositeSource })`.
- `src/components/brief/ReviewStep.tsx`: row "Product screenshot: W×H" when present.
- `src/app/(app)/brief/page.tsx`: wiring only.
- Tests: `tests/unit/postStylesWizard.test.ts` (+6 cases); `tests/e2e/product-screenshots.test.ts` TC-SHOT-13 (written, not run).

## Primitives used

`FieldLabel` (as span), `Button` (secondary, sm), `Notice` (error), `Select` unchanged, `cardCls`, `ICON`, lucide `Upload`/`Loader2`. No new component, no `ui-exception`. No `FileInput` primitive exists, so the hidden `<input type=file>` plus `Button` pattern from `ImagesStep` is reused.

## Accessibility

- Visible label "Product screenshot (required|optional)"; help text linked to the Add button with `aria-describedby`; hidden file input has `aria-label`, is `tabIndex=-1` and `hidden`.
- Remove button: visible "Remove", accessible name "Remove product screenshot". Thumbnail `alt="Product screenshot preview"`.
- One persistent `role="status"` region holds the letterbox advisory and the required line, so they are announced when they appear. Upload refusal is a `Notice` with `role="alert"`. Uploading state shows a spinner with "Uploading…" and disables Add.
- The `device-screen` card keeps native `disabled` plus its visible reason, as before.

## Judgement calls

- "Picking `device-screen` without a screenshot shows the field as required": the card is disabled without a screenshot, so it cannot be picked; the label shows "(required)" and a red line whenever the pick would need one (reachable only defensively), and the help text always names the dependency. The label reads "(optional)" otherwise.
- Remove does not delete the stored object (no route for it in T7); a removed or replaced upload stays in `BUCKET_DOCS` until discard cleanup, as T7 defined. Worth a note for T12 limits.
- The field sits outside `image-style-section` so `TC-LOOK-10`'s `button[aria-pressed]` count (6) is unchanged.
- The advisory text is longer than the bare "Will be letterboxed" but starts with it.
- TC-SHOT-13 does not `test.skip` on mocks (the wizard needs a seeded Bistec team and MinIO only); it deletes its uploaded objects and brief drafts. Screenshots (390 and 1440 px, light and dark) are for the orchestrator.
- No back-end change needed.
