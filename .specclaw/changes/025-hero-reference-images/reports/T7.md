## Judgement calls

1. **Drafts and the owner check.** The row stores `teamId`, so `deleteBriefDraftImages` takes it as a required third argument (its only callers are inside `briefDrafts.ts`). The payload schema alone cannot know the team, so it checks the key shape; the owner check is at save (400) and at delete (skip).
2. **Preview with `draftId`** also requires the key to sit under the session's team, so a stamp can never be used to read another team's object.
3. **PNG and WebP truncation.** A header-only parse cannot tell a cut file, so a PNG must end in an IEND chunk and a WebP's RIFF size must fit the file. JPEG is only checked up to its SOF (a trailing-bytes JPEG is common).
4. **`briefInput.ts` and `wizardStyleState.ts` still pass `hasCompositeSource: false`.** Both are outside T7's list. The generation plan in `pathB.ts` is T8's. Until T8, a device-screen brief with a stored source resolves to `device-screen` at brief creation but plans as classic with `missing-input-classic` at generation and regenerate. Do not push `v2` between T7 and T8 without T8 (same caution as T1 and T2).
5. **TC-SHOT-14b** creates a `Draft` row directly with Prisma (teamId and briefId only), because a composite generation does not exist until T8; it skips when no test DB is reachable from the runner.
6. **Storage assertions** go straight to MinIO (`tests/helpers/minio.ts`), since the docs bucket has no public URL.
7. **`Node` module note:** the test PNG builder has its own CRC32, so it does not need Node 22's `zlib.crc32`.
