Implementer: sonnet subagent, 2026-10-26. Not committed (the orchestrator commits). Covers FR-12 to FR-15, NFR-05, NFR-07, NFR-08, AC-11, AC-12, AC-13, as amended by A1: insertion and the render check use the **stamped / detected rect**, never the contract region.

## What changed, per file

- `src/lib/composite/render.ts` (new, pure): `COMPOSITE_TOKEN`, the `CompositeRender` type (`{ token, dataUri, rectPx }`), and `CompositeRenderError` (`reason`: `composite-not-rendered` or `composite-source-missing`; an optional `uploadedKey` that the API design loop sets). Kept apart from `assets.ts` so the renderer imports no storage code.
- `src/lib/composite/insert.ts` (new, pure): `insertComposite(html, rect, canvas)`, `stripComposite(html)`, `compositeRectPx`, `compositeElement` and `compositeHtmlProblems(html, rectPx)`.
  - Strip removes the canonical element and any other element with a `data-composite` attribute (a quote-aware tag scan, nesting-aware, void tags handled; `data-composite-img` is not matched on its own).
  - Insert strips first, then writes one `<div data-composite="0">` (fixed at the rect in canvas px, rounded to 0.1, `z-index:2147483647`, `#0b0b0b`, `overflow:hidden`) holding `<img src="__COMPOSITE_0__" style="object-fit:contain">`, before the last `</body>` (appended with none). Idempotent; strip after insert restores the page byte for byte.
  - `compositeHtmlProblems` is the pure check: exactly one `data-composite` attribute, the canonical element at the rect, exactly one token.
- `src/lib/composite/assets.ts` (new): `compositeRenderForSource(key, rect, teamId, canvas)` (refuses a key outside `screenshots/<teamId>/` or with traversal, reads the object once with `getObjectBytes`, validates it with `readImageHeader`, builds the `data:` URI) and `compositeRenderFor(stamp, teamId, size)` (null without composites; otherwise the stamp's first entry's key and rect). Every failure is `composite-source-missing`.
- `src/lib/renderer/puppeteer.ts`:
  - `renderHtmlToPng(html, w, h, composites)` and `evaluateInRenderedPage(html, w, h, fn, composites)` take a **required** `composites: CompositeRender | null`.
  - With it set: the pure HTML check runs first (also under `MOCK_PUPPETEER`); `withRenderedPage` replaces the token with the data URI just before `setContent` (the caller's string is never changed), then `verifyComposite` measures in the page before `fn`/the screenshot. The page code awaits `img.decode()`, then reports `found`, `complete`, `naturalWidth`, the element's `getBoundingClientRect` and five `elementFromPoint` hits (centre and four points inset 10%, taken on the **stamped rect**). The verdict is the existing pure `evaluateCompositeFacts` with `COMPOSITE_TOLERANCE_PX`. A failure throws `CompositeRenderError('composite-not-rendered', detail)`.
  - Under `MOCK_PUPPETEER` the in-page part is skipped and `shouldMockCompositeFail(html)` makes the check fail.
- `src/lib/testHooks.ts`: `COMPOSITE_MOCK_SENTINEL = '__MOCK_COMPOSITE_FAIL__'`, `shouldMockCompositeFail(html)` (gated on `MOCK_AI`), and `buildMockHtml` copies the sentinel from its prompt context into a comment between the doctype and `<html>`.
- `src/lib/agent/types.ts`: `DesignAgentOptions` gains optional `postProcess?: (html) => string` and `composites?: CompositeRender | null`.
- `src/lib/agent/designAgentCli.ts`: applies `postProcess` after extract and restore, then renders with `composites`. A failed check throws before anything is uploaded; the returned `htmlContent` is the inserted HTML.
- `src/lib/agent/designAgent.ts` (API loop): `postProcess` runs on each `renderHtml` tool input after the inline assets are restored (a local copy, so the message history keeps the model's own HTML), on the mock path, and on the final-text fallback; `executeTool` passes `composites` to `toolRenderHtml`. When a `CompositeRenderError` ends the loop after an earlier passing render, the error carries that render's export key (`uploadedKey`).
- `src/lib/agent/tools.ts`: `toolRenderHtml(html, w, h, composites)` (required).

  - A **provisional** `settleComposition(plan, background, placed)` only decides whether the look was kept at the pixel check; the stored stamp is settled after the design (NFR-08). The detected rect is `provisional.composites[0].rect`.
  - For a kept composite look, `compositeRenderForSource(key, detectedRect, brief.teamId, canvas)` is built once; a failure falls back to classic **without the hero image** (`composite-source-missing`) and the design runs once.
  - The design prompt names the **detected** screen: the contract's composite region is replaced by the detected rect (`withDetectedScreen`) before `designContractText`.

Any other error is rethrown.

## Judgement calls

1. **`compositeRenderFor(stamp, teamId, size)`** takes the size (the brief named `(stamp, teamId)`): the rect in px needs the canvas, as design section 10 has it. `compositeRenderForSource` is the lower level generation uses, because there is no stamp yet.
2. **The design prompt names the detected rect**, not the contract region: it was natural (one `size` swap) and it tells the model exactly where the screenshot lands. The text regions are unchanged, and the detector already guarantees the rect clears them.
3. **A provisional settle before the design.** `settleComposition` fails a `requires` look closed without a third argument (T1 carry-over e), so generation passes a provisional `{ ok: true }` only to learn "kept at the pixel check", and never stores it. The stored stamp comes from the settle after the render passed, or from the fallback.
4. **`composite-source-missing` also drops the hero image** (design section 12). The blank failure keeps it (Phase 1 behaviour). Say if you want the source-missing case to keep it too.
5. **The pure check counts the text `data-composite` anywhere in the HTML** (comments, CSS, script), not only as an attribute. It is conservative and fails closed. My first render tests tripped it with a CSS selector, so they use `div[style*="2147483647"]` instead.
6. **`uploadedKeys` on the error** carries every export the API loop uploaded in the run so the fallback can delete them all (the brief asked the fallback to delete "the uploaded export"). The CLI path never uploads before the check, and the mock path throws before any upload.
7. **`toolRenderHtml` and the new options are required or optional as follows:** `renderHtmlToPng`, `evaluateInRenderedPage` and `toolRenderHtml` are required (tsc lists callers); the options of `observeLayout`, `extractDomFacts` and the design agents are optional, because the stamp-driven callers arrive in T9.
8. The fallback design call costs one more design call in time; the segment budget (`budget.ts`) was not changed (spec "Known limits").

## The 10 MB `setContent` timing (NFR-07)

`tests/render/composite.test.ts` renders a 2300 by 1450 noise PNG of 10.88 MiB (a 14.51 MiB data URI) at SQUARE on this machine (Windows, local Chromium, browser warm):

- `setContent` plus the in-page composite check: **2047 ms** (no screenshot taken);
- the full `renderHtmlToPng` (load, check, 2x PNG screenshot): **2300 ms**.

The test asserts a bound of 30 s for the load; the real cost is about 2 s, well inside `SET_CONTENT_TIMEOUT_MS` (60 s).

## Real-Chromium results (AC-12, A1)

At SQUARE, PORTRAIT and STORY, a 1600 by 1000 test pattern (four coloured quadrants, a 1 px grid) is placed at a stamped rect that differs from the contract region: the box is within 2 px on every edge, and the PNG colour at each quadrant centre is within DeltaE 3 of the source. A missing object (`composite-source-missing`), a covering element, a moved element, a resized element, an undecodable image, a missing element and a second element each throw `CompositeRenderError` (the detail strings are asserted for the covering, moved and resized cases, so they fail in the page and not on the pure check). The stored string keeps the token.
