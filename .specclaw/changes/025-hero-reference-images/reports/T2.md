# T2 report: availability by `requires`

## What changed

- `src/lib/designData/composition.ts`: `imageStyleOptions(size, source, { hasCompositeSource })`; a look with `requires` and no source is `supported: false` with `reason: 'Needs a product screenshot'` (`NEEDS_SCREENSHOT_REASON`). `supportsSize` now checks the size only (active look and a declared size), independent of `requires`.
- `src/lib/postStyles/resolve.ts`: `ResolveNote` gains `missing-input-classic`; `ResolveInput.hasCompositeSource`; checked after `retired-classic` and before `default-unavailable` / `size-classic`. `unattended-classic` and `path-a-classic` still come first.
- `src/lib/brief/compositeSource.ts` (new): `compositePairingError`.
- `src/app/api/briefs/route.ts`: passes `hasCompositeSource: false`; a `requires` look with no source is 400 `{ error, code: 'IMAGE_STYLE_NEEDS_SCREENSHOT' }`, checked on the final image style (an explicit one or the post style's default).
- `src/lib/agent/briefInput.ts`, `src/lib/brief/wizardStyleState.ts`: pass `hasCompositeSource: false` explicitly.
- `src/components/brief/SizeDesignStep.tsx`: shows `opt.reason` when set, else the old size text.
- `src/components/brief/useBriefWizard.ts`: resume uses `styleAfterSizeChange` (picker rule) instead of `supportsSize`, so a resumed `device-screen` drops to classic.
- `plan.ts` needed no change (T1 already has the flag and `composite-source-missing`); `types.ts` needed no change (`ResolveNote` lives in `resolve.ts`).
- Tests: `tests/unit/compositeSource.test.ts` (new), `tests/e2e/product-screenshots.test.ts` (new, TC-SHOT-01, not run).

## Adapted and added test cases

- `designData.test.ts` "picker lists classic first ... every card is supported": all supported only with `hasCompositeSource: true`; without it only `device-screen` is unsupported.
- `lookDataset.test.ts` "picker lists the five looks ...": same adaptation, plus the reason text and no reason on the other looks.
- `postStylesResolve.test.ts`: new describe for `missing-input-classic` (wizard, briefs-api, explicit look, flag keeps it, unattended wins, released looks unaffected).
- `postStylesWizard.test.ts`: touched `device-screen` resolves to classic; size change drops it.
- `compositionPlan.test.ts`: no flag gives classic `composite-source-missing` at all three sizes; flag gives a hero plan.
- `briefImageStyle.test.ts`: not changed (`validateImageStyle` unchanged).

## Judgement calls

- `supportsSize` kept size-only (a resumed or size-change check goes through `imageStyleOptions`/`styleAfterSizeChange`), so `lookDataset` supportsSize cases keep passing.
- The missing-input branch sits before the `!option` / `!supported` branches so the note is `missing-input-classic` even if the size is also unsupported.
- Error shape is the route's `{ error, code }`, as for `UNKNOWN_POST_STYLE`.
- TC-SHOT-01 uses its own fresh team (as `image-looks.test.ts` does) so it needs no seeded providers.
