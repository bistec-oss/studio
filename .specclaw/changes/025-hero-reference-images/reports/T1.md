## Decisions (for the reviewer)

1. **`settleComposition` and a kept `requires` look with no composite argument.** The design only says "optional third argument". Left to the stamp schema, that case would throw at parse (a kept `requires` look with no `composites` is invalid). I made it settle to classic with `composite-source-missing` instead, so a caller that forgets the argument fails closed rather than throwing mid-generation. T8 passes the argument.
2. **`refineContractText` gained an optional `canvas`.** The refine prompt options had no canvas, but the spec sentence includes pixels. With `canvas` the sentence is identical to the design prompt's; without it the pixel part is omitted. `src/lib/agent/prompts/refine.ts` is not touched (out of T1's scope); T9 passes the canvas.
3. **Spec table vs rows, STORY.** The spec table's "Screen in px" column says 567 for STORY, but its row 29.5% of 1920 gives 566.4. The rows are used as written (told to follow the table verbatim). 907.2 / 566.4 = 1.6017, inside the 0.5% rule for 16:10. The test asserts the width exactly and the height within 1 px, with a comment. SQUARE and PORTRAIT match exactly.
4. **`stamp.ts` imports `getArchetype` from `./composition`.** No cycle (`composition.ts` imports nothing from the module). `stamp.ts` stays pure.
5. **Hit-point and edge checks in `evaluateCompositeFacts`** compare the four edges (left, top, right, bottom), not width and height, so "within 2 px on every edge" cannot be satisfied by a 4 px resize. A `hits` array that is not exactly five long fails.
6. **The order of the design prompt's composite line** is directly after the text-region list, before the tone line.
