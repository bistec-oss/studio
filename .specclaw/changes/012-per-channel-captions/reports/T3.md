# 012 T3 report: the migration planner and the publish resolver (pure)

**Status:** built. Four new files. Both modules import only `@/lib/channels` and types, with no Prisma value import and no I/O.

## Modules

- **`captions/migrationPlan.ts`:** `planCaptionMigration(legacyText)` returns `{outcome: 'SPLIT'|'UNSPLIT_FALLBACK'|'EMPTY', rows}`. There is one row per registry channel, `{channel, text, status: 'READY', needsReview}`.
  - **A header is:**
    - an optional `#` to `######` followed by whitespace;
    - an optional `**`/`__` wrapper, closed by the same token;
    - `instagram|ig|linked ?in|whatsapp`, case-insensitive;
    - an optional `caption|post|copy`;
    - an optional colon, inside or outside the wrapper.
  - **SPLIT** needs exactly one IG header and one LI header, at most one WA header, nothing but whitespace before the first header, and no section that is empty after normalising.
  - **Fallback:** IG and LI each get the legacy text, trimmed, flagged `needsReview`; WA gets `''`.
- **`captions/resolve.ts`:** `resolveCaptionForPublish(channel, row)` returns `{ok:true,text}` or `{ok:false,reason}`. The six FR-14 rules run in spec order with the exact reason strings, and counts are formatted en-US. A `null` row falls under rule 2.

## Decisions

1. **Same-line body text needs a colon after the header,** so "Instagram is where…" isn't read as a header.
2. **`#instagram` (no space) is a hashtag, not a header.**
3. **Emptiness is checked after normalising,** so a section that is only `**` falls back.
4. **CRLF is normalised only when splitting.** The fallback is verbatim apart from the end trim.
5. **The pure resolver's rule 1 covers only "not publishable in the registry".** T7's `publishToChannel` must also treat a missing publisher as rule 1, with the same wording.
6. **A FAILED row with a null `failureReason`** leaves out the parenthesis.
