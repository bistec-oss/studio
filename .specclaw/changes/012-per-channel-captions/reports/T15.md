**Status:** built. `node --check` passes on both scripts. tsc is clean (`npx tsc --noEmit -p .`, exit 0). Lint has 0 errors and the 7 pre-existing warnings. Unit passed 74 files / 2025 tests. No app code, no test file and no new file in the repo changed. Nothing is committed.

Covers FR-22 (scripts): "`scripts/export-posts.mjs` and `scripts/import-posts.mjs` carry captions and the headline. An old bundle's `copyText` is imported as `legacyCaptionText`, and the loader materializes it." (spec.md:482)

## `scripts/export-posts.mjs`

- **`MANIFEST_VERSION` 1 → 2.** A pre-012 importer (on another machine) would otherwise read a new bundle, write `copyText: d.copyText` (now `undefined`) and create every draft with no caption at all. With the bump it stops with "Unsupported manifest version: 2" instead. The new importer accepts both 1 and 2.
- **The draft query** includes `captions: true`. Every caption row is flattened into a top-level `captions` array, next to `revisions` and `posts`, and counted in `counts.captions` and the summary line.
- **The draft rows** already carried every scalar column, so `headline`, `captionMigration` and `legacyCaptionText` (the Prisma name of the `copyText` column) are in the bundle with no further change. The nested `captions` relation is stripped from each draft row, the same way `revisions` and `posts` are.
- **The export only reads.** It runs `findMany` on the DB and `GetObject` on MinIO, and writes only to `--out`.

## `scripts/import-posts.mjs`

- **Bundle versions:** it accepts 1 and 2. `manifest.captions ?? []`, because a v1 bundle has no captions array.
- **`draftCaptionFields(d)`** is one small function that maps a bundle draft to its caption fields:
  - `legacyCaptionText`: the bundle's own `legacyCaptionText` when the key exists (v2), else the old `copyText` (v1), else null;
  - `headline` and `captionMigration`: as exported, or null.

  It replaces the old `copyText: d.copyText` line, which the current Prisma client rejects.

- **What this gives:**
  - **A v1 draft** has `legacyCaptionText` set, a null `captionMigration`, a null headline and no rows. That is exactly what `materializeStep` (`src/lib/captions/store.ts:75`) treats as a legacy draft to migrate on first read, or to defer while it is `IN_PROGRESS`. Design falls back to the brief topic for the null headline (FR-03).
  - **A v2 draft** is restored as it was. A post-012 draft has its headline and a null legacy text. An already-migrated draft keeps its `captionMigration` and legacy text, so `materializeStep` returns null for it and it is never migrated twice. A legacy draft that was never materialized at the source is materialized here on first read.
- **Caption rows** are written after the drafts, because of the FK, with `createMany({ skipDuplicates: true })`.
  - Before writing, the importer reads the existing rows that match either a bundle caption id or a bundle draft id. A row is skipped when its id exists, or when this machine already has a row for that `(draftId, channel)`, for example one the loader materialized here.
  - So a re-run never changes an existing caption, and the dry run's counts are exact. `skipDuplicates` stays on as a guard against a concurrent writer.
  - Every column is restored: `text`, `status`, `failureReason`, `needsReview`, `createdAt` and `updatedAt`. The fallback-migration review flag survives the transfer.
- **The dry run now prints what would be written:**
  - for each draft it would create: its headline, `captionMigration`, the legacy caption length and its caption channels;
  - for each caption row it would create: its slot, status, length and `needsReview`.

  This is the same `data` object the real path passes to `prisma.draft.create`, so the dry run exercises the mapping. That is why no unit test was added (see "Ripples").

- **The summary** gains a `captions:` line.

## Flagged, not fixed: out of scope

- **🔴 Pre-existing, since team tenancy (2026-07-21): a real import fails.** `Brief`, `Draft` and `Post` have a required `teamId` with no default (`prisma/schema.prisma:427,459,543`), but `import-posts.mjs` builds its `data` objects without one. So the first `prisma.brief.create` in a real run is rejected by Prisma validation, before any caption code is reached.
  - The dry run doesn't call `create`, so it doesn't show this.
  - The export does carry `teamId` on each row, but the source team id is meaningless on another machine. A fix needs a remap decision, for example a `--team <name>` flag or matching the team by name. That is outside T15, so I didn't make it.
  - Until that is fixed, idempotency can be shown only by the dry run, as here (run 2), not by a real import.
- **PENDING caption rows are imported as they were.** This is the same as `Draft.status`, which the importer already copies verbatim. It is not filtered the way non-terminal `Post` rows are, because no scheduler acts on a caption row.

## Review fix (orchestrator)

- **Review WARN (`reviews/T15.md`):** caption rows were being imported for every bundle draft, including drafts the draft loop had skipped as already present. So a v2 re-import could add rows to a local draft that had none, for example an un-read v1 draft, while leaving its unmigrated legacy text in place.
- **Fix:** the caption rows are now filtered to drafts created in this run (`!haveDrafts.has(c.draftId)`) before the id and slot checks. The comment says so.
- **Re-check:** `node --check` passes. The three dry runs were re-run with `--env-file=.env.test`, against target `bistec_studio_test` (printed first), and gave the same counts as above:
  - export: 0/6 captions;
  - new bundle: 6 created;
  - old bundle: 0 rows.
- **Follow-up:** the `teamId` gap is logged as learning L22, a follow-up after 012.
