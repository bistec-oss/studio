## Incident (disclosed)

The backfill bundle was run once against the **dev** DB by accident: `@prisma/client` loaded `.env` even though `DATABASE_URL` was unset.

- The advisory lock and unlock both ran.
- The first `findMany` then failed with P2022, because the new column doesn't exist on the un-migrated dev DB, and the process exited 1.
- **Nothing was written.** The run did confirm that the lock SQL works and that the unlock runs in `finally`.

## Schema

- New enums: `CaptionStatus` (PENDING, READY, FAILED) and `CaptionMigration` (SPLIT, UNSPLIT_FALLBACK, EMPTY).
- New model `DraftCaption` (spec FR-02): a cascading FK, `@@unique([draftId, channel])` and `@@index([draftId])`.
- `Draft` gains `headline String?`, `captionMigration CaptionMigration?` and the `captions` relation. `copyText` is untouched; T9 renames it.
- **Migration `20261011130000_draft_captions`:** matches `prisma migrate diff`, plus the named CHECK `DraftCaption_failed_has_no_text` (`status <> 'FAILED' OR text = ''`). It contains no DROP or RENAME, so it meets AC-27.

## Store (`captions/store.ts`)

- **`materializeStep` (pure):** returns `migrate` only when there are 0 rows, the legacy text is not null and `captionMigration` is null. It returns `defer` when the draft is IN_PROGRESS or its pending action is REGENERATE_COPY.
- **`migrateDraft`:** one `$transaction`: `createMany` with `skipDuplicates`, then an `updateMany` guarded on `captionMigration: null`. It returns `written` only if this call recorded the outcome, so a race logs each draft once.
- **`loadDraftCaptions`:**
  - a deferred draft gets synthesized PENDING rows, which are never stored;
  - an eligible draft is migrated on read and logged, with a REVIEW line for an unsplit fallback;
  - a missing channel gets an empty READY row;
  - rows come back in registry order.
- **Other functions:**
  - `captionReviewLines`;
  - `captionRowsFromFields`, which is pure and used by T5's sync path;
  - `saveGenerationCaptions`, with each row update guarded on PENDING and the headline written only when valid;
  - `claimCaptionAction` (design §5).
- **Deferred to T6:** `settleCaptionAction` and `settlePendingCaptions`, which need T6's pure `settleCaptionRow`.

## Backfill (`captions/backfill.ts` and `src/scripts/backfill-captions.ts`)

- An advisory lock with the unlock in `finally`, and keyset paging over `(createdAt, id)`.
- Deferred drafts are counted, and each draft is migrated inside its own `try/catch`.
- The summary is `[captions] backfill: N drafts — split S, unsplit-fallback F, empty E, deferred D, errors X`, followed by REVIEW lines.
- `--report` takes no lock and makes no writes.
- The CLI uses its own `PrismaClient` with `connection_limit=1`, so the advisory lock stays on one session.

## Deploy wiring

- **Entrypoint:** runs `node dist/scripts/backfill-captions.js` after `migrate deploy`, inside the `SKIP_MIGRATIONS` guard.
- **Dockerfile:** a second esbuild bundle, picked up by the existing `COPY dist`.
- **`package.json`:** new `captions:backfill` and `captions:report` scripts, using `tsx --env-file=.env`.
  - **T10 risk:** a missing `.env` makes Node error out, so CI may need `--env-file-if-exists` or a direct tsx call.
