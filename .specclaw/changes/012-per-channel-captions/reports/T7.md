# 012 T7 report: publishing through the one resolver; the terminal failure in the job runner

**Status:** built.

## Changes

- **`captions/resolve.ts`** (declared ripple, T3 NOTE 1): exports one shared `unavailableReason(channel)`, used by resolver rule 1 and by the publisher-map miss, so the strings are identical.
- **`captions/store.ts`:** `loadCaptionForPublish(draftId, channel)` and `loadCaptionText`. Both go through `loadDraftCaptions`, so a legacy draft is migrated first.
- **`publishToChannel(channel, exportKey, draftId, teamId)`:**
  1. a publisher-map miss throws a terminal error with `unavailableReason`;
  2. the caption is resolved, and a refusal throws a terminal `PublishError` with the resolver's reason;
  3. **only then is the export signed.** "Draft export missing" stays retryable.

  `copyText` is no longer selected.

- **`jobRunner`:** passes the draft id. A terminal error → FAILED at once, with the reason, `nextRetryAt: null` and `retryCount` unchanged, logged `→ FAILED (terminal)`. Other errors keep the existing backoff.
- **`POST /api/posts`:** after the export check, a refused caption → 422 `{error, code: 'CAPTION_UNPUBLISHABLE'}` with no Post row, on both the immediate and the scheduled path.
- **GET routes:** `/api/posts` and `/api/posts/[id]` return `draft.caption` (the post channel's text) instead of `copyText`.
- **`posts/[id]/publish`:** passes the draft id. A refused caption → FAILED, with the reason.
- **`testHooks.mockPlatformId(channel, caption)`:** `mock-<channel>-<ts>-<sha256(caption)[0:12]>`, used by the mock publishers. The existing prefix is kept.
- **`generationRunner`:** unchanged, and its unit test passes (FR-16 is met through the resolver).

## Notes

- **The retry route's existing pre-check** signs the export URL before `publishToChannel` runs, and the URL is discarded. It is kept because it gives the route's 422 for a missing export; inside `publishToChannel` the caption is still resolved before signing.
- The immediate path loads the captions twice: once up front and once inside the publisher. Both reads are cheap.
- The social publishers' parameter is still named `copyText` (internal).
- **The pre-existing 201-on-FAILED bug is not fixed here.** It is a separate follow-up.
