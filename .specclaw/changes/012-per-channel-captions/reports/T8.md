## `publish_post` and a refused caption (FR-17)

The spec FR-17 and design §419 behaviour holds on the existing path:

1. **Non-publishable channels.** WhatsApp, and any other channel without a publisher, is still rejected up front by `isPublishableChannel`, before any lookup or row exists (FR-15).
2. **The pre-checks.** The status, export and duplicate checks are as they were before T8.
3. **A refused caption.** A failed, pending, empty or over-limit caption goes through `createAndPublishPost`. That path writes a PENDING row, then `publishToChannel` runs the resolver **before** it signs the export. The resolver refuses with a terminal `PublishError`, and the row becomes **FAILED, with `errorReason` = the resolver's reason**.
4. **What the caller gets.** The tool throws the existing format, `Publish failed (<reason>) — recorded as post <id> with status FAILED`. A platform failure gets the same format.
5. **What is never touched.** The export is never signed, and the platform is never called. The header comment "every attempt (success or failure) leaves a Post row (FR-20/NFR-9)" stays true.

An interim version of T8 added an up-front, no-row refusal. It was removed on the orchestrator's ruling, which follows the approved spec.
