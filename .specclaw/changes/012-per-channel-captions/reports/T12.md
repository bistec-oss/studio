## What changed

### `CaptionPanel.tsx`

The order in the panel follows design §9: the notices, then the textarea, then the counter row, then any limit warning. The FAILED notice and the last-regenerate-failed notice can never both show, because one needs `FAILED` and the other `READY`. Each notice's icon is `AlertTriangle`, with `aria-hidden`.

**The notices:**

| Notice                  | Shown when                                     | Tone      | Role     | Exact text                                                                                                     |
| ----------------------- | ---------------------------------------------- | --------- | -------- | -------------------------------------------------------------------------------------------------------------- |
| Review                  | `caption.needsReview`                          | `warning` | `status` | Migrated from the old single caption, which wasn't split by channel. Review this caption before publishing it. |
| FAILED (T11, unchanged) | `status === 'FAILED'`                          | `error`   | none     | The <Label> caption failed to generate (<reason>). Write it below, or use Generate.                            |
| Last regenerate failed  | `status === 'READY' && failureReason !== null` | `warning` | none     | The last regenerate failed: <reason>. The caption below is unchanged.                                          |

- **The review notice goes once the row is edited or regenerated.** The server does this: the PATCH (`store.ts:411`) and a successful settle both write `needsReview: false`, and the refetch then removes the notice. A failed regenerate keeps `needsReview`, since `settleCaptionRow` doesn't write it, so the notice stays. The caption has still not been reviewed.
- **The last-failed notice clears the same way.** The PATCH and a successful settle both write `failureReason: null`.

**The counter and its warnings:**

| Channel                              | Counter (exact)              | Past the limit                                                                                                                |
| ------------------------------------ | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Instagram (hard 2,200)               | `1,234 / 2,200 (Instagram)`  | The counter turns `font-semibold text-status-failed`, and a line below reads "Over the Instagram limit" in `--status-failed`. |
| LinkedIn (hard 3,000)                | `412 / 3,000 (LinkedIn)`     | The same, with "Over the LinkedIn limit".                                                                                     |
| WhatsApp (soft 1,000)                | `412 / 1,000 guide`          | A line below reads "Longer than the 1,000-character guide" in `font-semibold text-status-scheduled`. The counter stays muted. |
| A channel with no limit (none today) | `n characters`, kept from T6 | none                                                                                                                          |

- Every number goes through `count()` (`en-US` separators), and the guide's number comes from `spec.softLimit`.
- Saving is never blocked, and the save path is unchanged.

**The WhatsApp helper text** is "Not published from Studio yet. Copy it and post it in WhatsApp."

- It is shown when `!spec.publishable`, with `spec.label` filling in the channel name, so today it appears only on WhatsApp.
- It sits on the left of the counter row (`min-w-0`, so it wraps). The counter is `ml-auto shrink-0`.

**The a11y wiring.** The textarea's name is unchanged: `aria-labelledby` its h3. It gains `aria-describedby`, which lists, in this order and only for the parts that are rendered:

1. the review notice;
2. the FAILED or last-failed notice (one id, because the two never show together);
3. the helper text;
4. the counter;
5. the limit or guide warning.

So on focus, a screen reader reads for example: "WhatsApp … Not published from Studio yet. Copy it and post it in WhatsApp. 1,001 / 1,000 guide Longer than the 1,000-character guide".

## Notes and choices

1. **The FAILED wording.** FR-19 gives the FAILED notice's tone and contents (its `failureReason` and the Generate button), but not exact words. T11's "… Write it below, or use Generate." meets that, so I kept it.
2. **No `role` on the last-failed notice.** FR-19 gives `role="status"` to the review notice only, and the FAILED notice from T11 has none either.
   - Both notices arrive through the poll, so a screen reader doesn't announce them as they appear.
   - The textarea's description does carry them on focus.
   - If the review wants them announced, adding `role="status"` is a one-line follow-up. The page's own `pendingActionError` line has no role either.
3. **The guide counter stays muted past 1,000.** FR-19 colours only the warning amber. For a hard limit it says the counter turns red, so the guide case deliberately differs.
4. **The review notice goes on a saved edit, not on a keystroke.** "It goes when the row is edited" is read through the server's `needsReview`. AC-24 ("editing IG removes IG's notice only") is met after the blur-save.
