## The guard (`tests/unit/legacyCaptionGuard.test.ts`, AC-08)

It is a static scan of every `.ts`/`.tsx` under `src/`, in the style of `uiTokenGuard.test.ts`. The design names only the file, and AC-08 asks for a guard plus a self-test, so this is the form I built. Comment lines are skipped. **The read forms are an allowlist, so a new write form fails by default.**

- **Allowed:**
  - `legacyCaptionText: true` (a select);
  - `legacyCaptionText: { not: null }` (the backfill filter);
  - a type annotation (`?:`, `: string`);
  - a property read that is not assigned;
  - a destructuring read.
- **Flagged:**
  - any other object-literal key, which covers a `data:`, `create:` or `update:` object;
  - a shorthand property `{ legacyCaptionText }`;
  - a property assignment, including `['…'] =` and compound `??=`;
  - **any raw SQL naming `"copyText"`.** This one goes slightly beyond AC-08's wording. It closes the obvious bypass of FR-10's "no writer writes it". No `src/` file has such SQL today.
- **3 cases:**
  - the scan over `src/` finds nothing;
  - a self-test where each of 9 write samples is flagged exactly once;
  - a self-test where 9 read samples, including the exact lines in `store.ts` and `backfill.ts`, pass.
- **The mutation.** I added `legacyCaptionText: '',` to `createPendingDraft`'s `data` in `generateDraft.ts`. The scan went red: `src\lib\agent\generateDraft.ts:242: object-literal key: legacyCaptionText: ''`. I restored the file from a byte copy, it has 0 hits, and the test is green again.
