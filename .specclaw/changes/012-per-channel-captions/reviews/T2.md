## Security checks

- **Scanner (extract.ts:49-81).** It is a single O(n) pass, with no regex and so no ReDoS risk. `json +=` is fine under V8 ropes. A `}`, `{` or `\"` inside a string value is handled, because string state and the escape flag are tracked. Nested objects are one span, and arrays are rejected by `parseCandidate`. A caption-shaped object planted inside a string value never becomes a span. A planted object in the preamble or trailer gives 2 candidates, so `multiple-objects`. A truncated or unbalanced planted object swallows the span, so `no-object`. Every ambiguous path fails closed.
- **Exactly-one and requested-keys.** The "exactly one candidate" check and the unknown-key check against the requested set both run before any field is read. `__proto__` arrives as an own key from `JSON.parse`, so it is rejected as an unknown key. A key outside the requested set cannot be smuggled in. Duplicate keys resolve last-wins in `JSON.parse`, which is harmless.
- **Order of operations (extract.ts:91-100).** CRLF replacement, normaliser, trim, empty check, then `captionLength` against `hardLimit`, all on the text that is stored. This is correct.
- **Headline (headline.ts:14-30).** The `**` removal loops to a fixpoint before the fence and `<<<` checks, so `` `**`` `` and `<<**<` cannot reassemble into a blocked token afterwards. Whitespace collapse removes every newline. The cap is applied after cleaning. Sound.
- **Prompt and extractor share the key list** via `captionReplyKeys`. The prompt's bullets and key line come from the registry. The test that mocks the registry is meaningful.

## Findings

### NOTE: src/lib/captions/extract.ts:25-26 / 74-80 (control characters)

Only `\n`, `\r` and `\t` are escaped inside strings. Any other raw C0 character (for example U+0008 or U+001F) makes `JSON.parse` throw, so the whole reply fails as `no-object`. That is fail-closed and safe. Escaping `/[\u0000-\u001f]/` generically (`\u%04x`) would be more tolerant of a noisy model. Optional.

### NOTE: src/lib/captions/extract.ts:56-61 (lone brace in prose)

A stray unmatched `{` in a preamble, such as "Here's the {draft:", opens a span that swallows the real object. The result is `no-object` and a failed regenerate, never a wrong write. The spec accepts this (departure 3). The fix, if it ever shows up in logs, is to retry the scan from the next `{` after a failed span. Not needed now.

### NOTE: src/lib/agent/prompts/caption.ts:60-66 (untrusted fencing)

`brief.topic`, `description`, `goal`, `tone`, `brandVoice` and `campaignBriefing` are interpolated raw, with no `fenceUntrusted` or `UNTRUSTED_CONTENT_GUARD`. This is identical to the old copy prompt (compared against `git show HEAD:copy.ts`), so there is no regression. The spec's fencing requirement is for the design and background prompts, which carry the headline (T5). The extractor is the real boundary here: planted JSON gives `multiple-objects`, and the model cannot add keys. Optional hardening: fence `description` and `campaignBriefing`.

### NOTE: src/lib/captions/headline.ts:14-30 (prompt rules not enforced)

The prompt says "no hashtags, no emoji, no markdown", but `validateHeadline` enforces only `**`, length, fences and `<<<`. A `#tag` or an emoji headline is accepted. The spec lists only the four reasons, so this is by design. Just be aware that the on-image headline is not emoji-checked. Design prompts T10 forbid emoji separately.
