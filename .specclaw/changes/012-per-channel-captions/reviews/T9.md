# Review: 012 T9 (the legacy rename)

**Mode:** full. Reviewed from `git diff -- prisma scripts src tests` plus the three new files, checked against design "Data Model Changes". Not re-run: tsc, unit, migrate.

## Spec compliance

Built what T9 said, nothing more.

- **Migration:** one statement, `ALTER COLUMN "copyText" DROP NOT NULL`. The column is not renamed (`@map("copyText")`), so the previous container still selects and writes `"copyText"` during a rolling deploy. Relaxing NOT NULL cannot break the old container's INSERTs or SELECTs. Safe (A1).
- **down.sql:** matches the design block word for word (the COALESCE of IG text, then LI text, then `''`, then `SET NOT NULL`, then the trailing comment). It lives outside `prisma/migrations/`, so `migrate deploy` never applies it. It restores the pre-012 shape: every post-012 draft gets a non-null legacy text, so the old image's non-null read works.
- **Placeholders:** both `copyText: ''` writes are gone (`generateDraft.ts`), and the writer tests assert `not.toHaveProperty('legacyCaptionText')`.
- **Reads:** the loader and the backfill read `legacyCaptionText`. The backfill adds the `{ not: null }` filter that the T-earlier TODO asked for, and its test pins the exact where clause.
- **Seed:** native fixtures (headline, three READY captions, no legacy text). They match the task's stated wording.
- **`grep copyText src` leftovers are acceptable:**
  - `instagram.ts` / `linkedin.ts` use a local parameter named `copyText`. It is not the column, and renaming would be churn outside the task's files. Optional later: rename to `caption` when the publishers are next touched.
  - The comments in `drafts/[id]/route.ts:221` and `captions/requests.ts:66` name the rejected legacy PATCH body, which is accurate.
  - The alias outputs in `generate/copy/route.ts` and `mcp/tools/generate.ts` are the intended A4 external name.

## Does the guard genuinely fail on a write?

Yes. It scans every `.ts`/`.tsx` under `src/`, with an allowlist of read forms, so an unknown form is flagged by default. The self-test proves each write form is caught (create, update and upsert keys, shorthand in both positions, `=`, `['…'] =`, `??=`, raw SQL on `"copyText"`). It also proves the read forms pass. A key whose value sits on the next line fails closed, because the allowlist test sees an empty value.

## Findings

### [NOTE] tests/unit/legacyCaptionGuard.test.ts:28-52 - line-based, not AST

**Problem:** the guard is regex on single lines. It cannot see a write through a spread (`data: { ...row }`) or a computed key built from a variable. It also does not scan `scripts/` (`import-posts.mjs` still uses `copyText`; T15 owns that, as stated).
**Fix:** none for T9. The Prisma type check is the real backstop, since a spread of a typed object still names the field somewhere. Revisit when T15 lands.

### [NOTE] src/lib/captions/backfill.ts:109, src/lib/captions/store.ts:159 - non-null assertions

**Problem:** `d.legacyCaptionText!` relies on a comment-documented invariant (the page filter in one case, `materializeStep` returning 'migrate' in the other).
**Fix:** acceptable and commented. If it ever drifts, the failure is in `migrateDraft` on a null, which the backfill already catches per row.

### [NOTE] Named risk, outside the diff - rolling-deploy window

**Problem:** between running the new image and a rollback, drafts created by the new image have `copyText` NULL, and the old image reads it as non-null. This is exactly what down.sql repairs, and it requires the operator to run it before booting the old image. FR-06 documents that, so no code change is needed.
**Fix:** none; make sure the T16 docs say "run down.sql before the old image".

## Verdict

PASS
