## Findings

### [WARN] src/lib/captions/store.ts:~330 (`settlePendingRows`) and ~355 (`settleCaptionAction` headline guard): stale worker vs a newer claim

**Problem:** The settle guards are "row is PENDING" and `pendingAction: 'REGENERATE_COPY'`. They identify a state, not the claim this run took. After the 15-minute sweep clears run A and the user starts run B (rows PENDING again, claim held), a late finish of A passes both guards and writes its text or headline over B's rows. The brief asks that a stale worker cannot overwrite a newer claim. This is the same known limit as the "claim token is a follow-up" ruling for 004. Real-world likelihood is low (a >15 min model call).
**Fix:** Accept and record it as the 004 follow-up. Do not widen T6. If cheap, compare `updatedAt` captured at claim against `Draft.updatedAt` in the headline `updateMany`.

### [NOTE] src/app/api/drafts/[id]/regenerate-copy/route.ts:~54-80: a throw after the claim strands the claim and the PENDING rows

**Problem:** If `startDraftAction` throws before the work starts (for example `resolveClaudeAuth`), the catch returns 422 with the claim held and the rows PENDING until the sweep (15 min). The claim half already behaved this way, but now the panels also show skeletons for that window.
**Fix:** In the catch, call `releaseDraftAction` and `settleCaptionAction(draft.id, targets, failedCaptionFields(...))`, but only when the claim was taken.

### [NOTE] src/app/api/drafts/[id]/route.ts (PATCH headline): headline edit is allowed while a generation runs

**Problem:** `saveHeadlineEdit` refuses only `REGENERATE_COPY`. An edit during an `IN_PROGRESS` generation can be overwritten when generation writes the headline.
**Fix:** Also refuse when the draft status is `IN_PROGRESS`, or accept this as benign.

### [NOTE] regenerate-copy body must be JSON (behaviour change)

**Problem:** An empty body now returns 400 "Invalid JSON body". All in-repo callers send `{}`, but an external script that POSTs with no body breaks.
**Fix:** Optional: treat an empty body as `{}`. Otherwise keep it documented.

### [NOTE] src/components/drafts/CaptionPanels.tsx: the "Regenerate all" button remains enabled during a generation's PENDING rows

**Problem:** It is gated on `ready` (EXPORTED or PUBLISHED), so it is correct while IN_PROGRESS. No fix is needed. Per-panel Regenerate and Undo are deferred to T11, as the report states.
