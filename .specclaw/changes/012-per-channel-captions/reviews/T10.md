## Safety

- `testDbUrl()` refuses anything whose pathname does not end in `_test`, and it throws before any script or SQL runs. The scratch URL is derived from that URL.
- `run()` spreads `.env.test` over the process env and then pins `DATABASE_URL` last. Node's `--env-file` never overrides an existing variable, so `.env` cannot redirect the backfill to the dev DB.
- The scratch DB is dropped with `WITH (FORCE)` before creation (stale leftovers) and again in `finally`, after `$disconnect`. The drop runs on the test DB connection, which is not the scratch DB.
- The Post that TC-CAP-12 creates is deleted in `finally`.
- The `workers: 1` and `fullyParallel: false` settings mean no other test writes legacy drafts while the backfill counts "2 drafts".

## Findings

### [NOTE] tests/e2e/captions.test.ts:371-375 - TC-CAP-09 releases the claim outside a finally

**Problem:** the `pendingAction` and PENDING-row seed is undone at the end of the case. If an assertion above fails, that draft is left claimed. It is a test-owned draft, so nothing else meets it, and the 15-minute sweep would heal it.
**Fix:** wrap the assertions in `try { … } finally { release }`. Optional.

### [NOTE] tests/e2e/captions.test.ts:523 - the TC-CAP-12 "clear" run migrates every legacy draft in the test DB

**Problem:** this makes the later counts deterministic, which is the intent. It also means the case depends on the whole test DB being free of other legacy-shaped drafts at that moment. With one worker that holds. A future parallelisation, or a suite that leaves legacy drafts, would flake the "2 drafts" line.
**Fix:** none now. If this ever flakes, assert with `toMatch(/split \d+/)` on the totals and keep the per-draft DB assertions as the real check.

### [NOTE] tests/e2e/captions.test.ts:595-598 - the scratch DB name is not itself guarded

**Problem:** the name is hardcoded and the URL is derived from the guarded test URL, so this is safe today. The `DROP DATABASE` string is unguarded against someone editing the constant.
**Fix:** none needed.

### [NOTE] Named risk, outside the diff - CI runs of the backfill

**Problem:** `--env-file-if-exists` fixes the missing `.env`. TC-CAP-12 and TC-CAP-13 also shell out to `npm`, `npx` and `tsx`, and `captions:backfill` needs the CI job's `DATABASE_URL` to end in `_test`. The workflow env must carry it, because `readEnvTest` falls back to `process.env` and `testDbUrl` throws otherwise. I did not inspect `e2e.yml`. T10's report says the case passes locally only; confirm on the first CI run.
**Fix:** check the first fork CI run, not a code change.
