## Findings

### [WARN] captions.test.ts TC-CAP-15, `expect(done.headline).toBe(draft.headline)`

**Problem:** The mock headline is deterministic per topic (`Mock headline ${topic}`, per TC-CAP-16). If `{}` wrongly regenerated the headline, it would write the identical value and this assertion would still pass. The headline half of "never the headline" cannot fail here.
**Fix:** Make the headline distinguishable first. For example, PATCH the headline to a hand value before the regenerate, then assert it survives. TC-CAP-15 needs no DB access for that.

### [NOTE] N1 captions.test.ts `AXE_RULES`: duplicated list

**Problem:** A second copy of the 12 rules can drift from `a11y.test.ts`.
**Fix:** In a later cleanup, move the list and `expectNoAxeViolations` to `tests/helpers/axe.ts` and import it from both files. Not for this gate.

### [NOTE] N2 TC-CAP-18, `grantPermissions(['clipboard-read','clipboard-write'])`

**Problem:** This works in Chromium, including headless, which is what CI runs. It throws on Firefox and WebKit projects. Playwright config is outside the diff; if the suite is Chromium-only there is no issue.
**Fix:** None now. If a second browser project is ever added, guard on `browserName`.

### [NOTE] N3 TC-CAP-17, `.locator('section').filter(...).last()`

**Problem:** `.last()` depends on nesting order. A wrapping section that also contains the h2 would be skipped, but a restructure could silently change which one is picked.
**Fix:** Optional. Scope by a `data-testid` or `aria-labelledby` if the desk gains one.

### [NOTE] N4 Fixed sleeps and DB safety

**Problem:** None found. There are no fixed sleeps. Every wait is a `toBeVisible`, `toHaveValue` or `expect.poll`. DB access is only `makeLegacyDraft` (guarded by `dbAvailable` skips) and the API client. There is no dead code.
**Fix:** None.
