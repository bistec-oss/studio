## Known limits

These are carried over from `verify-notes.md`. They are deliberate rulings or accepted limits, not defects.

- **The background skip notice is per draft, not per revision** (T2 concern 4). After a restore or Undo, the notice describes the latest generation, regenerate or refine. This matches how `imageUrl` already behaves.
- **A rejected (not-applied) refine, or a brand-kit-conflicted refine, records no skip** (T2 concern 3).
- **A refine on a team with no image provider leaves the skip unchanged** and never records NO_PROVIDER itself (T2 ruling). Generation on that team has already recorded NO_PROVIDER. E2E `background-notice.test.ts:315` covers this.
- **The skip-detail redaction of `name:digits` host:port is broad,** so a string like `status:429` also reads as `<host>` (T2 fix round, FR-3).
- **The refine skip writer stores only PROVIDER_ERROR.** NO_PROVIDER and DECISION_ERROR from a refine leave the notice unchanged, by design. Refine resolves the image provider first (T2 fix round).
- **"Exactly the allowlist" holds at the `buildChildEnv` level.** On win32, libuv re-adds non-secret required vars (HOMEDRIVE, HOMEPATH, USERNAME, WINDIR…), and cmd.exe adds PROMPT. None of them is a secret (T4 review).
- **AC-16 is an operator run** (docker-build-local, the user's own token through `--env-file`). It is recorded above with the pinned version 2.1.287.
- **The CLI vision size guards** are 5 MB per image (stricter than the direct API's limit) and 32 MB per call. The 600k prompt guard counts text only (T6, superseding T5).
- **The pinned CLI 2.1.287 declares Node ≥22,** and the `v2` runner is node:20, which only prints an EBADENGINE warning.
- **Unit runs leave empty `bistec-cli-*` temp dirs** (the real `mkdtemp` runs).
- **Gemini (T8) is mock-verified only.** No live key was used. The shapes are from https://ai.google.dev/api/generate-content and https://ai.google.dev/gemini-api/docs/image-generation as of 2026-10-02. The model is `gemini-3.1-flash-image`, called over generateContent, not the newer Interactions API that the image-generation page's REST examples use.
- **Other binding build rulings:**
  - FR-02 and FR-03 apply to the IMAGE slot only, and COPY behaviour is byte-identical to before 005 (T1).
  - The moderation regex is anchored, and provider detail is redacted (T2).
  - Auth classification reads only CLI-written fields: `api_error_status` 401, or 403 with "OAuth token revoked" result text. It never reads model text (T5 → T6).
  - Settings isolation uses `--safe-mode`, `--setting-sources ""`, `--no-session-persistence`, an empty temp cwd and `DISABLE_AUTOUPDATER=1` (T6; FR-08/AC-14 amended).
  - The native installer is the primary Windows route, with winget as the alternative (T9; FR-14/AC-22 amended).
