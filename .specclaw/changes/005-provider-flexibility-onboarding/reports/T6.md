### Notes on individual items

- **Item 9: re-implemented, not imported.** In the standalone image, `claudeCli.ts` exists only inside Next's server chunks, and `dist/scheduler/worker.js` doesn't export it. So the script restates the stream-json argv and the POSIX `buildChildEnv`.
  - **Drift guard:** a unit case imports `sandboxArgs`, `sandboxChildEnv` and `VISION_MODEL` from the script and checks them against the argv the real `runClaudeCliStreamJson` spawns and against `buildChildEnv(parent, 'linux', token)`.
  - The script's `main()` runs only when the script is executed directly, so the unit run never makes a call.
- **Item 16: 403 is not treated as an auth failure.** Only a structured 401 is. A permission or plan 403 doesn't mean the token is bad, and I couldn't observe what the CLI reports for a revoked token. A status-less `is_error` result falls back to the regex over the result text and stderr only.
- **Item 16: text mode is unchanged.** On a non-zero exit, text mode still classifies raw stdout. A `-p` text run prints only its final result, so model text there can only appear on exit 0, which is never classified.
- **Item 17: `StringDecoder` instead of `setEncoding`.** The effect is the same, and the four test files' fake children (plain `EventEmitter`s with no `setEncoding`) keep working unchanged.

**Fix 1 in detail:**

- **Text-only check.** The 403 branch tests `err.stdout` only, never stderr. For a stream-json run, `finalizeStreamJson` fills `stdout` only with the `result` text of an **is_error** result, and fills it with `""` otherwise. Assistant text and non-JSON lines go to the human-only `diagnostic`.
- **Model text stays out.** `apiErrorStatus` is set only by a stream-json run. Text mode never sets it, so its raw stdout never reaches this branch. For an is_error result, the text is the CLI's own rendering of the API error. Examples:
  - the observed 401 `"Failed to authenticate. API Error: 401 OAuth access token is invalid."`;
  - the binary's `"OAuth token revoked · Please run /login"`.

  That text is never model output, which is the item-16 contract.

- **What I couldn't prove.** I could not watch a real revoked-token run, so the 403 shape comes from the controller's reading of the binary.
- **Unit cases:**
  - 403 + revoked text gives an auth failure, and the personal → team retry fires: `visionCli.test.ts:465` and `claudeCliAuth.test.ts:113`.
  - 403 permission_error with other text, even text containing "Please run /login", is not an auth failure: `visionCli.test.ts:477`.
  - 403 whose result isn't is_error is not one: `:489`.
  - 403 with an empty is_error result, where the revoked text appears only in assistant text or stderr, is not one: `:500` and `claudeCliAuth.test.ts`.
  - 401 is unchanged, and another status with the revoked text is still not one.

**Fix 2 in detail:**

- **Re-check, then re-create.** Before every reuse, `spawnCwd` checks the cached dir with `stat(dir).isDirectory()`. If the dir has gone, it makes a fresh `bistec-cli-*` dir and caches that.
- **The race.** The dir could still vanish between that check and the spawn. In that case the spawn's ENOENT handler sees `!existsSync(cwd)` and rejects with a plain Error, "Claude CLI working directory … disappeared before the spawn (a temp cleaner?). Retry the request.". That is never an auth failure, and the next call's check re-creates the dir.
- **The not-found message.** The friendly not-found message stays only for ENOENT with the cwd intact, which means a genuinely missing binary.
- **Tests:**
  - `claudeCliArgs.test.ts:417`: the dir is re-created and reused afterwards.
  - `:434`: the mid-flight ENOENT isn't reported as "not found", and the next call recovers.
  - `:452`: the not-found message is kept for a missing binary.
  - To support them, the fake spawn gained `spawnErrorCode` and `onSpawn` hooks.

**Fix 3 in detail:**

- **The sample env.** The sample parent env is built from the exported `CHILD_ENV_ALWAYS` plus `CHILD_ENV_WIN32` (21 names), plus these secrets: `DATABASE_URL`, `BISTEC_CANARY`, `TOKEN_ENCRYPTION_KEY`, `ANTHROPIC_API_KEY`, a stale `CLAUDE_CODE_OAUTH_TOKEN` and `DISABLE_AUTOUPDATER=0`.
- **What it asserts.** The test asserts that the real POSIX child carries every POSIX name, and that `sandboxChildEnv` equals `buildChildEnv(…, 'linux', …)`.
- **Because the lists are imported, not copied:**
