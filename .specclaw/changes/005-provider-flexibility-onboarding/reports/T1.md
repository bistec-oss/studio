## Decisions

- **COPY compatibility.** `instantiateCopyProvider` supports `cli`, `openai` and `anthropic`. Today's POST accepts _any_ `providerName` for COPY with an unrecognized key format; the existing TC-PROV cases register `groq`, `testprovider`, `provA` and `provB` that way. To keep that flow unchanged, COPY refuses only a provider that is **known** (in either `SLOT_PROVIDERS` list) but not in the COPY list. Today that is `gemini` only. An unknown name still passes for COPY, as the spec's "unknown provider name is refused for IMAGE" implies. IMAGE is strict: only `openai` and `gemini`.
- **First-row default ignores an explicit `isDefault:false`.** FR-02 says the row "is stored with `isDefault: true`" whenever the slot has no enabled default, so a request can't opt out of that. The /team form never sends `isDefault`.
- **First-row default applies to both slots,** following the brief and design ("in that slot"). Both seeded teams have an enabled `cli` COPY default, so this never fires for COPY in the seeded data.
- **A disabled row can't be the default** (400). FR-03 asks for coherent default state. Without this, `PATCH {isDefault:true}` on a disabled row would take the default away from an enabled row, and teammates would quietly drop to the fallback.
- **The mock seam sits at the top of `validateApiKey`.** It covers every provider, including T8's gemini branch, without further edits. For an unknown provider, the only change under `MOCK_AI` is that a key containing `invalid` now gets 422; live, an unknown provider still skips validation.
- **The E2E suite uses a fresh team per case** rather than purging rows from Bistec. This also fixes a latent pollution problem: before, TC-PROV-06 cleared Bistec's seeded `cli` COPY default and never restored it.

## Concerns

1. **Gemini rows between T1 and T8.** `gemini` is image-capable for the routes and the resolver now, but `instantiateImageProvider` has no gemini case until T8. A manually named `gemini` IMAGE row (unknown key format, `providerName: 'gemini'`) can be registered, and if it is chosen the resolver throws `Unsupported provider`. Callers already guard this (`background.ts` catches it). This only exists on `v2`, never on prod. T8 closes it.
2. **Concurrent first registrations.** Two POSTs racing in the same slot with no default can both read "no enabled default" under READ COMMITTED and both store `isDefault:true`. Design §Data Model rejected a partial unique index. The resolver stays deterministic (oldest default), and the next default toggle repairs the state. Low risk; noted, not fixed.
3. **CLI mode, COPY slot.** With no COPY default, an API-key COPY row registered **via the API** (the /team UI hides COPY in CLI mode) would now become the default. That overrides the CLI copy path for that team. This follows the brief's slot-generic rule, but the effect differs from IMAGE. If that is unwanted, restrict FR-02 to IMAGE.
4. **Release note (NFR-03).** Teams whose only IMAGE key isn't flagged default now spend on it for scheduled, MCP and API-agent images. This was already called out in the spec.
5. **Case sensitivity.** The `in` filter is case-sensitive. Rows written through the route are lowercased, and the old `instantiateImageProvider` lowercased before matching, so a hypothetical legacy `"OpenAI"` row seeded outside the route would now be skipped. None is known.
