## Concerns

1. **Refine now always runs its decision first.** Before T2, a refine on a team with no image provider skipped the Haiku decision entirely. Now it spends one decision call, because that is the only way to tell "wanted a background, none set up" (`NO_PROVIDER`, which is recorded) from "didn't want one" (`NOT_NEEDED`, which leaves the draft alone), as the brief's refine semantics require. On a team with a provider the calls are unchanged; only the order differs. The cost is one Haiku call (about 2–5 s in CLI mode, with a 90 s cap) per refine on a team with no provider. The pre-existing unit case "refine: no provider ⇒ decision never called" was rewritten to the new contract. If that cost is unwanted, the alternative is to treat refine-without-a-provider as "unknown", leave the skip unchanged, and lose `NO_PROVIDER` for refine.
2. **Out-of-list edit: `tests/e2e/path-a.test.ts`.** The skipped TC-GEN-05 stub actually lived in `path-a.test.ts`, not in `path-b.test.ts` as the brief says. I moved it to path-b, because only Path B generates a background, and left a 3-line pointer comment in path-a. Without removing the stub, skips could not drop to 3.
3. **A refine that is rejected (not applied) or hits a conflict records no skip,** even if its background failed. Only a committed refine writes, and that matches how `imageUrl` behaves.
4. **Restore and Undo don't touch the skip fields,** just as they don't touch `imageUrl`. After an Undo of a regenerate, the notice describes the latest regenerate, not the restored version. This is pre-existing behaviour for `imageUrl`, and the spec says nothing about it.
5. **`renderStamps.test.ts` mocks `runPathBDesign` without the new `background` field.** It still passes, because `generationSkipFields` treats a missing result like Path A (clear). I didn't edit that file, since it isn't in the T2 list.
6. **The mock seam's `NOT_NEEDED` sentinel on a team with no provider** gives `NO_PROVIDER` for generation, because generation resolves first, as in prod. TC-BG-08 relies on exactly that.
