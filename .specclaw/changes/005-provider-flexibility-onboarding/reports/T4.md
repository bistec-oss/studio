## Smoke test

No token is stored in the dev DB: there is no ACTIVE `UserClaudeToken` row and no team token. So the full `runClaudeCli` path with a real token was not possible.

I ran three things instead. No token value was printed.

- **(a) The real `runClaudeCli` inside `runWithClaudeAuth`, with a deliberately FAKE token.**
  - It spawned `claude.exe -p --strict-mcp-config --tools  --model haiku`. That `.exe` comes from `CLAUDE_CLI_PATH` in `.env`, so `shell:false`.
  - The CLI booted under the allowlisted env and printed stdout.
  - It exited 1, and the run was classified as an **auth failure**, so the retry path fired.
  - This proves the arguments parse (no "unknown option" error) and that the env is enough for the CLI to start.
- **(b) The same command, args and `buildChildEnv` env, minus `CLAUDE_CODE_OAUTH_TOKEN`,** so the CLI used the developer's logged-in session under `USERPROFILE`. Run with `--output-format stream-json --verbose` to read the `init` event:

## Concerns

1. **Node 24 emits `DEP0190`** whenever `shell:true` is used with an args array, because the args are concatenated and not escaped. This was already true of the old `claude.cmd` spawn.
   - It is harmless here: no user input is in argv, since the prompt and token go via stdin and env.
   - But it will print a warning on every Windows dev spawn, and a future Node may remove the behaviour. Two ways out later: pass one pre-joined command string with `shell:true`, or resolve `claude.exe` / `claude.cmd` ourselves.
2. **The child no longer inherits `NODE_ENV`, `windir`, `CLAUDE_CONFIG_DIR` or the rest of the parent env.**
   - This is by design (FR-10), and the Windows smoke test shows the CLI works without them.
   - A dev who relies on `CLAUDE_CONFIG_DIR` would lose it. It is not in the allowlist and I did not add it.
   - The container-side proof is T6 / AC-16.
3. **The log line now reads `stdin=N chars` instead of `prompt=N chars`.** This is diagnostic only.
4. **No E2E run.** `.env.test` runs `DESIGN_PROVIDER=claude-html` (API mode), which never spawns the CLI, so E2E cannot exercise this change.
