## Chosen model

`gemini-3.1-flash-image` (Nano Banana 2), marked "Stable" on its model page (last updated 2026-09-03).

- The docs call it the "generalist workhorse".
- `gemini-2.5-flash-image` is "legacy", and Google recommends moving off it.
- Its aspect-ratio table at 1K lists 1:1 (1024x1024), 4:5 (928x1152) and 9:16 (768x1376).
- No `imageSize` is sent, so the documented default of 1K applies.

## Cited docs (checked 2026-10-02), with the request and response shapes

- https://ai.google.dev/gemini-api/docs/image-generation (last updated 2026-09-23): the model list and the "Aspect ratios and image size" tables.
  - **Notable:** this page's REST examples now use the **Interactions API** (`POST /v1beta/interactions`, `response_format.aspect_ratio`, `steps[].content[]`).
- https://ai.google.dev/gemini-api/docs/migrate-to-interactions (2026-09-23): "While generateContent remains fully supported, we recommend the Interactions API for all new development."
- https://ai.google.dev/gemini-api/docs/interactions-overview (2026-10-01): it lists "Custom safety settings are not supported in the Interactions API".
- https://ai.google.dev/api/generate-content (2026-09-23), the shapes used:
  - **Endpoint:** `POST https://generativelanguage.googleapis.com/v1beta/{model=models/*}:generateContent`.
  - **Request:** `{ "contents":[{"parts":[{"text":prompt}]}], "generationConfig":{ "responseModalities":["TEXT","IMAGE"], "imageConfig":{"aspectRatio":"4:5"} } }`. `ImageConfig.aspectRatio` lists "1:1, 1:4, 4:1, 1:8, 8:1, 2:3, 3:2, 3:4, 4:3, 4:5, 5:4, 9:16, 16:9, or 21:9".
  - **Response:** `candidates[].content.parts[].inlineData { mimeType, data }` (the base64 image).
  - **Blocks:** `promptFeedback.blockReason` ("If set, the prompt was blocked and no candidates are returned"). `Candidate.finishReason` includes SAFETY, PROHIBITED_CONTENT, IMAGE_SAFETY, IMAGE_PROHIBITED_CONTENT, IMAGE_OTHER, NO_IMAGE and IMAGE_RECITATION.
- https://ai.google.dev/gemini-api/docs/safety-settings (2026-09-17): "If promptFeedback.blockReason is set, then the content of the prompt was blocked … finishReason was SAFETY … The content that was blocked is not returned."
- https://ai.google.dev/gemini-api/docs/troubleshooting (2026-10-01): the error statuses. The `{error:{code,message,status}}` envelope is Google's standard API error body.

## Concerns

1. **The image-generation page now documents the Interactions API, and this provider uses generateContent.**
   - I chose generateContent for three reasons. It is documented as fully supported. Its reference documents how a blocked prompt or image appears (`promptFeedback.blockReason`, `finishReason`). The Interactions reference documents no equivalent for a blocked image. The header comment records this.
   - If Google ever retires generateContent for image models, switching to `/v1beta/interactions` is contained in this one file.
2. **The `responseModalities: ["TEXT","IMAGE"]` combination is the long-documented one.** Whether `["IMAGE"]` alone is accepted by 3.1 Flash Image isn't stated on the reference page, so I didn't rely on it.
3. **The storable mime list is duplicated from `RASTER_IMAGE_TYPES`** (4 entries, commented), so that importing the provider doesn't construct the S3 client or require every unit test's minio mock to export it. If `RASTER_IMAGE_TYPES` changes, this list should follow.
4. **Recitation and other no-image finish reasons read as "no image",** not as a refusal. They aren't safety blocks, so the draft notice shows the provider-error sentence with the reason.
5. **WebFetch was blocked for `ai.google.dev`** ("Unable to verify if domain … is safe"). The pages were fetched with curl and read locally. No Gemini API call was made with any key, real or fake: all E2E validation went through the MOCK_AI seam.
6. **TC-BG-11 isn't added to the `docs/e2e-test-plan.md` catalog,** because that file is outside the T8 list.
