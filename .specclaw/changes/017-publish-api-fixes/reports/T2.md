# T2 report — Check order, and the posts list's batch caption load

**Implemented by:** the orchestrator directly. It is small, and the files were already read.

## Changes

- **`src/app/api/posts/route.ts`:**
  - POST runs its checks in this order: the input checks (400/404/422), then `scheduledAt` validation (400), then the duplicate check (409), then the caption check (422) (FR-05).
  - The caption check still precedes both the scheduled and the immediate branches, so a refusal never leaves a row.
  - The GET reads the page's captions with `loadCaptionTexts` in one query (FR-06).
- **`src/lib/captions/store.ts`:** new `loadCaptionTexts(posts)`.
  - It runs one `draftCaption.findMany({ draftId: { in } })` over de-duplicated draft ids, and no query for an empty page.
  - It returns a map keyed `${draftId}/${channel}`. A missing row reads as `''`, the value `loadCaptionText` returns.
  - It deliberately does not fill missing rows; the single-draft readers still do that.
- **`tests/unit/jobRunner.test.ts`:**
  - the `draftCaption.findMany` mock is wired;
  - AC-05: three posts across two drafts, one query, a missing row reads as `''`, and no single-draft load;
  - AC-04: a live post plus a refused caption gives 409 with `postId`, and no row is created.
- **`tests/unit/captionStore.test.ts`** (review NOTE 1): direct `loadCaptionTexts` cases. An empty page runs no query; the ids are de-duplicated; a missing row reads `''`; nothing is written.
