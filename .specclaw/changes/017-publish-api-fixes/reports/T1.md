# T1 report — A failed publish or retry is a 502, and the UI shows it

**Implemented by:** implementer subagent; condensed by the orchestrator.

## Changes

- **`src/app/api/posts/route.ts` (FR-01):** the immediate path returns **502** `{error: post.errorReason ?? error.reason, code:'PUBLISH_FAILED', postId, status}` when `createAndPublishPost` returns an error. The FAILED row is still written, and success stays 201.
- **`src/app/api/posts/[id]/publish/route.ts` (FR-02):** a retry that throws `PublishError` updates the row to FAILED, as before, and returns the same 502 shape. Success stays 200.
- **`src/components/library/PublishDialog.tsx` (FR-03):**
  - a visible reason line under a failed channel (`text-ui-xs text-status-failed`), linked to its checkbox with `aria-describedby`;
  - a failed channel is not locked;
  - the dialog already skipped `onSuccess` when any channel failed; it now actually sees failures.
- **`src/app/(app)/library/page.tsx` (FR-04):**
  - `handleRetry` now catches: `toast.error("Retry failed: <reason>")` on failure, `toast.success` on success;
  - the history drawer row is updated in place, and the library query is invalidated;
  - closing the dialog also invalidates the library.
- **`drafts/[id]/page.tsx`:** no change needed.
- **Tests:**
  - `jobRunner.test.ts` gets 4 new cases: immediate 502 with a FAILED row; immediate 201; retry 502 with a FAILED row and `nextRetryAt` null; retry 200.
  - E2E: TC-PUB-03 now expects 502 for the immediate failure and for a failing retry.
  - New TC-PUB-10 (AC-03): a `__FAIL_ALWAYS__` draft published through the dialog shows Instagram ✕ failed with "Mock Instagram publish failure" visible (and as the checkbox's accessible description, still enabled), LinkedIn ✓ published and disabled, and the dialog stays open with its summary.
