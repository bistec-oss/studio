# 014 T10 report: one control height per size, from tokens

**Status:** built.

## Tokens

- **`globals.css` `:root`:** `--control-sm: 30px`, `--control-md: 36px` and `--control-lg: 40px`. They are theme-independent.
- **`tailwind.config.ts`:** `theme.extend.spacing` gains only `control-sm|md|lg` → `var(--control-*)`. No default spacing key is redefined.

## Changes

- **`Button` sizes:** sm, md and lg use `h-control-sm|md|lg`.
- **`Input.tsx`:** a private `fieldBase` builds both strings. `fieldClasses` (textareas) keeps `px-3.5 py-2.5`, and the new `inputClasses` is `h-control-md px-3.5`. `Input` and `Select` use `inputClasses`.
- **`ui/folio.ts`:**
  - `ICON_BUTTON` → `h-control-sm w-control-sm`;
  - `COMPACT_FIELD` → `h-control-sm`, with no vertical padding;
  - **new `COMPACT_TEXTAREA`** = the compact box + `py-1.5`.
- **`AppShell`:** `SHELL_ICON_BUTTON` → md. The dashboard `QuickAction` → md.
- **The library search, brief Topic and font search** use `inputClasses`.
- **`ImagesStep`:** the intent and remove buttons use sm.
- **`PostCard`:** the delete and expand buttons use sm.
- **`ElementEditPanel`:** the colour well uses md.
- **`BrandKitAssistantPanel` (not in the T10 list, deliberately):** its "Brand voice" textarea used `COMPACT_FIELD`. It switches to `COMPACT_TEXTAREA`, so it doesn't collapse to 30 px. This is logged as a `design_gap`.

## Left alone

- Textareas, `CODE_FIELD`, `TITLE_FIELD` and the prompt fields.
- The library skeleton bar and the brief image thumbnail. Neither is a control, and the guard names both as exceptions.
- Still literal 30 px, outside T10's list: the draft-page expand button and the `KitDetail` feed-to-AI switch.
- DESIGN_SYSTEM §9 wording (FR-20 hands §9 to T18).

## Tests

- **`designTokens.test.ts`, "control heights (014 AC-06)":**
  - the `:root` values;
  - the spacing map (only the three keys);
  - one `h-control-*` per Button size;
  - `inputClasses`, `Input` and `Select` carry `h-control-md` with no `py-`;
  - `fieldClasses` and `COMPACT_TEXTAREA` have no height;
  - `COMPACT_FIELD` and `ICON_BUTTON` use sm;
  - the AC-06 per-file grep over the FR-07 files.
- **`a11y.test.ts`, "Control heights (T10)", 2 cases:**
  1. the campaign Input, Select and Create button are 36;
  2. the add-colour field and Add are 30, and the font search is 36.

  Each case then overrides `--control-sm` and `--control-md` and asserts the controls follow, so a literal height fails.

- **Mutation proof:**
  - **Unit:** 8 mutations each turned a test red: the Button md, the token value, `ICON_BUTTON`, the Tailwind map, `AppShell`, `PostCard`, `inputClasses` and `COMPACT_FIELD`.
  - **E2E:** a Button md literal failed with "expected 52, got 36", and a `COMPACT_FIELD` with `py` failed with "expected 30, got 34.25".
