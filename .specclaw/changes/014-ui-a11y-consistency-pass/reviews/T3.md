## Findings

### [WARN] src/app/(app)/library/page.tsx:152-169 -- search box can no longer shrink between md and about 860 px

**Problem:** The search box was a direct flex item (`relative w-full sm:w-72`) of the head row. Its `input` is `w-full`, so its min-content is about 0 and the box shrank when the row ran short. It is now inside `PageHead`'s `actions` wrapper (`flex flex-wrap items-center gap-2`). The wrapper is the flex item, and its auto min-width is the min-content of its child, which is the fixed `sm:w-72` (288 px). So the wrapper cannot shrink below 288 px.

- At 768 px the content width is 768 - 220 (sidebar) - 64 (padding) = 484 px.
- The row needs about 270 (lead) + 16 + 288 = 574 px.
- Before: both columns shrank, and the search came out at about 240 px.
- Now: the search stays at 288 px and the title/lead column takes all the shortfall (about 180 px), so the lead wraps earlier.
- This shows from `md` (768) up to roughly 860 px. It does not show at 375 or 1440, the two widths the task named. So it passes those checks, but it is not a visual no-op, and A5 does not list it as accepted.

**Fix:** Let the search shrink. Do one of:

- give the search div `sm:w-72 sm:min-w-0 sm:shrink` and add `min-w-0` to PageHead's actions wrapper (a fixed width still sets the wrapper's min-content, so verify);
- or switch the search to `sm:basis-72 sm:min-w-0 sm:shrink` / `w-full sm:w-72 max-w-full`.

Whichever is chosen, check it with the compare script at 768 (and ~820).

If the 768 look is judged acceptable, record it as an accepted drift in `reports/T3.md` and A5 instead. The implementer's "none expected" claim is not accurate for this width.
