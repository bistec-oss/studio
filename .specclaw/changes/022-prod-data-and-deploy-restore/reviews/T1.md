### [NOTE] scripts/test-upgrade-path.mjs:85 - safety

`const SOURCE_URL = process.env.DATABASE_URL || ...` Only the database name is pinned; the host is whatever DATABASE_URL points at. A shell that exports a prod DATABASE_URL would CREATE/DROP `bistec_studio_upgrade` on the prod server (never any real database, but still a write on prod). The T1 incident came from this class of mistake. Optional: refuse unless the host is localhost/127.0.0.1 or CI is set. Does not affect the data-safety of the migration.

### [NOTE] prisma/migrations/20261012130000_legacy_caption_carryover/migration.sql:49

`CREATE TABLE "LegacyCaptionArchive"` has no IF NOT EXISTS, so a re-run after a manual partial state fails loudly. This is the safer behaviour (the atomic block means no partial state arises) and matches the header's documented recovery. No change needed.
