# T2 — The env preflight before migrate, the catalogue comment and the restored deploy workflow

**Covers:** FR-04, FR-05, FR-06; AC-06, AC-07, AC-08. No commit was made (the orchestrator commits).

## Changes

- **`src/scripts/env-preflight.ts` (new, lines 1–31).**
  - It loads `@/lib/env` with a dynamic `import()` inside `try`. That way a throw while `env.ts` evaluates lands in the `catch`: the zod parse, the `CLAUDE_CLI_MODEL` transform or the production fail-fast checks.
  - On success it prints `[preflight] environment ok`. On failure it prints `[preflight] environment invalid — refusing to boot (no migration was run):` and then the error message to stderr, and exits 1.
  - There is no skip flag. `env.ts`'s own build-phase skip keys on `NEXT_PHASE`, which is never set at container boot.
  - It uses an async `main()` rather than top-level await, because esbuild's `--format=cjs` cannot emit top-level await.
- **`Dockerfile`.**
  - **Lines 59–69:** a new builder-stage `RUN npx esbuild src/scripts/env-preflight.ts` step, with the same flags as the worker (`--bundle --platform=node --format=cjs --external:@prisma/client`), writing to `dist/scripts/env-preflight.js`.
  - **The existing `COPY --from=builder /app/dist ./dist`** carries it. Its comment now names both bundles (lines 135–136).
  - **The entrypoint COPY comment** now reads "Runs the env preflight, applies pending migrations, then execs CMD" (line 138).
  - No `GIT_SHA` comment was touched (ruling 7).
- **`docker-entrypoint.sh`** keeps LF line endings (0 CR bytes) and passes `sh -n`.
  - **Lines 2–3:** the header summary now begins with the environment check.
  - **Lines 21–31:** the header explains why the preflight runs first. The app validates env only after `migrate deploy` has changed the schema, so the "previous container keeps serving" fallback no longer held. The preflight runs even with `SKIP_MIGRATIONS=1`, and it is fail-closed with no skip flag.
  - **Lines 38–40:** `node dist/scripts/env-preflight.js` runs under `set -e`, after `CHECKPOINT_DISABLE` and **before** the `SKIP_MIGRATIONS` branch.
- **`src/lib/models/catalogue.ts` lines 13–21:** the FR-05 comment block "Prod boot depends on this file (change 022 FR-05)".
  - The preflight validates `CLAUDE_CLI_MODEL` against `MODEL_KEYS` and the current apiIds.
  - A value that is no longer accepted blocks prod's boot.
  - So before removing or renaming a key, or retiring an apiId into `previousApiIds`, check prod's Coolify `CLAUDE_CLI_MODEL` (app and scheduler) first.
- **`.github/workflows/docker-publish.yml`** is restored by `git checkout a3cecda^ -- .github/workflows/docker-publish.yml` and was not edited. That command **staged** the file (`A` in the index).
- **`.github/workflows/e2e.yml`:**
  - **Lines 8–13, the header:** the fork wording is gone. It now says that this workflow gates every PR and every push to `v2` and `main`, checks only, and that `docker-publish.yml` deploys on pushes to `main` (GHCR, both Coolify redeploys, the `/api/health` commit check).
  - **Lines 253–294, a new `build`-job step** after "Docker image build": "Env preflight runs before migrations (runner image)".
    - It boots `bistec-studio:ci` twice, with `--network none`, `timeout 120` and the job's validly shaped dummy env passed by name (`-e DATABASE_URL -e TOKEN_ENCRYPTION_KEY …`).
    - **`default` must:** exit non-zero (and not 124, a timeout), name `CLAUDE_CLI_MODEL`, and contain no `[entrypoint] applying pending Prisma migrations`.
    - **`sonnet` must:** exit non-zero (and not 124), and show the ok line on an earlier line than the applying line.
  - **Line 92:** the MinIO comment's "a maintained drop-in fork" now reads "a maintained drop-in replacement". It was the only other "fork" in the file, and AC-08 requires `grep -ci fork` to print 0.
  - **Lines 101 and 171:** `for i in` becomes `for _ in`; see the decisions.

## Decisions

- **Dynamic `import()` rather than a static import.** With a static import, `env.ts`'s throw would escape as an uncaught module-load error. The exit code would still be non-zero, but the output would be a raw stack with no `[preflight]` framing. esbuild bundles the dynamic import into a lazily initialized module in the same file, so it is still one self-contained bundle.
- **`--external:@prisma/client` was kept** on the preflight bundle. `env.ts` never imports Prisma, so the flag has no effect; it is there only because the spec says "the same esbuild flags as the worker".
- **The CI step passes env by name** (`-e NAME`) from the `build` job's existing dummy env, so the values live in one place. It asserts that the `sonnet` run's exit is non-zero (the unreachable database), and it treats exit 124 (a `timeout` kill) as a failure in both cases, so a hang cannot pass.
- **Two `e2e.yml` edits outside the letter of the task, both needed for AC-08 to be satisfiable:**
  - "drop-in fork" → "drop-in replacement" (MinIO comment, line 92), so `grep -ci fork` prints 0.
  - `for i in` → `for _ in` (lines 101 and 171). These fix pre-existing shellcheck SC2034 warnings that made actionlint exit 1 before this change.
- **Neither the entrypoint's `SKIP_MIGRATIONS` semantics nor the env vars changed** (NFR-04).
- **No DB command was run.** The only database-shaped strings used were the bogus `localhost:5432/x` and `127.0.0.1:1` URLs, which nothing could reach.
