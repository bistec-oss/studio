## FR-05: the caption and headline Undo settle on state (L25)

This copies the RefinementPanel `settleArmed` pattern from change 015. The panel arms only after the awaited post-202 refetch. It settles once the polled `pendingAction` is null. Then it clears the Undo only if the text equals the snapshot.

- `src/components/drafts/CaptionPanel.tsx`
  - :51-59: `CaptionUndoHandle` gains `arm()`, so "Regenerate all" can arm a panel.
  - :72-73 and :96: a new `actionPending` prop (the polled `pendingAction !== null`).
  - :152-156: `settleArmed` state. `arm` sets it, and the handle exposes it.
  - :158-168: the settle effect replaces the `wasPending` ref edge:
    `if (!settleArmed || actionPending || pending) return; setSettleArmed(false); if (caption.text === undo.snapshot) clearUndo()`.
  - :228: `regenerate()` arms after `onRegenerate` resolves `ok`. `onRegenerate` resolves only after `CaptionPanels` has awaited `onActionStarted()`, which is the refetch. A refusal still reverts, as before.
- `src/components/drafts/HeadlinePanel.tsx`
  - :33-34 and :58: the same `actionPending` prop.
  - :113-127: `settleArmed` and the settle effect replace the `wasBusy` ref edge. The condition is `!settleArmed || actionPending || busy`, and the comparison is `headline === undo.snapshot`.
  - :170: `regenerate()` arms on `ok`.
- `src/components/drafts/CaptionPanels.tsx`
  - :35-37: the `onActionStarted` doc now says it is awaited.
  - :113-115: an accepted "Regenerate all" arms every caption panel through `undoRefs.forEach((r) => r.current?.arm())`. A refusal still runs the reverts.
  - :165 and :177: `actionPending={draft.pendingAction !== null}` is passed to the headline panel and to each caption panel.
- Both observed-edge refs (`wasPending`, `wasBusy`) are removed.
- I checked one ordering on the server. `settleCaptionAction` writes the rows first, and only then does `completeDraftAction`/`releaseDraftAction` release `pendingAction`. So `pendingAction === null` means the rows have settled. The extra `pending`/`busy` guard is belt-and-braces only.
- An edge case is unchanged. A regenerate that **changes** the text keeps its Undo, and Undo restores the old text. TC-CAP-18 still passes.

## FR-06: the revision list retries after a failure

All of this is in `src/app/(app)/drafts/[id]/page.tsx`:

- :63-64: `REVISION_RETRY_DELAYS_MS = [2000, 4000, 8000]`.
- :119-128: `fetchRevisions` now returns `Promise<boolean>`: `true` when the list loaded, `false` when the request failed.
- :144-180: the follow-the-draft effect.
  - **On a failure,** it schedules a retry after 2, 4, then 8 s, at most 3 retries per revision number. The count is kept in `revisionRetryRef`, keyed by the number, and resets when a different number appears.
  - **When the timer fires,** it resets the guard (`requestedRevisionRef.current = null`) and bumps `revisionRetryTick`. The tick is in the effect's deps, so the effect requests the list again. This only happens if that number is still the one asked for.
  - **A success that still lacks the number** returns without retrying, which keeps 015 FR-02's no-loop rule.
  - An unmount effect clears any pending timer.
