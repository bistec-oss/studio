# T11 report: the briefing assistant schedule with post styles

## Changes

- `src/lib/campaign/briefingAssistant.ts`: the schedule item schema is `{ topic, postStyle?, goal?, tone, daysFromNow, postAction }` (the `goal` default is gone). `extractSchedulePlan` is now shape-only and returns raw items. New `normalisePlan(items, { defaultStyle, styles = activeStyles() })`: an active key is kept; a missing, unknown or retired key becomes the campaign default (if active) or `general`; a legacy `goal` stands in for a missing key through `legacyGoalStyle` and is dropped from the row; a replaced proposed key sets `styleReplaced: { proposed }`. New `scheduleGrammarText(styles = activeStyles())` builds the grammar part of the system prompt (key, label, summary from the dataset at call time); the literal sentence in `runBriefingChat` is replaced by it. `runBriefingChat` normalises the plan (lazy lookup of `Campaign.defaultPostStyle`, only when a plan is present), in the mock and the real path.
- `src/components/campaigns/BriefingAssistantPanel.tsx`: rows have a "Post style" select (`postStyleOptions`) instead of the goal text; a replaced row shows "Suggested style {proposed} is not available; using {label}" (`data-testid="style-replaced"`), cleared when the user changes the select; `scheduleAll()` sends `postStyle` and no `goal`. No new atom, no new `ui-exception`.
- `src/lib/testHooks.ts`: the mock schedule reply uses `postStyle: 'launch'` on row 1 and the bad key `'flash-sale'` on row 2 (still two rows, so existing E2E counts hold).
- Queue batch route: unchanged (FR-32).
- `tests/unit/schedulePlan.test.ts` (new, 10 tests): AC-29.
- `tests/e2e/assistants-031.test.ts` (new): TC-AS-01 to TC-AS-03.
- `docs/e2e-test-plan.md`: §AL added (TC-AS-01..03; TC-AS-04..06 follow in T12).
