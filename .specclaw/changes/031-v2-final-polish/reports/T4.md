## Deviations from design §4

1. `ImageSource` has one extra field, `personalProvider`, set with `personalFailed` on the team tier. FR-14 names the failed key's provider ("Your image generation key (Gemini) failed ..."), but on the team tier `provider` is the team's. The AC-11 shape is otherwise as written.
2. The write fragments live in a new server-only file, `src/lib/drafts/imageSourceFields.ts`, not in `backgroundNotice.ts`: the JSON null needs `Prisma.DbNull`, and `backgroundNotice.ts` is imported by client code.
3. `backgroundSkippedFor` takes a third argument (the source) so the no-team-provider sentence replaces the generic `PROVIDER_ERROR` text. The brief's file list did not name `generateDraft`'s `ProducedDesign` or `regenerate-design`; both needed the new field (regenerate-design is a draft writer).
4. The FR-14 text uses plain "OpenAI" / "Gemini" words, not `KEY_PROVIDER_LABEL` ("Gemini (Google)").
5. A team-provider failure after a personal failure is today's ordinary `PROVIDER_ERROR` and records no `imageSource` (the spec only requires the two outcomes above).
6. Scheduled runs: `userId: null` is the existing guard in the resolver (covered by a unit case); no change was needed.
