- Mock sentinels live in `mockCheck.ts` (re-exported through `renderedText/index`), dormant outside `MOCK_PUPPETEER`; `testHooks.ts` is unchanged.

## Existing callers

All new options are optional. With none set: the headline read, the `check` object (`{ headline }`, no `absent` key), the render call and the stamp are as before; the restore and export routes still pass `null`. A unit test pins the no-option call shape.

## Tests and fixtures

- `tests/unit/renderPost.test.ts`: mock `absentPainted`, the three sentinels, `runAbsentCheck` (sum, throw and hang read 0).
- `tests/unit/commitAcceptRender.test.ts` (new, prisma/storage/renderer mocked): rejection uploads nothing, opens no transaction, writes nothing; accept path stamps `checkText` and passes `absent`; default caller unchanged.
- `tests/render/applyCheck.test.ts` (new, real Chromium, via `spliceText`): after a splice painted and `absentPainted` 0; the old text still painted by a second element gives `absentPainted` 1 (`old-still-painted` through `acceptRender`); target hidden gives `not-visible`.

Finding: the collector reads `innerText`, so a CSS `::after` copy is invisible to it. The brief's `::after` fixture therefore cannot yield `old-still-painted`; I used a second DOM element and added a fixture that records the pseudo-element limit (`absentPainted` 0). Worth a line in the spec's known limits.
