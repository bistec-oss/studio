## Deviation: no `import 'server-only'` in `catalogue.ts`

The brief asked for it. The `server-only` package is not installed, and the real package throws when imported outside Next. `src/mcp/tools/brandkit.ts` now imports the catalogue, and the MCP server runs under plain `tsx` (the scheduler is esbuild-bundled for plain node, and T7 will import it there). The import would crash both. Instead the boundary is enforced by a test, `tests/unit/fontsBoundary.test.ts` (no `'use client'` file imports `lib/fonts/catalogue`; `index.ts` does not re-export it). No vitest alias was needed.

## What changed, per file

- `src/lib/fonts/types.ts`: `FontFamily`, `FontCatalogue`, `FontCategory`, `OFFERED_SCRIPTS` (`['sinhala']`), `isOfferedScript`.
- `src/lib/fonts/merge.ts`: pure `mergeCatalogue` (FR-17: never removes, `delisted: true`, flag cleared on return, date set, sorted).
- `src/lib/fonts/url.ts`: pure `googleFontsUrl(families, lookup)` per design 5.2 (weights in 400 to 700 else the family's own; no axis for one weight without italics; `:wght@`; `:ital,wght@0,..;1,..`; unknown family has no axis and one `[fonts] unknown family` warning per process; de-dup; `display=swap`).
- `src/lib/fonts/catalogue.ts`: `CATALOGUE_DATE`, `findFamily` (exact, case-sensitive, delisted allowed), `searchFamilies` (prefix first, then substring), `familiesForScript`.
- `src/lib/fonts/validateKitFonts.ts`: `validateKitFonts(submitted, stored, lookup)` and `validateScriptFonts(submitted, lookup)` (FR-20, FR-21). `KitFont` is a type alias so it is assignable to Prisma JSON input.
- `src/lib/fonts/index.ts`: re-exports only the client-safe parts: the types, `OFFERED_SCRIPTS`, `googleFontsUrl`, `mergeCatalogue`, `validateKitFonts`, `validateScriptFonts`, `MAX_KIT_FONTS`, `KitFont`.
- `src/lib/fonts/catalogue.json`: generated.
- `scripts/refresh-google-fonts.mjs`: fetches the metadata once (strips the `)]}'` guard if present), maps it, reads the previous snapshot, calls `merge.ts` through `tsx/esm/api` `tsImport`, writes the file. Exits non-zero and writes nothing if the fetch fails.
- `src/app/api/fonts/route.ts`: `GET /api/fonts`, `withTeamAuth`, `q` cut to 60, `script` must be in `OFFERED_SCRIPTS` (else 400), at most 20, returns `{ snapshotDate, families }`.
- `src/app/api/admin/brandkits/route.ts` (POST) and `src/app/api/admin/brandkits/[id]/route.ts` (PATCH): validate fonts through `validateKitFonts` (POST has no stored fonts; PATCH reads the kit's stored fonts); 400 `Unknown font: {name}` or the over-6 error, nothing written. `scriptFonts` is not wired (T7).
- `src/mcp/tools/brandkit.ts`: `createBrandKit` validates the same way and throws on a refusal. `src/mcp/server.ts` is unchanged (no update tool writes fonts; the tool schema is unchanged).
- Tests (new): `tests/unit/fontsMerge.test.ts`, `fontsUrl.test.ts` (Instrument Serif, JetBrains Mono, Noto Sans Sinhala, two families, unknown family), `fontsValidate.test.ts`, `fontsRoute.test.ts`, `fontsBoundary.test.ts`: 40 cases.
