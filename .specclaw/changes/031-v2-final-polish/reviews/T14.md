## Findings

### [WARN] src/lib/renderer/puppeteer.ts:~351-360 (runAbsentCheck catch) — Correctness / FR-40, NFR-06

`return 0` after a throw or timeout means "old text not painted". For Apply, a failed absent check then passes acceptRender (`absentPainted === 0`) and the revision commits even though old-still-painted was never verified. The headline check fails closed on its own (timeout -> `not-checked` -> `not-painted`), so the absent check is the only fail-open leg. NFR-06 only requires that the check never fail a render and that Apply's check fails only the Apply, so failing closed for Apply is allowed. Fix: have it return `null` (or a sentinel such as -1) on failure, expose `absentPainted: number | null`, and make Apply's acceptRender (T15) treat null as rejection (`old-still-painted` or `render-failed`). Callers that pass no `absent` are unaffected. The unit test at tests/unit/renderPost.test.ts ("never throws: a throw or a hang is 0") pins the current behaviour and would change with it.

### [NOTE] src/lib/renderer/puppeteer.ts runAbsentCheck — Timeout budget

The 5 s bound covers all absent texts together, and runs after the headline check's own 5 s, so a render can add up to 10 s. Acceptable (absent has one text for Apply).

### [NOTE] tests/render/applyCheck.test.ts — AC-37 wording

AC-37 names a CSS ::after copy; the fixture uses a second element, plus a pinned pseudo-element limit case. Accepted by the orchestrator; add the limit to the spec's known limits.
