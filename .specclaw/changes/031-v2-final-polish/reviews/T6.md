## Findings

- [NOTE] tests/unit/fontsBoundary.test.ts:16-20 — Boundary test is shallow. It only catches a `'use client'` file that imports `lib/fonts/catalogue` directly. A shared module with no directive that imports `catalogue.ts` and is then imported by a client component would pass the test while bundling the 263 KB JSON. It also does not catch `./catalogue` relative imports. Suggestion: assert that the set of files importing `fonts/catalogue` (and `catalogue.json`) is an allow-list of server files (route, MCP tool, brandkit routes). Deviation (a) (no `server-only`) is justified; the test just needs to be the allow-list form to be the real replacement.
- [NOTE] src/lib/fonts/url.ts:14-20 — If a family had empty `weights` and `italics: true`, the result is `:ital,wght@` with nothing after it. The catalogue has no such family, so this is only a guard gap.
- [NOTE] src/lib/fonts/url.ts:34 — For an unknown name only spaces are encoded. A name with `&` or `#` would alter the query. Validation stops this at write time, but readers of old stored names do not go through it. Suggestion: `encodeURIComponent(name).replace(/%20/g, '+')`.
- [NOTE] src/app/api/fonts/route.ts:24 — Delisted families are offered in picker search. FR-20 allows saving them, so this is consistent; confirm that is wanted for the picker in T8.
- [NOTE] src/lib/fonts/catalogue.json — 263,944 bytes (257.8 KiB) against the NFR-09 "under 250 KB" target. Shape and sample entries (`Noto Sans Sinhala` has `sinhala`) are as specified. A target, not a hard limit; the deviation is small and declared.

Not in T6 scope, noted only: `validateScriptFonts` is exported but not yet wired into the PATCH route (the `scriptFonts` column does not exist yet), and `googleFonts.ts` is still present (FR-18 removal presumably lands with the picker in T8).
