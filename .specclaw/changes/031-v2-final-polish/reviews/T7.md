## Findings

### [WARN] src/lib/fonts/inject.ts:51-52, 159 (CUSTOM_NOT_FAMILY) - Correctness

`/size|weight|style|...|display|line|.../` rejects any custom property whose name contains those words.
Run through `applyPostFonts`:
`:root{--font-heading:"Poppins",sans-serif;--font-display:"Playfair Display"}` extended `--font-heading` but left `--font-display` untouched.
`--font-display`, `--font-headline` and `--font-inline` are common names for a heading font stack, and FR-22 says every property matching `/^--[\w-]*font[\w-]*$/i`.
The value gate (`isFamilyItem`, `NOT_FAMILY_VALUE`) already rejects `20px` and `700`. The name list is needed only for keyword values such as `--font-size: large`.
Fix: drop `display`, `line` and the other words that are plausible family names, or apply the list only when the value is a single bare keyword.
Effect today is a missed Sinhala entry in that stack, not corruption. The OS fontconfig fallback still covers Sinhala.

### [NOTE] src/lib/fonts/inject.ts:459-462 - Correctness

An unquoted `style=font-family:C` attribute is skipped (`!a.quote`), and a tag that never closes stops the scan. Both leave the document unchanged, which is safe.
They are limits to record, not defects.
