## Findings

- NOTE `src/app/api/drafts/[id]/apply-text/route.ts:60-86` — the HTML and headline are read before the claim, and the splice is made from that snapshot. A refine or headline edit that settles between the read and `claimDraftAction` would be overwritten by the older HTML. The claim guards `pendingAction` only, and `commitDraftRevision` forbids a claim together with a CAS. The window is milliseconds. Re-reading the draft after the claim and comparing `htmlContent` and `headline` would close it.
- NOTE `src/app/(app)/drafts/[id]/page.tsx:255-259, 365` — `designUndo.capture` runs before the request, and an async failure (not-painted, old-still-painted, render-failed, conflict) leaves the Undo button showing for a revision that was never changed. Undo then restores the current revision, which is harmless but misleading. Only the synchronous 422 path clears it.
- NOTE `tests/e2e/apply-text.test.ts:113` (TC-AP-01, `renderedText` toEqual) — it pins the exact stamp shape. That is fine today, but it will break if the stamp ever gains an optional field such as `reason`.

No BLOCK or WARN findings.
