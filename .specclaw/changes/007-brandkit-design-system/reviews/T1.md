## Findings

### [WARN] tests/unit/designDataBoundary.test.ts:55-66 — Design adherence / test quality (FR-16, AC-16)

`GENERATION_SIDE` lists `src/lib/agent`, `systemContext.ts`, `captions`, `drafts`, `scheduler`, the API routes and `mcp`, but not `src/lib/designData/` itself. The generation pipeline imports the 009 modules in that directory (`plan.ts`, `composition.ts`, `layout.ts`, `evaluate.ts`, `promptText.ts`, `regions.ts`, `stamp.ts`), so those are the files most likely to be edited to import `./authoring`, and the only one the guard reads is `index.ts` (regex `/authoring/`). A planted `import { entries } from './authoring/entries'` in `plan.ts` passes the test. The `src/lib/agent` scan itself does catch a planted `@/lib/designData/authoring` import: `specifiers()` handles multi-line imports, `export * from` and dynamic `import()`, and the matcher self-test covers them.
**Fix:** add the non-authoring files of `src/lib/designData` to the scan, e.g. `...walk('src/lib/designData').filter((f) => !f.includes('/authoring/'))`, and assert the list contains `src/lib/designData/plan.ts`.

### [NOTE] src/lib/designData/authoring/entries.ts:104 — Correctness (detector false positives on brand prose)

Probed: "Dominates the market." flags `canvas-share` with no design noun (`dominates?` also matches "dominate"; the spec says "dominates" only, and every other ambiguous word needs a design noun). Also flagged: "Ample parking space for guests" (`logo-clear-space`), "a smooth transition for customers" (`edge-blend`), "enough room in the budget". These are advisory chips the author can dismiss, and the spec's noun rule technically allows the last three, so NOTE.
**Fix:** make the `dominates?` trigger require a design noun within three words (canvas, background, layout, design, image, palette). `near()` uses `\s+`, which also crosses newlines ("Large\n- logos" matches); use `[ \t]+` there.

### [NOTE] src/lib/designData/authoring/detect.ts:62 — Correctness (FR-07 quote cap)

FR-07 says `quote` is at most 160 characters; nothing enforces it, and the report's reason (the patterns cannot produce one) is not strictly true: a `near()` match can exceed 160 if one "word" is a very long letter or hyphen run. Contrived, but "bounds what any edit can delete" rests on it.
**Fix:** skip a match with `m[0].length > 160` beside the `m[0].length === 0` check.

### [NOTE] src/lib/kitUpgrade/review.ts:88-96 — Design adherence (stale revival)

`textChanged` turns a `stale` edit back to `pending` when its quote reappears exactly once. The spec only defines pending to stale, and AC-13's UI copy is "text changed, ask again". Revival is safe in the sense that `applyEdit` re-locates against the live text, the edit is still one the validator approved for that quote, and `accepted`/`rejected` never revive. But a pending insert can now land in a sentence the author has since rewritten, and the UI can flicker between disabled and enabled while typing. Keep it if T3's panel copy matches, otherwise drop the `|| e.status === 'stale'` branch. The test "The text comes back" in `kitUpgradeReview.test.ts` encodes the choice, so change both together.

### [NOTE] src/lib/kitUpgrade/review.ts:99-101 — Design adherence

The bare `accept` action marks a pending edit accepted without re-checking the text, so a host that dispatches `accept` instead of calling `acceptEdit` can mark an edit accepted that cannot be applied. AC-15 is met through `acceptEdit`. **Fix:** tell T3 the hook uses `acceptEdit` only, or make `accept` carry the text and require `locateEdit`.

### [NOTE] src/lib/kitUpgrade/review.ts:55-62 — Correctness (insert placement)

Sentence end is the first `[.!?]` followed by whitespace or end, or a newline. Probed: "similar heights, ok e.g. this. Next" inserts after "e.g." (mid-sentence); "(similar heights.) Next" skips the `.)` and inserts after the next sentence; a bullet line without a full stop gets a `.` added (documented). Acceptable for v1 since the author sees the diff before accepting. `countOccurrences` here duplicates `occurrences` in `validate.ts`; fine, it avoids a runtime import.

### [NOTE] src/lib/designData/authoring/validate.ts:63-72 — Correctness (provenance slot swap)

`setProvenance` matches by unit, so "Brand colour 1 covers 25% ..., brand colour 2 no more than 70%" (slots swapped, each number inside some range of the entry) is `dataset`. Harmless for v1 and stated in deviation 5; a follow-up tightening is to use each range at most once, in order.

### [NOTE] src/lib/designData/authoring/measurable.ts:11-12 — Correctness (false "measurable")

`12:30` (a time), `call 5 x people`, `3 em dash` and `2.0x` count as measurable, so a sentence holding one exempts its vague phrase from the detector (false negative) and passes `isMeasurable` as a replacement. AC-05's table passes in full (60%, 45-60%, 45-60 %, ~12 px, 3:2, 2x, both reference-object cases, and every non-example), and `lostMeasurableRules` returns original spans (reformatting such as `45 – 60 %`, `~45-60%` and mixed case is not a loss). Accepted by the spec's definition. One real gap in the loss comparison: "1.5 wordmark letters" vs "1.5 of the wordmark letters" reads as a loss because the in-between words are part of the token.

### [NOTE] tests/unit/kitUpgradeValidate.test.ts:106-116 — Test quality

"apply bounds: only the quote is removed (replace) or nothing is (insert)" asserts only `kind` and `quote.length <= 160`. The byte-for-byte replace/insert behaviour is covered in `kitUpgradeReview.test.ts`, so nothing is untested, but the title over-claims. Rename or move.

### [NOTE] src/lib/designData/authoring/index.ts:9 — Dead code

`export const authoring = { entries } as const` is referenced nowhere (the `export *` lines carry everything). Remove unless T2 imports it.
