## Assumptions and deviations

1. **`buildMockKitUpgradeReply` takes `{ id, mockReplacement }[]`, not `Candidate[]`.** `testHooks.ts` is imported by generation code; importing the authoring dataset there would pull it into the generation bundle (FR-16 intent). `upgrade.ts` maps candidates to `mockReplacement` via `getEntry`.
2. **`buildImprovePrompt` lives in `kitUpgrade/prompt.ts`**, not a new file: a Next route file may not export extra names, and the task's file list had no better home.
3. **Check order:** 404 then body 400 then 409. The spec lists 404 before 409; body validity was not placed, so 400 comes after the kit lookup (no existence leak either way).
4. **Log `entries=`** lists the unique entry keys of the candidates sent to the model (FR-17 wording: "asked to fill"; FR-05 says "proposed"). It is emitted on every call, including the no-candidates case (`candidates=0 ... entries=`); a parse failure emits only the parse-failed line.
5. **BAD sentinel** needs three detected candidates (valid, no number, hex) plus an unknown id; with fewer candidates the missing proposals are skipped. **OUTOFRANGE** multiplies every number in the first candidate's mock replacement to 997 (measurable, out of range, `unverified`).
6. Model call uses `maxTokens: 2048`. The base text goes in the user message inside `fenceUntrusted`; the guard, roles and candidates are in the system message.
7. Caught during the work: a heredoc ate a `\n`; the escape in the parse-failed log is verified by a unit test (no raw newline, `\n` escaped).
8. `next build` rewrote `next-env.d.ts`; reverted.

- Sentinel constants: `MOCK_UPGRADE_UNPARSEABLE|NONE|BAD|OUTOFRANGE`, `MOCK_IMPROVE_DROP_RULES` from `@/lib/testHooks` (server side; an E2E should use the literal strings `__MOCK_UPGRADE_*__`).
- Improve response: `{ draft: string, lostRules: string[] }` (original spelling, `[]` when nothing was lost). The UI must read `lostRules` (it may be absent from an old server only in theory).
- Upgrade errors the UI handles: 400 `{error}`, 404 `{error}`, 409 `{code:'STALE_BASE', activeVersion}`, 422 `{code,message}`, 502 `{code:'UPGRADE_PARSE_FAILED', message}` (show "Try again"). 200 bodies: `edits` (`baseVersion`, `edits`, `rejected`, `candidates`) or `none` (`reason`, `rejected`, `candidates`).
- `baseVersion` is the kit's active prompt version, 0 when none.
- In a MOCK_AI E2E the upgrade needs at least 3 detected candidates for the BAD sentinel (the text `Give the logo generous clear space. Keep the logo a similar size to the wordmark. Leave plenty of breathing room around the logo.` yields three).
