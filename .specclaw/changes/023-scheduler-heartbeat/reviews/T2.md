## Findings

- NOTE: `src/lib/scheduler/heartbeat.ts` runTick. FR-03 says a "hung" write must not stall the loop, but the writers have no timeout; only throw/reject is handled. A hung DB call would hang the job's DB calls too, so the practical risk is low. Either add a short `Promise.race` timeout or accept it and soften the spec wording. Not blocking.
- NOTE: parallel-worker leakage in §Z. The table is global; `mode: 'serial'` only orders tests within this file. If Playwright runs with `workers > 1`, another file (for example `campaign-scheduling` or the a11y suite loading a campaign page) could run while §Z has seeded "online" rows. That only removes the banner for them, and a banner-asserting case in §Z could be affected by another file's `clear`. It is benign today: no other suite writes this table and no other suite asserts on the banner. Confirm `workers: 1` in the Playwright config (T3's full run covers it), or leave the "default is no rows" invariant documented.
- NOTE: TC-HB-06 deviation (a bogus `better-auth.session_token` cookie to get past `proxy.ts`) is sound. It exercises the route's real 401 path, and the comment explains why. It depends on the proxy only checking cookie presence, so it could break if the proxy starts validating sessions; the comment already notes the reason.
- NOTE: tests assert outcomes (states, keys, DOM text, truncation length of 81, tooltip, absence of the first-try reason), not just mock calls. One small gap: TC-HB-05 does not check the PENDING retry reason colour. Not needed.
- NOTE: the `startedAgoMs`/`endedAgoMs` zod fields accept negative values (future timestamps). That is useful for skew tests and harmless behind the gating.

No BLOCK or WARN findings. No scope creep: all files are in the T2 list.

PASS-level, with notes. Verdict: NOTE
