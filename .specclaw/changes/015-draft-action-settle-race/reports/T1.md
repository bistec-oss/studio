# T1: the forced-race E2E cases, failing on the current code

**Implemented by the orchestrator directly.** The task is small and the repro was already in hand.

## What was built

- **`tests/e2e/settle-race.test.ts`** (new, §X) has two cases:
  - **TC-RACE-01** (AC-01): a refine.
  - **TC-RACE-02** (AC-02): a Regenerate design.
- **`holdFirstRefetchAfter(page, draftId, actionPath)`**, a helper in the file, holds the first `GET /api/drafts/<id>` sent after the action POST for 3 s. It matches the exact path, not `/revisions`. The in-process mock action therefore always finishes before the client sees it: the order the CI runner produces on its own.
- **Each case asserts that the hold happened** (`expect(held()).toBe(true)`), so a green run can't come from the race simply not being forced.
- **"Current" is checked as a list item.** `currentVersion(page)` finds the version list item carrying the "Current" marker. Before the fix that item doesn't exist: the list is stale at v1, while the draft's current revision is 2.
