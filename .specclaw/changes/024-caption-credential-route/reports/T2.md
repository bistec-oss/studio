## Assumptions and deviations

- A1. `PickerModels.captionCredential` is optional (absent reads as `credential`), so the many picker tests and `modelPicks.ts` need no change; the server always sets it on `ModelsView`.
- A2. The tasks' "`reportRoute` wrapper" is not a separate wrapper: each provider class already reports its route in its reply, and the mock reports the decision's route. Simpler, same observable result.
- A3. `captionCredentialFor(teamId)` returns `'team' | null` (not a full tier) so `captionRoute.ts` does not import `policy.ts` (which imports the registry, which imports the loader).
- A4. The chosen row's key is read by `id` with `teamId` in the `where`, in its own `findFirst`, after the decision.
- A5. A legacy `cli` row builds the CLI provider without decrypting a key, as before; the decorator wraps any CLI-route provider, including the legacy one.
- A6. `POST /api/briefs` loads the route with no brief key (it only needs `chosen`/readiness) and `copyProviderIsClaude` loads it again for the caption-pick check: two cheap queries on one request. Not worth a shared-value refactor now.
- A7. `modelCallFor`'s `route` is recorded by the `MOCK_AI` seam only. The real `AnthropicCopyProvider` records through `createMessage` with no route (the spec says other callers pass none), so only mock records carry it; the stamp is the durable record.
- A8. spec.md and tasks.md agree on everything I used; one wording note: tasks says "the caption select list `CAPTION_SELECT`", the file's constant is `ROW_SELECT`. `route` is added there and to `CaptionRow`, so the draft GET now returns `route` on each caption (additive).
- The never-chosen decision (user, 2026-10-22) is implemented: the brief key still picks the row; once chosen it is ignored.
