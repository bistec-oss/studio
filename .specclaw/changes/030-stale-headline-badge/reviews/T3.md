## Findings

### [WARN] tests/unit/renderedTextWriters.test.ts:73-82 (and :60-66): writer guard has blind spots

The guard only inspects a call's own parentheses. The commit's draft write is built from a separate variable (`revisions.ts` ~line 664, `htmlContent: html` inside `const data = {...}` spread elsewhere), so `htmlContent` is not in the `tx.draft.update(` args and that write is never scanned. The third test only asserts when the call has a literal `data: {`; a variable `data` passes silently. The fourth test is satisfied by any one `...draftStampFields(` in each file. Net effect: a writer inside `revisions.ts`, `generateDraft.ts` or the regenerate route that adds a new HTML write via a variable, or drops the spread from the commit's draft data, is not caught. A new writer in a new file with an inline literal is caught.
Fix: scan for object literals containing `htmlContent`/`htmlSnapshot` keys (not only call args) and require the matching `*StampFields(` spread within that literal, or count occurrences per file against an expected number.

### [NOTE] src/lib/drafts/revisions.ts ~line 582 (`stamp = currentRenderStamp(args.model ?? null, args.composition, ...)`): adopt-without-export would overwrite the adopted stamp

If `adoptRejectedRevisionId` were ever passed with no `exportKey`, the render branch replaces the adopted stamp with a fresh one built from `args`. Today the only adopt caller always passes `exportKey`, so this is unreachable. Guarding with `adopted ? ... : ...` or throwing would make the invariant explicit.

### [NOTE] formatting: `src/lib/agent/generateDraft.ts:9`, `src/app/api/drafts/[id]/regenerate-design/route.ts:10`

`import { currentRenderStamp,draftStampFields, ... }` is missing a space after the comma. `prettier --check` also warns on `generateDraft.ts`, the regenerate route, `types.ts` and `designAgent.ts` (the last two mix quote styles in the new imports, `"@/lib/renderedText/vocab"`; some may predate this task). Run prettier on the changed lines.
