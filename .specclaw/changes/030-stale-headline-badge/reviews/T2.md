## Findings

### [WARN] tests/render/headlineCheck.test.ts:91-96 (fixture "clipped by overflow hidden on a parent") - Test quality

Quoted: `position:absolute;left:0;top:0;width:80px;height:40px;overflow:hidden"><h1 style="margin:0;white-space:nowrap;font-size:60px;position:relative;left:300px">`
**Problem:** the whole text sits outside the 80 px clip box, so the centre of each rect is outside the box and `elementFromPoint` there does not return the h1. A collector that skipped the clip-box step would still say `not-visible` through the topmost check. The fixture does not prove the clip step in real Chromium (the pure clip rule is covered only by the T1 facts tests).
**Fix:** clip partially so the rect centre stays inside the box, for example a 300 px wide overflow-hidden parent with a 700 px wide nowrap headline (centre of the rect inside the parent, right half cut). Then only the clip check fails it.

### [NOTE] src/lib/testHooks.ts:906 (buildMockRefineReply) - Correctness (mock only)

Quoted: `base.replace('</body>', \`${carried}</body>\`)`
**Problem:** the replacement is a string, so `$&`, `$$`, `` $` `` and `$'` in a headline are interpreted by `String.replace` ("Win $$$ now" loses a dollar), and the carried headline would no longer equal the stamped one.
**Suggestion:** `base.replace('</body>', () => \`${carried}</body>\`)`.

### [NOTE] src/lib/renderer/puppeteer.ts:262 and :287 - Security (known limits)

Quoted: `const norm = new Function("return " + normaliseSource)()` and `document.elementFromPoint(...)`
**Problem:** (a) `new Function` fails under a page CSP without `unsafe-eval`; the result is a safe `not-checked`, so only a note. (b) `elementFromPoint` skips `pointer-events:none` elements, so a covering overlay with `pointer-events:none` would not be seen as covering, and a headline with `pointer-events:none` would read as covered (fails toward unconfirmed, safe). Worth one line in the known limits next to L1.
