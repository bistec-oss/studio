# Review T1: the pure rendered-text module (030)

Scope: `src/lib/renderedText/*.ts`, `tests/unit/renderedText.test.ts`. Mode: task-scoped. I read the files once and ran the new test file (34/34 pass). Spec FR-02, FR-03, FR-07 to FR-14, AC-02, AC-05 and AC-09 are met, as are design sections 2, 3.3 and 7.

## Spec compliance

- **FR-08 and the verdict** (`facts.ts:40-60`): visibility, empty rects, canvas bound (every rect inside the canvas is equivalent to the union inside it), every rect inside every clip box, and all `topmost` true. The four outcomes are correct, and a hidden duplicate does not cause `ambiguous` (A3). The 1 px tolerance is applied on all four sides.
- **Stamp** (`stamp.ts:9-20`): the discriminated union gives "reason iff unverified". `.strict()` is on the entries and the outer object. `HEADLINE_MAX` (100) is enforced. `parseRenderedText` is tolerant, and `renderedTextColumn` parses strictly.
- **Normaliser** (`normalise.ts:8-16`): self-contained, with no imports or closures. The literal NBSP, U+2007 and U+202F in the regex are real characters (checked with `od`). `new Function('return ' + SOURCE)()` works under vitest.
- **`headlineState`** (`state.ts:12-17`) matches FR-11 exactly: null stamp, missing key or null headline gives unknown, then unverified gives unconfirmed, then the normalised compare.
- **`mockHeadlineCheck`** (`mockCheck.ts:36-46`) matches design 3.3: the sentinel first, comments, head, script, style and template stripped, tags replaced by a space, `&amp;` decoded last, whole-text count. `<head\b` does not eat `<header>`.
- **Notice sentences** (`noticeText.ts:16-54`) are word for word FR-13 and FR-14, including the curly quotes and the "post/posts" plural.
- **Purity:** the only imports are zod, `HEADLINE_MAX`, and the `Prisma` namespace. There is no client and no I/O. Nothing is out of scope. There is no dead code beyond the exports that T2 to T5 consume.

## Findings

### [NOTE] src/lib/renderedText/index.ts:3 and stamp.ts:4,34 -- bundle weight (named risk)

`stamp.ts` uses `Prisma.DbNull` as a value, so the barrel `index.ts` makes any client import of `@/lib/renderedText` pull `@prisma/client` into the browser bundle. Design 2 says "type only", but `DbNull` is a runtime value (the same as `toJsonColumn`, so it is acceptable on the server). T5's client components (`HeadlineImageNotice`, `PublishDialog`) should import `@/lib/renderedText/noticeText` and `/vocab` directly, not the barrel. This is not a T1 defect.

### [NOTE] tests/unit/renderedText.test.ts:176-184 -- tolerance test only covers the left edge

Only `left: -1` and `-1.5` are tested. A mutation that dropped the tolerance on the right, bottom or top edge, or on `clipBoxes` (`facts.ts:36-38`, `:45`), would survive. Add a right-edge and a clip-box case, for example a rect that overshoots the clip box by 1 px (painted) and by 1.5 px (not-visible).

### [NOTE] tests/unit/renderedText.test.ts:169 -- "covered" case has mismatched shapes

`topmost: [true, false]` is paired with a single rect. It still discriminates, because `every(t === true)` fails, but it does not model a real two-line headline. Use two rects with `[true, false]`.

### [NOTE] tests/unit/renderedText.test.ts:55-57 -- rebuilt-versus-original is tautological on its own

It would pass for any self-contained implementation, which is the intent. The behaviour is pinned only by `:60-61` (case, whitespace, NFC). Add explicit expected values for NBSP, U+2007, U+202F and Sinhala (for example `expect(normaliseHeadline('a b')).toBe('a b')`), so a wrong regex fails.

### [NOTE] src/lib/renderedText/mockCheck.ts:21-34 -- stand-in is looser than Chromium (for T2/AC-07)

The stand-in counts whole-text occurrences inside larger text ("Join Big Launch today" gives `painted`), but the real check needs an element whose whole text equals the headline. Punctuation adjacent to the headline ("Big Launch!") gives `not-found` in the stand-in. FR-10 specifies this, so it is conformant. AC-07 should only compare the four listed fixtures and must not generalise.

### [NOTE] src/lib/renderedText/stamp.ts:40 -- `slice` can split a surrogate pair

`text.slice(0, HEADLINE_MAX)` can cut an emoji in half. It only matters for the over-long fallback case, and the result is still valid for zod. This is negligible.

### [NOTE] src/lib/renderedText/facts.ts:52 -- `tolerance` parameter

The third parameter is not in design 2.3's signature and nothing needs it yet. This is harmless and costs one line. It is mild YAGNI.
