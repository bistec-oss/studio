# T3 report: the stamp column, the stamp helpers and every render writer

## What was built

- **Schema and migration.** `renderedText Json?` on `Draft` and `DraftRevision` (commented in the schema's style). Migration `prisma/migrations/20261027120000_rendered_text/migration.sql` (two additive `ADD COLUMN`s, no backfill). Down script `prisma/rollback/030-stale-headline-badge.down.sql` in the 025 down script's shape. Applied to `bistec_studio_test` only (explicit `DATABASE_URL`), then `prisma generate`.
- **Stamp helpers (`src/lib/drafts/revisions.ts`).** `RenderStamp.renderedText`; `currentRenderStamp(model, composition, postStyle, renderedText)` with the fourth argument required; `revisionStampFields` and `draftStampFields` add `renderedText: renderedTextColumn(...)`; `restoredRenderStamp` returns `parseRenderedText(revision.renderedText)` (also when re-rendered); `rejectedRenderStamp` selects and parses it. RenderStamp header gained a 030 paragraph.
- **Generation and regenerate design.** `DesignAgentOptions.headline` (required) and `DesignAgentResult.headlineCheck`. `runDesignAgentCli` renders with `renderPost(..., { headline })`. `runDesignAgent`: the `MOCK_AI` branch passes the headline to `buildMockHtml` and `toolRenderHtml`; `toolRenderHtml` takes the headline and returns `headlineCheck`; the loop tracks `lastHeadlineCheck` (null when nothing rendered); the conflict mock returns null. `runPathADesign` and `runPathBDesign` pass the headline they already had (Path B's result spreads the agent result, so the fallback render's check is the one returned). `produceDesign` and the regenerate-design route build `stampFromCheck(headline, check ?? 'not-checked')`; regenerate checks `designHeadline(draft, draft.brief).text`. `runDesignAgentRefine` omits `headline` from its options (refine does not render here). `emitGenerationFinished` untouched (T4).
- **Commit and rejected render.** `renderDraftHtml(..., headline: string | null)` returns `{ png, headlineCheck }` via `renderPost`. A local `RenderResult` interface in `revisions.ts` (puppeteer.ts exports no such type; I did not touch T2's file). `commitDraftRevision`: the composition (all the canonical HTML needs) is settled first, the draft's headline is read once before the render (`findUnique` selecting `headline` and `brief.topic`, through `designHeadline`), the stamp is built after the render from the check; an adopt keeps `rejectedRenderStamp`; a caller-supplied export with no adopt id gets a stamp with `renderedText: null` (nothing saw those pixels). `recordRejectedRender` reads the headline, stamps `not-checked` by default and replaces it with the render's check after a successful render (a failed render and a row with no document keep `not-checked`). Restore and export pass `null` and use `.png`.
- **Writer guard.** `tests/unit/renderedTextWriters.test.ts` (4 cases): the source scan over `src/` (finds exactly the three allowed files; a new file fails with its path; literal `data:` objects must spread the stamp helper).
