# T4 report: the read side and the events

## What was built

- **`src/lib/renderedText/track.ts` (new).** `trackHeadlineEdited({ draftId, teamId, userId, via, before })`, the only writer of `draft.headline_edited`, not re-exported from the index. One query reads `headline`, `renderedText` and the SCHEDULED post count (`_count` with a `where`). It returns without tracking when `before` equals the current headline exactly (a case-only edit is still a change, with state `fresh`), and otherwise tracks `{ via, state: headlineState(...), scheduledPending }` with source `web`. The whole body is in a try/catch, so it never throws. No text in the payload.
- **Callers.** The `PATCH /api/drafts/[id]` headline branch reads `headline` in its existing draft select and calls it after a successful save (`via: 'edit'`). `settleCaptionAction` now returns `SettleResult { headlineWritten, headlineBefore }`: `headlineBefore` is read with `tx.draft.findUnique` inside the transaction just before the claim-guarded headline write, and `headlineWritten` is that write's `count === 1`. A lost claim, a failed or unrequested headline return `{ false, null }`. `regenerate-copy/route.ts` calls the emitter after the settle when `headlineWritten` (`via: 'regenerate'`). The `onError` settle is wrapped so it still returns void.
- **Catalogue.** New `draft.headline_edited` (web, no outcome); `publish.settled.headlineState` and `generation.finished.headlineCheck`, both optional. The vocabularies are imported from `@/lib/renderedText/vocab`.
- **`emitGenerationFinished`.** `headlineCheck` is `'painted'` when the design stamp's headline is verified, otherwise its `reason`; absent when there is no design or no stamp.
- **`publish.settled.headlineState`.** `PublishOutcome.headlineState?`, passed through by `trackPublish`. Callers compute `headlineState(parseRenderedText(draft.renderedText), draft.headline)` at the attempt, from the draft load each already makes (select extended, no new query): `publishDraft.ts` (also MCP and ACP), `posts/[id]/publish/route.ts`, `jobRunner.ts` (the only file under the unattended surfaces that changed).
- **GET `/api/drafts/[id]`.** The state is computed first from the columns `include` already returns (`renderedText` comes with the scalars). Only for `stale` or `unconfirmed` does the `Promise.all` gain a fourth read, `prisma.post.aggregate({ where: { draftId, status: 'SCHEDULED' }, _count: true, _min: { scheduledAt: true } })`; otherwise that slot is `null`. `data.headlineImage = headlineImageFor(...)`. `api-types.ts`: a `HeadlineImage` interface (written against the `vocab` types, no runtime import) and `DraftDetail.headlineImage`.
- **GET `/api/library`.** The list select gains `headline` and `renderedText`; the map destructures them out and returns `headlineState` only. `DraftRecord.headlineState` added to the type.
- **Seam `POST /api/test/draft-rendered-text`.** `{ draftId }` sets `renderedText` to SQL NULL on the draft and all its revisions (`Prisma.DbNull`, one transaction). Gating: 404 in production, 404 without `MOCK_AI`, then `withTeamAdmin` (a team admin or super admin), and a draft of another team is a 404.

## Deviations

1. The seam is team-scoped through `withTeamAdmin` (after the production and `MOCK_AI` gates), not `requireRole('admin')` as `worker-heartbeat` does, because `requireRole` returns no team and the brief asks for team scoping. A global-admin-only user who is not a team admin gets 403; the E2E admin is a super admin.
2. `trackHeadlineEdited` uses the `teamId` argument for the event and does not read `teamId` from the draft (the callers already hold it; design 5.1 signature).
3. A full `npm run test:unit` run once showed three source-scan tests (`designTokens`, `postStylesBoundary`, `uiTokenGuard`) time out at 5 s while the machine was loaded; they pass alone and in the next full run (173 files, 4253 tests). No test was changed for it.
4. No unit test of the seam's gating: `MOCK_AI` is a module constant, so the gate is covered by the T5 E2E (TC-HL pre-030 case) instead.
