## Spend control (traced)

- Ledger is appended before the request. The ledger is written at run-look-check.mjs:447, before `await generate(` at :450, so a crash, throw or timeout after that line still counts. A thrown error inside `generate` is caught at :424 and becomes a result with `error`.
- A partial or torn ledger line is parsed as `{malformed:true}` and counted toward the total (lookCheck.mjs:162-163). `planNext` checks `entries.length >= cap` first (:183).
- Cap is `2 * SLOTS.length` = 16 (:141), computed, not typed. The runner refuses to start at the cap, exiting 3 before sign-in (:360-363). Inside the loop it re-reads the ledger every slot (:438).
- Attempts are counted on every path, including a brief 4xx, a timeout and a failed draft. That is conservative and correct. A crash between the ledger write and the results write leaves a ledger line with no result; the next `planNext` counts it as attempt 1.
- Generations are strictly serial inside one process (`await` in a `for` loop).

## `--base`

`checkBase` (:217-229) parses with WHATWG `URL`, requires `http:` and an exact hostname of `localhost` or `127.0.0.1`.

- `localhost.evil.com`, `127.0.0.1@host`, `localhost@evil.com` and `https://` are all rejected, because `hostname` is the post-userinfo host.
- A backslash trick parses to localhost in both `URL` and `fetch`, so there is no mismatch.
- The runner concatenates the raw `args.base` string (:367). It is the same string that was validated, so there is no drift.

## Other constraints

- `lookCheck.mjs` has no import, fetch, fs or prisma (a test enforces this).
- Credentials are read only from `LOOK_CHECK_*` env vars (:354). `--dry-run` and `--verdict` exit before any network call; `--base` in dry-run is only validated.
- Results record key, size, `contractVersion` (from `composition.contractVersion`), `briefId`, `draftId`, `render`, `styleKept` and `accepted`. The field names match the stamp in `designData/plan.ts`. The pass rule is last result per slot with `styleKept === true && accepted === true`, and a look passes only if all its slots pass.
- The eight briefs match their styles and invent no date, price or number.
  - launch: names Bistec Studio and has one CTA.
  - announcement: news in the first sentence, no number.
  - event (SQUARE, STORY): states only Colombo and "online", and gives an open CTA.
  - hiring: names the role, says to get in touch, no salary or deadline.
  - promotion (SQUARE, STORY): no price or end date, "find out more" or "get in touch" CTA.
  - milestone: thanks the audience, no number or year.
- Nothing under `009-hero-image-design/` is touched.

## Findings

- NOTE scripts/look-check/run-look-check.mjs:311. The cap lives in `<out>/ledger.jsonl`. A different `--out`, or a deleted ledger, resets the count. This is operator-controlled and probably acceptable, but the runbook should say "reuse the same `--out`".
- NOTE scripts/look-check/run-look-check.mjs:438-447. There is no lock between processes. Two runners started together could both pass `planNext` and overshoot by one call or a few. "One at a time" holds only within a process. A `flag: 'wx'` lock file would close it, but that is probably over-engineering for an operator tool.
- NOTE scripts/look-check/run-look-check.mjs:417. The `exportUrl` fetch goes to a server-supplied URL without the localhost guard. It carries no cookie or credentials, so the risk is low.
- NOTE scripts/look-check/run-look-check.mjs:329-331. `--verdict` can set `accepted` on an errored or fallback result. This is harmless, because `slotPassed` still requires `styleKept`.
