# Spec: Image looks (027b): 9:16 for the two looks, Full-bleed scene and Spotlight, and a pixel check that can fail

**Change:** 028-image-looks · **Size:** architectural · **Proposal:** [proposal.md](proposal.md) · **Party:** [party-report.md](party-report.md)
**Created:** 2026-10-25
**Status:** 🟡 Draft

## Overview

009 shipped two image looks, `product-showcase` and `editorial-split`, at SQUARE and PORTRAIT only (`src/lib/designData/composition.ts:67-69`: "STORY is absent from both"). A 9:16 brief is therefore always classic, and `resolvePostStyle` turns the Launch and Announcement defaults into classic with the `size-classic` note (`src/lib/postStyles/resolve.ts:99-105`). Six of the eight 027 post styles default to classic because no look fits them (`src/lib/postStyles/styles.ts`, `defaultImageStyle: 'classic'` on six rows).

This change is phase b of 027, cut down by the user after the panel. It makes four things:

1. **STORY for the two looks.** `product-showcase` and `editorial-split` get `versions[2]`: SQUARE and PORTRAIT copied unchanged from v1, STORY added, `current: 2`. v1 is never edited.
2. **Two new looks**, `full-bleed-scene` (one text band along the bottom, over the scene) and `spotlight` (a headline band at the top, a call-to-action band at the bottom, the subject centred between), each at SQUARE, PORTRAIT and STORY.
3. **A pixel check that can fail, proven per contract.** Every (look, current version, size) has one pass image and two fail images (one `busy`, one `contrast`) in the real-Chromium render harness. Dataset validation fails any contract with no `text` region.
4. **A capped real-image check** in `scripts/look-check/`, run once by the operator after the build (OP-028). It is the only gate for moving post-style defaults onto the new looks, which happens in a separate, operator-gated task (T7) and only for looks that passed.

Scheduled, MCP and ACP posts stay classic, exactly as today. There is no allow-list, no runtime switch, no new resolver note for unattended runs and no insights section (the user's decisions 2 and 4).

**What this does not claim.** The panel (party-ba) said neither problem has usage data behind it. That is true and this spec does not rest on it. STORY support is a capability the user asked for on 2026-10-24; there is no measured count of 9:16 briefs. The look-to-style mapping (Event and Hiring to Full-bleed scene, Promotion and Milestone to Spotlight) is the user's choice, not drawn from usage. The new looks therefore ship as opt-in picks. 006's existing "Image styles" insights section (`src/lib/analytics/queries.ts:292`) already reports, per requested look, how often it was generated and why it fell back, because the analytics vocabulary is imported from the dataset (`src/lib/analytics/catalogue.ts:34-37`). It picks up the new keys with no change.

## Approach

**One dataset, more rows.** Everything 009 built already reads the contract from `src/lib/designData/composition.ts`: the image prompt, the design prompt, the pixel check, the layout observation, the refine prompt, the stamp and the wizard picker (`imageStyleOptions`, `composition.ts:177-186`). Adding contracts is mostly data. The code changes are: a validator (`designData/validate.ts`), one optional field per region (`use`, so Spotlight can say which band holds the headline), one optional field per contract (`variantOf`, validation only), the resolver's `retired-classic` note, the STORY literals in the wizard, the mock layout box, the fixtures, and the runner.

**No migration.** `Brief.imageStyle` is plain `TEXT` (`prisma/schema.prisma:517`), and the stamp is `Json?` on `Draft` and `DraftRevision` (`:609`, `:833`). A new look key needs no schema change (NFR-03).

**The check discriminates; the real check judges.** The fixtures prove the pixel check can tell a calm text area from a busy or low-contrast one, for every contract and both properties. They say nothing about whether a real model image passes. That is OP-028's job, and OP-028 gates only the default moves (T7).

- **FR-03 — Dataset types and validation** (`src/lib/designData/composition.ts`, new `validate.ts`).
  - **Types.** `ArchetypeKey` (`composition.ts:15`) becomes `'product-showcase' | 'editorial-split' | 'full-bleed-scene' | 'spotlight'`. `Region` gains an optional `use?: string` (what goes in it; only the Spotlight bands set it). `Contract` gains an optional `variantOf?: { key: string; version: number }`. A v1 contract has neither field, so its JSON, its hash and its prompt text are unchanged.
  - **`lookDatasetProblems(source): string[]`** (pure, `validate.ts`). It returns one named problem per violation, in this list:
    1. a key that does not match `^[a-z]+(-[a-z]+)*$`, or a record key that differs from `archetype.key`;
    2. a `current` that names no version; a `status` other than `active` or `retired`;
    3. **a contract with no `text` region** (no empty check);
    4. a region outside `0..100`, with `w` or `h` not above 0, or with an area below its `minAreaPct`;
    5. `variantOf` rules: the base key exists; the base is not itself a variant; the base version exists; the variant key equals `` `${base}-${suffix}` `` with `suffix` in the closed list `VARIANT_SUFFIXES = ['light']`; every size of the variant version exists in the base version with deep-equal `regions` (subject and `textTone` may differ); every version of a variant names the same base key;
    6. **the prefix rule:** for two keys `a` and `b`, if `b` starts with `` `${a}-` ``, every version of `b` must have `variantOf.key === a`.
  - It runs in a unit test on the real dataset (must be `[]`) and on fixture datasets (each rule fails with its message; a valid variant fixture passes). It also runs at module load of `designData/index.ts` and throws outside production, like `defaultImageStyleProblems` does (`src/lib/postStyles/styles.ts:351-354`).
  - **No variant ships.** `variantOf` is unset on every shipped contract.

- **FR-08 — The fixture set** (the merge gate for the pixel check).
  - **Identity.** A fixture is keyed by `` `${key}@${version}:${size}` `` and a kind: `pass`, `busy` or `contrast`. The set is **exactly** the 12 current contracts × 3 kinds = 36 fixtures. 009's v1 fixtures (`tests/render/heroFixtures.ts`, `hero-sampler.test.ts`) stay as they are and are not extended.
  - **The table is pure data** (`tests/render/lookFixtureTable.ts`, no renderer import), so a unit test can read it. For each look it **declares the intended backdrop literally** (`dark` for all four), independent of the contract's `textTone`.
  - **The images** (`tests/render/lookFixtures.ts`), rasterized through the production renderer like 009's (`heroFixtures.ts:29-35`), at the provider's image size for the shape (SQUARE `1024x1024`, PORTRAIT and STORY `1024x1536`). Each text region is mapped to image pixels through `mapRegionToImage` (`regions.ts:37-58`), so a cropped row is never painted:
    - **pass:** busy stripes over the whole image, then the declared backdrop (a calm dark gradient) over every text region, expanded by 1% of the canvas on each side. It proves the subject area is not measured.
    - **busy:** the pass image, with stripes inside the **last** text region.
    - **contrast:** the pass image, with flat mid grey (`#808080`) inside the **first** text region. Mid grey is the wrong backdrop for light text whatever the `textTone` field says. For Spotlight, busy hits the bottom band and contrast the top band, so both bands are shown to be measured.
  - **Render test** (`tests/render/look-fixtures.test.ts`, real Chromium, `MOCK_PUPPETEER` off): for every fixture, `sampleRegionLuminance` then `evaluateRegions` with the contract's `textTone`: pass is `{ ok: true }`; busy is `{ ok: false, reason: 'busy' }` on the last text region; contrast is `{ ok: false, reason: 'contrast' }` on the first.
  - **Completeness and tone** (`tests/unit/lookFixtureCompleteness.test.ts`): the table's keys equal the set of (key, current version, size) in the dataset, each with exactly the three kinds; a fixture dataset with an extra size fails the completeness function; every look's declared backdrop is `dark` exactly when its current `textTone` is `light`.
  - **Tuning.** If a pass fixture fails, change the fixture or the geometry with a recorded reason, never an assertion's direction (009's rule). The thresholds in `evaluate.ts` do not change (Out of scope).

One brief per slot (design §9), sent with `designMode: 'GENERATE'`, the slot's `aspectRatio`, an explicit `imageStyle` and an explicit `postStyle`.
  - **The cap.** `capFor(slots) = 2 × slots.length` = **16**, computed, never typed. At most **one re-run per failing slot** (two attempts per slot). A slot "fails" when its last render did not keep its style or the user rejected it.
  - **The ledger.** `<out>/ledger.jsonl`, append-only. The runner writes one line (`{ at, runId, slot, attempt }`) **before** each generation request, synchronously, so a crash, a timeout or an error after the line still counts. The attempt count is the number of ledger lines, not the number of results.
  - **Refusals** (pure `planNext(ledger, results, slot, cap)`): it refuses to start when the ledger is at the cap; refuses a third attempt on a slot; refuses a re-run of a slot whose last render passed; refuses a re-run of a slot with no verdict yet. The runner prints `[look-check] call <n> of <cap>` on every call.
  - **Results.** `<out>/results.json`: one entry per attempt with `slot`, `key`, `size`, `contractVersion` (from the draft's stamp, null on a fallback), `briefId`, `draftId`, `render` (the PNG file name; the PNGs are not committed), `styleKept` (`appliedArchetype === requestedArchetype`), `fallbackReason`, `observations`, `error` (on a timeout or a failed request) and `accepted` (`null` until the user's verdict). `--verdict <slot>=accept|reject` records the user's verdict on that slot's last result and makes no call.
  - **Safety.** `--base` is required and must be `http://localhost:<port>` or `http://127.0.0.1:<port>`; anything else is refused. Credentials, team and kit come from environment variables (`LOOK_CHECK_USERNAME`, `LOOK_CHECK_PASSWORD`, `LOOK_CHECK_TEAM`, `LOOK_CHECK_KIT`), never from the source. Generations run one at a time (OP-1 hit Prisma's pool at three at once). `--dry-run` prints the slots, the cap and the ledger total and makes no call.

- **FR-15 — The pass rule and OP-028.**

In code (`lookVerdicts(results)` in `lookCheck.mjs`): for each slot, the last result counts; a slot passes when `styleKept` and `accepted === true`; a look passes when all of its slots pass. ## Known limits

- **L1:** the fixtures are synthetic; a pass says nothing about real model images (NFR-11).
