### T22: the locator, `src/lib/drafts/htmlLocator.ts` (new, per Ruling W5-A)

A pure string tokenizer and tree builder. It has no DOM and no new dependency, and it works under MOCK_PUPPETEER.

- `parseHtmlDocument(html)` (`htmlLocator.ts:624`) builds the tree (`build`, `:379`) and checks the document skeleton (`validateSkeleton`, `:594`). It returns `{ok:true, body}` or `{ok:false, reason}`.
  - Every element records source offsets: `start`, `tagNameEnd`, `openEnd`, `closeStart`, `end`, and per attribute `start`, `end`, `valueStart`, `valueEnd` (`:58`).
  - Tag and attribute states follow the HTML tokenizer (`readTag`, `:290`), so a `>` inside a quoted value never ends a tag.
  - Comments are handled, including `<!-->`, `<!--->` and `--!>`, as are bogus comments, `<!doctype>` and `<?…>`.
  - Raw-text elements (script, style, xmp, iframe, noembed, noframes) and RCDATA elements (textarea, title) are handled (`findRawTextEnd`, `:355`).
  - Void elements are handled. So is SVG foreign content: self-closing is honoured there, `<style>` is not raw text, `foreignObject`/`desc`/`title` are HTML integration points, and CDATA is read as text.
- `resolveElementPath(body, path)` (`:640`) follows element-child indices from `<body>`. `[]` is `<body>` itself. A miss returns null.
- `elementTextContent(el)` (`:654`) gives the DOM `textContent`. Comments and `<template>` content are excluded, and entities are decoded. It returns **null** if any character reference can't be decoded with certainty.
- `normalizeFingerprintText` (`:674`) collapses every JS `\s+` run (which includes nbsp and newlines) to one space, then trims.
- `decodeHtmlEntities(raw, 'text'|'attribute')` (`:200`) decodes the following:
  - numeric references;
  - the 106 legacy names, including the no-semicolon rule, which differs between text and attribute context;
  - a small, certain set of names that need a semicolon.
  - Everything else that could be a reference makes the result null.
- Writers:
  - `escapeHtmlText` (`:682`) escapes `&`, `<` and `>`.
  - `replaceElementText(html, el, text)` (`:688`) replaces `[openEnd, closeStart)` with escaped text.
  - `setStyleDeclaration(html, el, property, value)` (`:751`) sets exactly one declaration, as described under "The grammar" below.

## The exact payload (Ruling W5-B)

```ts
POST /api/drafts/:id/inline-edit
{
  mode: 'element',
  locator: {
    path: number[],   // int 0..100000, length ≤ 256; element-child indices from <body>, chrome excluded; [] = <body>
    tag: string,      // 1..64 chars, any case (compared lowercased)
    text: string,     // ≤ 100000 chars; the element's textContent at selection (compared whitespace-normalized)
  },
  edit: {
    kind: 'text' | 'color' | 'backgroundColor' | 'fontSize',
    value: string,    // ≤ 5000 chars
  },
}
```

Any `selector` or `target` field, at any level, is stripped by the schema and never consulted (AC-26).

## The leaf rule

A **text** edit is allowed only on an element that meets all four conditions:

- it has **no child elements** in the stored HTML (text and comment children are fine, and the whole content range is replaced);
- it has a content range, so it is not void and not a self-closed SVG element;
- its tag is not a raw-text or RCDATA tag, nor `template`;
- it sits inside `<body>`.

**Colour and size** edits are allowed on any element in `<body>`, including composite elements and `<body>` itself, except script, style, template and title.

## The grammar (Ruling W5-C)

- **Colour.** Input is trimmed, capped at 64 characters, and must contain none of `; { } \ " ' < >`, `url(` or `/*`.
  - Hex: `#rgb` or `#rrggbb` becomes lowercase 6-digit `#rrggbb`. `#rgba` and `#rrggbbaa` are rejected.
  - Functions: `rgb(r, g, b)` or `rgba(r, g, b, a)`, with a case-insensitive function name and flexible whitespace. Commas are required. Channels are 0–255 integers. Alpha is `0`, `1`, `0.x` / `.x` or `1.0`.
  - Output is canonical `rgb(r, g, b)` or `rgba(r, g, b, a)`.
  - Everything else is rejected: named colours, `hsl`, `var()`, percentages, decimals, space syntax, extra arguments, and `!important`.
- **Size.** `<decimal><unit>` with no space between them. The unit is one of px, pt, em, rem or % (case-insensitive). Exponents and signs are rejected. Bounds are the equivalent of 1–1000 px at a 16px root:

  | unit    | min    | max  |
  | ------- | ------ | ---- |
  | px      | 1      | 1000 |
  | pt      | 0.75   | 750  |
  | em, rem | 0.0625 | 62.5 |
  | %       | 6.25   | 6250 |

  Output is the shortest decimal plus the lowercase unit (`12.50PT` → `12.5pt`).

- **Serialized output is built from parsed numbers only.** It is never a substring of the input. `setStyleDeclaration` also re-checks the value against the only shapes the grammar emits, and the property against `{color, background-color, font-size}`. Anything else **throws**, as a programming error.
- **Text** is escaped (`&`, `<`, `>`) and written as a text node.
- **How a style declaration is written:**
  - If the element has no `style` attribute, ` style="prop: value"` is inserted right after the tag name.
  - If it has one, the value is decoded and split on top-level `;`, meaning outside strings, comments and parentheses. Any declaration of the same property is dropped (including `!important`; comments are stripped before the property is read). The other declarations are kept as written, and `prop: value` is appended. The value is re-encoded (`&` → `&amp;`, `"` → `&quot;`), and **only that attribute's bytes** are replaced, with the attribute double-quoted.
  - Duplicate `style` attributes, an unterminated string/comment/parenthesis, or an undecodable reference all cause a refusal (409 `element-unsupported`).

## Locator limitations (all fail closed as 409 `element-unsupported`; whole-document mode is unaffected)

The locator rejects the whole document whenever a browser's tree could differ from the markup as written. In most places the check is broader than the browser's own rule. Over-rejecting only costs availability, so the checks err that way.

- **Implied or mismatched tags:**
  - an unclosed element, a mismatched or stray end tag, or an end tag for a void element (`</br>`);
  - `<div/>` on a non-void element (the slash is ignored, so the element is left open);
  - EOF inside a tag, comment, raw text or CDATA.
- **Auto-closing and nesting:**
  - a p-closing start tag (div, section, headings, lists, table, hr…) while **any** `<p>` is open;
  - `li` inside `li` without a list between them;
  - `dd`/`dt` inside `dd`/`dt` without a `dl` between them;
  - a heading inside a heading;
  - `a`, `button`, `form` or `nobr` inside itself.
- **Tables:**
  - `tr` directly in `table` (the browser would add an implied tbody);
  - any non-table child of table/thead/tbody/tfoot/tr/colgroup (the browser would foster-parent it);
  - non-whitespace text directly in those elements;
  - td/th/tr/caption/col… outside their required parent.
- **Unsupported elements:** noscript (its parse depends on the scripting flag, and the editor iframe has scripting disabled), plaintext, select, option, optgroup, math, frameset, frame, image, isindex, keygen, and rb/rp/rt/rtc.
- **SVG:** an HTML breakout tag inside svg (for example `div`, `p`, `span`, `font`), unless it sits inside `foreignObject`/`desc`/`title`.
- **Skeleton:**
  - no `<body>`;
  - a duplicate or nested html/head/body;
  - content (text or elements) before `<html>` (for example a model preamble) or after `</body>`;
  - non-head elements or text in `<head>`, or before `<body>`.
- **Scripts and entities:**
  - `<!--` inside `<script>` (script-data escape states are not modelled);
  - an unknown named reference, or a numeric reference that is 0, a surrogate, above 0x10FFFF, or in the C1 range 0x80–0x9F. In the fingerprint these make the text unverifiable (409 `element-unsupported`). In a style attribute they cause a refusal.
- **Divergences not modelled beyond the checks above:** these are guarded only by the fingerprint (same tag and same normalized text at the same path).
- **The fingerprint can't tell identical siblings apart.** If a refine swaps two elements with the same tag and identical text, the edit lands on the equivalent node.

## Self-review findings

- **Element mode can't write markup.** Text only ever goes through `escapeHtmlText` into a content range. Raw-text and RCDATA targets are refused, so escaped text can never become CSS or JS. Post-write verification re-parses the document and requires an identical element count, and the exact text back.
- **Element mode can't write a free declaration or `url(`.**
  - The property comes from a fixed three-entry map.
  - The value is rebuilt from parsed numbers.
  - The anchored patterns plus `CSS_BREAKOUT` reject `;`, braces, backslash, quotes, `<`, `>`, `/*` and `url(`.
  - `setStyleDeclaration` re-validates the value's shape and throws otherwise.
  - The kept declarations are the model's own pre-existing content, which is not widened.
- **Element mode can't write outside the resolved node.** The writers only splice inside `[el.start, el.end)`: the content range, or the one style attribute or the insertion point after the tag name. `applyElementEdit` also checks that every byte before `el.start` and after `el.end` is identical before returning.
- **The target always comes from the server.** It is resolved from the current `htmlContent`, and the schema strips any selector or target. No address is ever stored.
- **Whole-document mode is unchanged.** It keeps the same order, messages and response; `git diff` confirms the helpers are unchanged, and TC-INLINE-01..04 still pass.
- **Minor clean-up.** I removed an `eslint-disable no-control-regex` that turned out unnecessary, which kept the lint baseline at 7 warnings.

## Concerns

1. **Lost update (pre-existing, not widened).** The route reads `htmlContent` and then commits, and `commitDraftRevision` has no compare-and-swap on the document. A whole-document or element edit that commits in between is overwritten by the later commit. Whole-document mode has the same property, and a running refine or regenerate is still 409'd by `pendingAction`. A fix would add an expected-revision guard to `commitDraftRevision`. That was out of scope under FR-19 ("reuse the writer"), so I left it.
2. **The locator is conservative.** Drafts whose HTML uses constructs on the rejection list get 409 `element-unsupported` for every element edit: tables without tbody, a block element inside `<p>`, noscript, select, math, unknown named entities, and so on. Generated posts rarely use these, and a whole-document save re-serializes through the browser, which normalizes most of them (it adds tbody and encodes entities as `&amp;`/`&nbsp;`). T24 should show the "use the whole-document editor" message for this code.
3. **Colour and size edits on large containers** need the container's whole normalized `textContent` as the fingerprint, capped at 100 000 characters.
4. **A style edit can be beaten by the cascade.** It sets an inline declaration, but a stylesheet rule with `!important` would still win. That is a question of whether the change shows, not of safety, and it is not detected.

## What T24 needs

- **Build the locator with the exported helpers:**
  - `path = editorElementPath(el, doc.body)`, which returns null for chrome, so don't allow selecting it;
  - `tag = el.tagName`;
  - `text = editorFingerprintText(el)`.
  - Snapshot `text` **at selection time, before any contenteditable typing**, because it must describe the stored HTML.
  - Both helpers live in `@/lib/drafts/inlineEdit`, which is client-safe: it pulls in only zod and the pure locator.
- **Only text-leaf elements get a text field.** Mirror the rule client-side: `el.children.length === 0` after the chrome is removed, and not script/style/void. The server still enforces it with 400 `element-not-text-leaf` / `element-not-editable`.
- **Treat these responses as follows:**
  - 409 `element-stale`: prompt a reload or reopen (the draft changed);
  - 409 `element-unsupported`: point to the whole-document mode;
  - 409 `draft-busy`: an action is running;
  - 400 `invalid-*`: show the message inline;
  - 200: returns `{reply, revisionId, exportUrl}`, the same as a whole-document save, so reuse `onSaved`.
- **Send the body with `mode: 'element'`, exactly per the payload above.** Omitting `mode` falls through to whole-document mode, which requires `html`.
- **Colour input:** the grammar takes only hex and `rgb()`/`rgba()`; a hex picker covers this. **Size input:** it takes px/pt/em/rem/% within the bounds above.
- **The E2E catalog** can build on TC-INLINE-05 and TC-INLINE-06. Pin a known document through whole-document mode first, then address elements by path.

## Critical

1. **A stale locator writes to a different same-tag EMPTY sibling.** The check is at `inlineEdit.ts:273-278`, following W5-B.
   - Setup: the editor loads `<body><div class="shapeA"></div><div class="shapeB"></div><div class="content">Hi</div>`, then a refine removes shapeA.

## Important

1. **Lost update.** Per request it is no wider than whole-document mode. But element mode introduces a new flow: many small commits in one session.
   - Example: edit an h1's text, then change a `<p>` colour while the first render (1–2 s in real Chromium) is still in flight.
   - Both requests read the same snapshot, both get 200, and the first edit silently disappears.
   - The render window is `revisions.ts:181-187`, before the transaction.
   - Fix: an expected-revision compare-and-swap inside `commitDraftRevision`'s transaction.

## Minor

1. **The style splitter ignores `{}` and `[]`, a trailing `\`, and raw newlines inside strings** (`htmlLocator.ts:702-736`, `:774-779`). Three reproductions, each of which returns 200 with an edit that has no effect:
   - `style="color: red; foo: {"`: the original colour is dropped, and the new declaration lands inside the open `{`.
   - A trailing `\`: the result is `bold\; color: …`.
   - A string with a raw newline: the splitter and the CSS bad-string rules disagree.

   Fix: track brackets, and refuse a trailing backslash or a newline in a string with 409 `element-unsupported`.

2. **Deep nesting returns 500 instead of 409.** The recursive `countElements` (`inlineEdit.ts:230`) and `elementTextContent` (`htmlLocator.ts:654`) throw RangeError at about 5000 levels. `htmlStack()` (`htmlLocator.ts:402`, `:433`) is also quadratic: 20 000 levels take 1.3 s. Fix: reject depth over 512 in `build`, matching Chromium's parser depth cap.
3. **Paths can descend into `<template>` content** (`resolveElementPath`, `htmlLocator.ts:640-649`). A browser's `template.children` is empty, so only a crafted request reaches this. Fix: stop resolution at an HTML-namespace template.
4. **Tag and attribute names use `toLowerCase()` instead of ASCII-only lowercasing** (`htmlLocator.ts:295`, `:316`). For example, `<tracK>` (Kelvin sign) parses as a void `track`. No wrong-node write was found, but ASCII lowercasing makes the tokenizer exact.
5. **Silent text differences.**
   - A browser drops a leading `\n` right after the `<pre>`/`<listing>` start tag. The post-write check (`inlineEdit.ts:320`) compares against the server parse, so it passes anyway.
   - A text edit silently deletes the leaf's comment children.
6. **Missing tests:** the empty-sibling and identical-sibling stale cases, deep nesting, and the style-splitter edge cases.

## Strengths (keep)

- The tokenizer fails closed. Probing found no markup injection, no second declaration, no `url(` and no attribute break-out.
- The grammar is anchored, ASCII-only, and rebuilt from numbers.
- Post-write verification.
- The tests check real behaviour.

## How a CAS miss is handled

- **The check.** Inside `withNextRevisionNumber`'s transaction, first thing, before the adopt guard or any write: `tx.draft.updateMany({ where: { id, currentRevisionNumber: expected }, data: { updatedAt } })`. It is a guarded UPDATE, the same idiom as the adopt guard, not a read followed by a write.
  - It takes the row lock, so a concurrent commit or restore either committed first, which gives 0 rows and a conflict, or waits and then re-evaluates its own write.
  - With 0 rows it throws `RevisionConflictError`. That is never retried: only P2002 is.
  - The transaction rolls back, so there is no revision row, no `htmlContent`/`exportUrl`/pointer change, and no not-applied clearing.
- **Proof over HTTP.** I temporarily instrumented both 409 branches (removed before commit) and ran TC-INLINE-09 12× in parallel. The loser was caught by the **in-transaction CAS** in 12/12 runs, and by the route check in 0. Both requests pass the route check, then the second one blocks on the row lock until the first commits.
- **The export object.**
  - The render and upload happen before the transaction, and the function already leaves the object in place on any failure after upload.
  - For a CAS miss specifically, and only when **this call** rendered and uploaded the object, it is removed best-effort with `deleteObject(BUCKET_EXPORTS, key)`. A failed removal is logged and never masks the conflict.
  - A caller-supplied `exportKey` is never deleted: it isn't ours, and an adopt reuses a rejected render's export.
  - Other failures keep the existing "leave it" behaviour on purpose. After, say, a dropped connection the commit may in fact have landed, and deleting the object would break a committed row.
  - In every case no DB row points at an object that was removed.
- **Unchanged callers.** Whole-document mode, refine, override and adopt don't pass `expectedRevisionNumber`, so no guard runs and their behaviour is byte-for-byte unchanged. The return value gains `revisionNumber`, which is additive and ignored by the other callers.

### 1. Lock order: what changed and why it is deadlock-free

Every writer of the chain now takes its locks in one order:

1. the revision insert, which takes the `(draftId, revisionNumber)` unique-index slot;
2. the rejected-render rows (the adopt stamp, then `discardNotAppliedRender`);
3. the draft row, which is **always the last write**.

That is the same order the unguarded commit, regenerate-design (insert → `draft.update`), `recordRejectedRender` (rejected rows → draft) and restore (discard → draft) already use. The draft-row guards are no longer a leading "touch". They are the `WHERE` of the final write:

```ts
const written = await tx.draft.updateMany({
  where: {
    id: draftId,
    pendingAction: null,
    ...(adoptRejectedRevisionId ? { notAppliedRevisionId: adoptRejectedRevisionId } : {}),
    ...(cas ? { currentRevisionNumber: casExpected } : {}),
  },
  data, // exactly what the plain draft.update writes
})
```

- **A miss** throws, and the throw rolls back the insert, the stamp and the discard.
- **A concurrent insert of the same number** makes our insert wait on the index and then fail P2002. `withNextRevisionNumber` retries with a fresh read.
- **Element vs element** stays deterministic: the loser gets P2002, retries at N+2, and then misses the CAS.
- **Element vs a whole-document save:**
  - If the save inserts first, the element insert waits, the save commits, the element retries and misses the CAS: a 409.
  - If the element inserts first, it commits, and the save's retry lands: both 200.
- **Plain path:** the non-CAS, non-adopt path is still an unguarded `tx.draft.update` after the insert. Its behaviour and order are unchanged.
- **Export cleanup:** the round-1 cleanup (remove our own upload on `RevisionConflictError`) is unchanged. An `AdoptConflictError` never uploads, because adopt reuses the rejected row's key.

### 2. url()

- **What counts as a url token.** When the splitter meets a `(` outside a string or comment, it reads back the function name, ASCII-lowercased. If the name is `url` and the first non-whitespace character after it is not a quote, the body is one url token, not a block.
- **Its end.** `unquotedUrlEnd` returns the index of the first `)`. It returns -1 (refuse) on any of these:
  - `"`, `'` or `(`;
  - a non-printable character;
  - `\` before a newline or at EOF;
  - EOF without a `)`.
- **Escapes.** Valid escapes are skipped. So is `\"`, which stays accepted.
- **Hidden `url` names are refused too.** `functionNameBefore` returns null (refuse) for:
  - a name holding a backslash (`u\72l(`);
  - a name that follows an escaped character (`a\;url(` is one ident);
  - a name after a hex escape's swallowed whitespace (`u\72 l(` **is** `url(` to CSS). The RED test caught this one: my first version missed it.
- **Still accepted:**
  - a quoted `url("…")`, whatever it holds;
  - `url(a.png)` and `url(a;b.png)`;
  - `myurl(a(b))`, which is an ordinary function.

### 3. Single-flight

- **The check.** The element CAS `WHERE` includes `pendingAction: null`. Only the CAS path adds it. Refine commits while it holds its own claim, and adopt already had the condition.
- **Distinguishing the two causes: a read inside the same transaction.** On `count !== 1` it does `tx.draft.findUnique({ select: { pendingAction } })` and throws `RevisionConflictError(pendingAction)`.
  - Under READ COMMITTED, that read sees the same committed state the `UPDATE`'s re-evaluation saw.
  - This keeps the classification next to the guard, so one typed error carries it, rather than the route doing a second, non-transactional read.
- **When both conditions fail**, busy wins: it tells the user why, and the edit is refused either way.
- **The route** maps via the pure `elementCommitConflict(pendingAction)`:
  - a set action gives 409 `draft-busy`, reusing `inlineEditBlockReason`'s exact message ("Another action is already running on this draft");
  - null gives 409 `element-stale`.
- **The error-code union** gains `draft-busy`, which the route already emitted from its own busy check.
