## T9: harness design, and why it lives where it does

**Layout:**

- `scripts/glyph-check/glyphCoverage.mjs` is the shared core. It is plain ESM with no dependencies (it uses only `node:zlib`) and contains:
  - `decodePng`: a small 8-bit, non-interlaced grey/RGB/RGBA decoder that handles all 5 row filters.
  - `measureInk`
  - `judgeGlyph`
  - `buildGlyphProbe`
  - `assessGlyphProbe`
  - `formatGlyphResult`
  - `codepointLabel`
  - `TOFU_RULES`
- `scripts/glyph-check/check-glyphs.mjs` is the in-image check, used for AC-01.
- `tests/render/rasterize.ts` is the reusable TypeScript harness. It provides:
  - `rasterize(html, w, h)`, which calls the real `renderHtmlToPng` and returns decoded RGBA plus the scale.
  - `pixelAt`
  - `checkGlyphCoverage(glyphs, opts)`
  - `assertNoTofu(glyphs, opts)`
  - `judgeRegion(image, candidateRect, controlRect)`, for tests that render their own HTML.
  - Re-exports of `measureInk`, `judgeGlyph`, `TOFU_RULES` and `codepointLabel`.
- `tests/render/render-fidelity.test.ts` holds 9 cases.
- `vitest.render.config.ts` and the `npm run test:render` script run the suite. The config includes `tests/render/**`, forces `env: { MOCK_PUPPETEER: 'false' }` and runs files serially with a 60 s timeout.
- `tests/unit/pngDecode.test.ts` holds 4 cases. The decoder underpins everything, so it gets its own unit test: every row filter, RGB and grey expansion, and rejection of unsupported input.

**Tofu detection is glyph-agnostic and compares against a control.** Each candidate is drawn in its own cell next to a covered control glyph (`H`), using the same font size and family. The default family is the generic `sans-serif` with no web fonts, so the check measures the OS fontconfig fallback that posts actually rely on. A candidate fails in either of two cases:

- **blank**: its ink is below 1% of the control's ink.
- **rectangle**: all four edges of its ink bounding box are at least 90% filled, and the box is glyph-sized relative to the control (at least 0.5× the control's height, and at least 0.25× the control's height wide).

The size comparison with the control is what keeps thin filled rectangles such as — | _ from reading as tofu. Both signatures occur in practice:

- In the Alpine image, uncovered codepoints render **blank**: Open Sans draws nothing for .notdef.
- On Windows Chrome they render as a **hollow box**, the rectangle signature.

**Why the harness is not in `tests/e2e` (a deliberate departure from the paths in tasks.md).** Playwright's testDir is `tests/e2e`. It would pick up `render-fidelity.test.ts` and run it under the CI e2e job, which sets `MOCK_PUPPETEER=true` job-wide. E2E tests also never import `src/`. The unit vitest config excludes browser tests by design. So the harness gets its own config and directory, `tests/render/`, which is what the controller's ruling 2 suggested.

**Why the shared core is in `scripts/`.** The image has no dev dependencies, no TypeScript and no tests. So the one file that must run in both places has to be plain ESM with no dependencies, and it gets mounted into the image. Only how the PNG is produced differs between host and image. Decoding and judging are the same file, so the two can never disagree about what counts as tofu.

**No new dependency.** The hand-rolled decoder was chosen over `pngjs` because `pngjs` would be a dev dependency. It would not exist in the runner image, so the in-image check would need a separate decode path, which would break the sharing.

**AC-03 guards:**

- `rasterize` throws if `MOCK_PUPPETEER` is on.
- It also throws if the returned buffer equals `MOCK_PNG_BUFFER`.
- The suite asserts `MOCK_PUPPETEER === false`.
- I also ran `MOCK_PUPPETEER=true npm run test:render`. The config override still applies and 9/9 pass on real renders.

## How CI runs it (`.github/workflows/e2e.yml`, build job; the only hunk is at the end of the file)

1. `docker build -t bistec-studio:ci .`. Previously this was an untagged `docker build .`.
2. **Glyph coverage inside the runner image:** `docker run --rm -v "$PWD/scripts/glyph-check:/app/glyph-check:ro" --entrypoint node bistec-studio:ci /app/glyph-check/check-glyphs.mjs`
   - It is mounted under `/app` so that the bare `puppeteer-core` import resolves from the image's `/app/node_modules`.
   - `--entrypoint` skips migrate-on-boot.
   - The script exits 0 only if ★ ✓ ✦ → • are covered **and** U+10FFFD is detected as tofu. That second condition is a self-check that proves the detector is live, so a pass cannot come from a detector that sees nothing.
3. **Render-fidelity harness:** `npm run test:render` on the runner's Google Chrome (`/usr/bin/google-chrome` is already in `pickExecutablePath`'s candidates).

Nothing is skipped: every failure path throws. I did not touch Node versions or the FROM lines.

## Concerns

1. **Known shape limitation.** A glyph whose real shape is a glyph-sized closed rectangle (□ ■ █ 口 田) reports `rectangle` even when it is covered. This is documented in the module header. Those glyphs need a different assertion; one option is `judgeRegion` against a reference rendered in a font known to cover them.
2. **The host harness has not been run on Linux Chrome.** It will first run on the CI ubuntu runner. That run expects ★ ✓ → • to be covered by the runner's system fonts, which DejaVu normally provides, and expects U+10FFFD and U+1FFFD to be uncovered. If the runner image lacks DejaVu, the ★ host case would fail there. That would be an environment issue, not a harness bug, but it would turn the build job red.
3. **Chromium launch args are duplicated.** `check-glyphs.mjs` repeats the launch args and 2× scale from `puppeteer.ts`, because the image cannot import TypeScript. A comment in both places says to keep them in sync.
4. **The two failure signatures appear in different places.** In the image, tofu with the default `sans-serif` renders blank. The prod reports of boxes came from brand fonts whose .notdef glyph is a box. Both signatures are detected: the rectangle signature is exercised by the host run and the blank signature by the image run. But the in-image check only ever sees the blank case.
5. **Out of scope here.** T8 (the font-set digest) is not included; it was not part of this dispatch.
