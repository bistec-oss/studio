## What was implemented

### The poll field (exact shape, Ruling E)

`GET /api/drafts/[id]` now returns, as a new top-level field:

```ts
notApplied: {
  reason: string
  instruction: string
  revisionId: string
  previewUrl: string | null
  rejectedAt: string   // ISO
} | null
```

Type defined once in `src/lib/api-types.ts:231-244` (`DraftNotApplied`), reused by:

- `src/lib/drafts/revisions.ts:366-401` — new `resolveNotAppliedOutcome(draft)`, the single function that builds it.
- `src/app/api/drafts/[id]/route.ts:133-137,157` — calls it in `loadDraft` and adds `notApplied` to the response (all other existing fields unchanged).
- `src/components/drafts/RefinementPanel.tsx` / `src/app/(app)/drafts/[id]/page.tsx` — the client type.

`resolveNotAppliedOutcome` implements the carried-in dereference exactly:

```ts
if (!draft.notAppliedReason || !draft.notAppliedRevisionId) return null
const row = await prisma.draftRevision.findFirst({
  where: {
    id: draft.notAppliedRevisionId,
    draftId: draft.id,
    rejectedAt: { not: null },
    discardedAt: null,
  },
  select: { id: true, instruction: true, exportUrl: true, rejectedAt: true },
})
if (!row || !row.rejectedAt) return null
```

— never trusts `Draft.notAppliedRevisionId` alone. `previewUrl` is `resolveExportUrl(row.exportUrl)` (dynamic-imported from `@/lib/storage/minio`, matching this file's existing pattern for `commitDraftRevision`/`recordRejectedRender`), `null` when the row has no export. Nothing else off the row (no `htmlSnapshot`, no `rejection` JSON) is returned.

I put the helper in `src/lib/drafts/revisions.ts` rather than inline in the route — it belongs beside `COMMITTED_REVISION`/`discardNotAppliedRender` as "the one place that reads the not-applied outcome," matching how T17 organized this file. `DraftNotApplied` is defined once in `api-types.ts` (a route already imports types from there elsewhere, e.g. `team/claude-token/route.ts`) and imported as a type into `revisions.ts` — no duplicate shape.

### Restore clears the outcome (T17 concern 4 ruling)

`src/app/api/drafts/[id]/revisions/[rev]/restore/route.ts:63-83` — the single `prisma.draft.update` is now a batched `prisma.$transaction([discardNotAppliedRender(prisma, params.id), prisma.draft.update({ ...NOT_APPLIED_CLEARED })])`, same two statements and same batch (non-interactive) form `completeDraftAction` already uses. Order matters and is preserved: discard runs first (while the FK still points at the row), the update clears the FK second.
