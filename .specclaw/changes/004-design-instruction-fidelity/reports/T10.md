## T11 — Inline-asset reconciliation replacing detection

**Files changed:** `src/lib/agent/inlineAssets.ts`, `tests/unit/inlineAssets.test.ts`

### Design

Added `reconcileInlineAssets(sentTokens: string[], replyHtml: string): ReconcileResult`, pure, no I/O, next to the existing `extractInlineAssets`/`restoreInlineAssets`/`missingTokens` in the same file (kept unchanged, per ruling — caller wiring is T17).

```ts
export type ReconcileResult =
  { kind: 'clean' } | { kind: 'restored'; missing: string[] } | { kind: 'mismatch'; reason: string }
```

Algorithm:

1. Scan `replyHtml` for all token-shaped occurrences via a new module-level `TOKEN_RE`, built from the same `TOKEN_PREFIX`/`TOKEN_SUFFIX` constants `extractInlineAssets` already uses (one token pattern for the whole file — no second literal pattern defined) — ``new RegExp(`${TOKEN_PREFIX}.*?${TOKEN_SUFFIX}`, 'g')``, counting occurrences per exact token string (multiset).
2. Any found token not in `sentTokens` → `mismatch` (covers renamed and reindexed placeholders).
3. Any sent token found more than once → `mismatch` (covers duplicated placeholders).
4. Otherwise, sent tokens absent from the reply are computed; none absent → `clean`; some absent → `restored` with the list.

**One deliberate design decision worth flagging:** the token regex's middle is a _lazy wildcard_ (`.*?`), not `\d+`. A first draft used `\d+` (mirroring how tokens are minted: `TOKEN_PREFIX + index + TOKEN_SUFFIX`), but that made a genuinely-renamed token (e.g. `__INLINE_ASSET_RENAMED__`, prefix/suffix kept, index replaced with non-numeric content) invisible to the scanner — it would just look like the original token vanished, i.e. a clean absence (`restored`), not a mismatch. The controller ruling's own wording — "anything else (unknown token such as a reindexed `__INLINE_ASSET_7__` not sent, a sent token appearing twice, renamed tokens)" — groups "renamed" together with "unknown token", implying a renamed token must still be _recognized_ as a token-shaped string in order to be flagged as unknown. Switching to a lazy wildcard between the fixed prefix/suffix makes that true without changing any minted-token round-trip behavior (numeric indices still match the same way, just via `.*?` instead of `\d+`).
