## Findings

### [NOTE] src/lib/renderer/puppeteer.ts (MOCK branch of sampleRegionLuminance) , Fail-closed coverage

**Problem:** the `MOCK_PUPPETEER` branch returns before the `data:`-only check and ignores degenerate regions (a 0x0 region gets a sample, not `null`). So under E2E mock a non-data URL or a bad region never produces `HeroCheckError` / `region-invalid` at this layer. This matches the design (T4's seams drive the error and region cases upstream), but T4 must supply those paths, since AC-12 is only proven here by the real-render tests.
**Suggestion:** none now; T4 should have a `__MOCK_HERO_*__` case for check-error and region-invalid.

### [NOTE] src/lib/renderer/layoutFacts.ts:52 , Security (accepted, same as export)

**Problem:** `measureLayoutBoxes` goes through `withRenderedPage`, so the model's HTML runs with JS enabled and the standard allowlist (MinIO + Google Fonts hosts), not the sampler's full block. That is the same trust boundary as export of the same HTML, so no new exposure. The sampler itself only ever loads a `data:` image and no model HTML, and is fully network-blocked.
**Suggestion:** none; just be aware that `networkidle0` means a layout measure can cost up to the render timeout (60 s). T4's `layoutMeasureMs` budget entry should use that worst case, since `observeLayout` has no timeout of its own.

### [NOTE] src/lib/renderer/puppeteer.ts (sampleRegionLuminance, `limit(async ...)`) , Concurrency

**Problem:** on timeout the race rejects and releases the p-limit slot while `heroSampleOnce` may still be unwinding (page.close is in flight). Brief, bounded, and no leak, but the cap can be momentarily exceeded by one closing page.
**Suggestion:** none.

### [NOTE] tests/render/hero-sampler.test.ts , Tuning claims vs assertions

**Problem:** the report cites a partial-band fixture (9% busy band, 1.64x over the limit) and a 6% textured-share estimate, but no test asserts it. The asserted margins (calm below limit/4, stripes above 3x, mid grey fails contrast with fraction 0) do back the 8.5x and 4.2x claims. `CONTRAST_PASS_FRACTION` is honestly reported as unconstrained (fixtures land at 0 or 1), and the test named for it only asserts the constant is 0.95, which is a constant-pin, not tuning evidence.
**Suggestion:** either add the partial-band case or drop the 1.64x claim from the report; OP-1 owns the real placement.

### [NOTE] tests/render/hero-layout.test.ts , measurement-error test

**Problem:** the "returns null and logs" case relies on `width: -5` making Puppeteer throw. It passes, but depends on a Puppeteer error rather than a deliberate seam.
**Suggestion:** none now.
