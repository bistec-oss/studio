# T3 report: the Chromium sampler, the layout extraction, the real-render fixtures, the tuning

Not committed (per instructions). No prisma or DB command was run against `bistec_studio`; the E2E ran on a freshly dropped and rebuilt `bistec_studio_test`.

## What changed

- `src/lib/renderer/puppeteer.ts`: added `HERO_CHECK_TIMEOUT_MS` (20 000), `HeroCheckError` and `sampleRegionLuminance(dataUrl, regions, canvas, timeoutMs = HERO_CHECK_TIMEOUT_MS)`. Steps follow design section 5.
  - A non-`data:` URL throws `HeroCheckError` before any page opens.
  - The page is network-blocked (only `data:` and `about:blank` pass).
  - Natural dimensions are read first. T2's `mapRegionToImage` runs in Node. The source rect is clamped to the image so `drawImage` never clips and re-maps.
  - A second `evaluate` draws each region with `imageSmoothingEnabled = false` onto a grid of at most `SAMPLE_GRID_MAX` points (`gw = round(sqrt(MAX*w/h))`, `gh = round(MAX/gw)`, each capped at the rect's pixel size). It returns raw RGBA.
  - Node drops points with alpha under 128 and converts the rest with T2's `relativeLuminance`. The page carries no formula copy.
  - The whole body runs in `Promise.race` against the timeout, inside the renderer's `limit`. On timeout the page is closed, and any throw becomes `HeroCheckError`. A region the mapping rejects returns `null`.
  - Under `MOCK_PUPPETEER` it returns 256 calm samples per region (L about 0.02, plus or minus 0.001) with `areaPct = w*h/100`. It reads no sentinel.
  - Design deviation, declared: an optional 4th parameter `timeoutMs`, so the timeout path can be tested on real Chromium without waiting 20 s. Production callers use the default. The internal helper is named `heroSampleOnce` (the file already had a `sampleOnce`).
- `src/lib/renderer/layoutFacts.ts` (new): `measureLayoutBoxes(html, {width, height, logoUrls, excludeUrls})` returns canvas-percent boxes. It throws on a browser error. `observeLayout(html, textRegions, opts)` is the wrapper: it calls T2's `evaluateLayout` and returns `null` (logged with `console.warn`) on any error. It also returns `null` under `MOCK_PUPPETEER`; the caller uses the mock seam there, per design.
  - It measures the text-node `Range` of every non-blank text node whose ancestor chain is visible (display, visibility, opacity), and every `<img>` whose `src` is in the kit's logo set.
  - Exclusions: the background image (`excludeUrls`), any box over 60% of the canvas (`FULL_BLEED_AREA_PCT`), brief images (never logos), hidden elements, and script/style text.
- `tests/render/heroFixtures.ts` (new): HTML fixtures rasterized through `renderHtmlToPng` at 2x, for both shapes (1024x1024 and 1024x1536): `calmDark`, `busyStripes`, `midGrey`, `cropRowsBusy(cropped|visible)`. It also holds a Node PNG encoder with `checkerboard` (the A3 fixture) and the layout page (`layoutPage`, `KIT_LOGO`, `BRIEF_IMAGE`, `BACKGROUND`).
- `tests/render/hero-sampler.test.ts` (new): 21 cases covering AC-11, A3 and AC-12 on real Chromium.
- `tests/render/hero-layout.test.ts` (new): 11 cases covering AC-14, the real half.

Undeclared files: none. `state.json`, `status.md`, `tasks.md` and `timeline.jsonl` of the change were already modified before I started (specclaw bookkeeping); I did not touch them.

## A3 proof: point sampling with smoothing off

Fixture: a 256x256 one-pixel black/white checkerboard, encoded in Node as a PNG with no colour chunks (so the bytes are the pixels), sampled over the whole image (`{0,0,100,100}`, canvas 256x256, so the cover fit is the identity). The sampler downsamples to about 63x63 points.

- Every returned luminance is exactly `0` or `1`. The distinct set is `[0, 1]`, and about half the points are white. A blend would show intermediate values.
- Control, in the same test file: the same `drawImage` downscale with `imageSmoothingEnabled = true` on the same bundled Chromium produces more than 100 intermediate-grey pixels. This shows the fixture can tell smoothing on from off, so the exact-0/1 assertion has teeth.
- The checkerboard's L* standard deviation is about 0.5, well above `BUSY_STDDEV_MAX`, so a textured region reads as textured.
- Alpha: a checkerboard with a fully transparent left half returns 40% to 60% of the full sample count, and `areaPct` stays at the region's 100. A fully transparent image returns 0 samples, and `evaluateRegions` gives `region-invalid`.

## Tuning table (synthetic fixtures)

The fixtures are synthetic: gradients, stripes and flat grey made in Chromium. These margins say the rules separate the obvious cases with room to spare. They are not evidence about real model images; the real fallback rate is OP-1's. Measured at the version-1 regions (SQUARE left 45%, PORTRAIT top 38%), about 3990 and 3956 points each.

| Fixture                         | L* std (limit `BUSY_STDDEV_MAX` 0.12) | max L (light-text limit 0.183) | passLight fraction (need 0.95) | Verdict                            |
| ------------------------------- | ------------------------------------- | ------------------------------ | ------------------------------ | ---------------------------------- |
| SQUARE calm dark gradient       | 0.0140                                | 0.0136                         | 1.000                          | pass                               |
| PORTRAIT calm dark gradient     | 0.0114                                | 0.0128                         | 1.000                          | pass                               |
| SQUARE busy stripes             | 0.4994                                | 1.0                            | 0.524                          | busy                               |
| PORTRAIT busy stripes           | 0.4999                                | 1.0                            | 0.489                          | busy                               |
| SQUARE mid grey `#808080`       | 0.0000                                | 0.2159                         | 0.000                          | contrast (light); passes dark text |
| PORTRAIT mid grey               | 0.0000                                | 0.2159                         | 0.000                          | contrast (light)                   |
| 1024x1536, busy in cropped rows | 0.0137                                | n/a                            | n/a                            | pass                               |
| 1024x1536, busy in visible rows | 0.1966                                | n/a                            | n/a                            | busy                               |

Margins:

- `BUSY_STDDEV_MAX` 0.12: calm sits 8.5x to 10.5x below it. Pure stripes sit 4.2x above it. The partial-band fixture (a 9% busy band) sits 1.64x above it. Treating the busy band as a two-level mix, the std is roughly 0.5*sqrt(p(1-p)), so the limit trips at a textured share of about 6% of the region. The value 0.12 is kept.
- `CONTRAST_MIN` 4.5 / light limit 0.183: calm max L is 13x below the limit. Mid grey (0.216) is 18% above it and fails cleanly: its pass fraction is 0.
- `CONTRAST_PASS_FRACTION` 0.95: every contrast fixture lands at 0 or 1.000, so the fixtures do not constrain this value. It is untuned beyond that; only a real-image set can place it. It is left at 0.95.
- `MIN_SAMPLES` 64 and `SAMPLE_GRID_MAX` 4000: a full region yields 3956 to 3990 points (cap and rounding), and a fully transparent image yields 0.
- No T2 constant was changed. Only `tests/unit/evaluateRegions.test.ts` asserts any of them, and it is untouched.
