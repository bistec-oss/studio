# T4 report: POST /api/events, the wizard events, brief.submitted, brief.abandoned and the funnel

## What changed

- `src/app/api/events/route.ts` (new): `POST /api/events`, `withTeamAuth`. Raw body read as text, more than 2 048 bytes is 413 (before parsing); invalid JSON 400; a name outside `CLIENT_EVENTS` 400; the payload is validated against the catalogue schema (400, so a bad client payload never reaches `track`'s test-seam throw); the 60 per user per minute window; a `briefDraftId` kept only when `briefDraft.findFirst({ id, userId })` finds it (a foreign or missing id is 404 and writes nothing); then `track` with `source: 'web'` and the session's `teamId` and `userId`. Any `teamId`, `userId`, `source` or `draftId` in the body is ignored (zod strips unknown keys). Answers 204.
- `src/lib/analytics/rateLimit.ts` (new): `allow(userId, now)`, a rolling 60 s window of timestamps per user in a `Map`; a refused event is not recorded; the map is swept of stale users once it passes 1 000 entries; `resetRateLimit()` for tests.
- `src/lib/analytics/track.ts`: `count` is now exported (one word; no behaviour change), so the route can record a refusal in `AnalyticsDrop` as `dropped` / `rate-limit`.
- `src/lib/analytics/client.ts` (new): `sendWizardStep(step, briefDraftId)`, a `fetch(..., { keepalive: true })` with `.catch(() => {})` inside try/catch; never awaited, never throws. It deliberately does not import the catalogue (that would pull Prisma into the client bundle).
- `src/components/brief/useBriefWizard.ts`: reports a step once per visit using a high-water mark ref (`maxStepReportedRef`). Fresh wizard: step 0 on mount (guarded for Strict Mode). Resume: nothing until the row loads, then the mark is set to the restored step, so only moving past it reports; a row that is gone or unreadable reports step 0 as a fresh start. `resumed` is sent in the `POST /api/briefs` body.
- `src/app/api/briefs/route.ts`: `brief.submitted` after `brief.create` (path, aspect ratio, image style, `resumed === true`); counts and enums only.
- `src/lib/brief/briefDrafts.ts`: `trackAbandoned`; emitted by `sweepExpiredBriefDrafts` (reason `expired`) and by `deleteBriefDraft` when `keepImages` is false (reason `discarded`). Step is read from the stored payload (null if it no longer parses). Eviction past the cap, the Generate-success delete and the unparsable-row cleanup in list/get emit nothing.
- `src/lib/analytics/queries.ts`: `shapeFunnel` (pure) and `funnel()` added to `insights()`: per step the count of `wizard.step` events and its share of step 0, `brief.submitted`, and `brief.abandoned` by reason. Tagged-template `$queryRaw` only.
- `src/components/admin/insights/sections.tsx` and the page: `FunnelSection` (a table plus two stats) built from the existing `DataTable`, `RateBar`, `Stat` and `InsightSection`; no raw colours, no `ui-exception`.

## Ambiguities and choices

1. **Status of a rate-limited event is 204**, the same as an accepted one. The design lists only 204 / 400 / 401 / 413 and the client must neither learn nor react; the loss is counted and shown on the page. A 429 would be more conventional HTTP and is a one-line change if wanted.
2. **A foreign `briefDraftId` answers 404.** "No event, consistent with 404 semantics" read literally. The client ignores errors.
3. **Rate limit runs before the ownership lookup** (so a flood cannot hit the database) and after validation (so the dropped event's name is known).
4. **Step 0 is reported on a fresh wizard** (the funnel needs a denominator; the payload range is 0 to 4). "Reached" = one event per step per visit, so the funnel counts visits, not distinct briefs; this is stated in the section's caption.
5. **`resumed`** is carried by a body field the route reads only for the event; `Brief.create` lists its fields explicitly, so it is not stored.
6. **Existing TC-OBS-10 needed one edit.** `POST /api/briefs` now writes `brief.submitted`, which consumed the single `failNext` meant for the generation. The case now creates the brief first, then arms `failNext`, then assembles. No assertion changed.
7. **Unit total 3273** (baseline 3255 plus 18); none deleted.
8. `git diff --name-only 3c9b593` lists `src/lib/agent/prompts/caption.ts`: that change is from an earlier committed task (T1/T2), not this one. `claudeCli.ts`, `heartbeatStatus.ts` and the status route are untouched.

## Orchestrator-requested fixes

1. **Capped body read** (`src/app/api/events/route.ts`): `readCapped` refuses a declared `Content-Length` over 2 048 without reading, otherwise reads `req.body` with a reader and a running byte count, cancels the reader and returns 413 as soon as the total passes 2 048 (a missing or lying length is still capped). Unit cases added: declared-large header is 413 with no body read; a chunked body with no length, and one with a lying length, are 413 and the stream is cancelled early; exactly 2 048 bytes is accepted (204) and 2 049 is 413.
2. **Funnel over 100%**: `shapeFunnel` now takes submissions split by `payload->>'resumed'`. `submitted` (fresh only) is rated against step 0; `submittedResumed` is a count with no rate. The page shows a row "Submitted from a resumed brief" with a dash, and the count column header is now "Visits". Unit and TC-OBS-29 updated (4 resumed submissions seeded beside 2 fresh: the fresh rate stays 20%, the resumed row has no rate).
