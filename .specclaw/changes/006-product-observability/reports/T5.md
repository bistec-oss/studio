# T5 report: usage accumulator, API-mode token counts, token columns

- `src/lib/analytics/trace.ts`: `UsageStore`, `newUsage`, `withUsage(store, fn)` (AsyncLocalStorage), `addUsage`, `usageFields` (null when `calls === 0`).
- `src/lib/models/anthropicCall.ts`: `createMessage` calls `addUsage(message.usage)` after the refusal check; a no-op with no active store.
- `src/lib/drafts/draftActions.ts`: `startDraftAction` runs `work` inside `withUsage` and puts `inputTokens`/`outputTokens` in the `draft_action.settled` payload (also on failure).
- `src/lib/agent/generateDraft.ts`: both lifecycles open a store (`GenerationTrace.usage`); `runGenerationForDraft` became a thin wrapper over `runGenerationForDraftInner`; `generation.finished` carries the token fields.
- `src/lib/analytics/queries.ts`: `durations` rows add `inputTokens`, `outputTokens` (sums over reported events only) and `notReported` (count of events with null tokens).
- `src/components/admin/insights/sections.tsx`: Input tokens, Output tokens, Not reported (%) columns; a row with every event unreported shows an en dash for totals.
- `tests/unit/analyticsUsage.test.ts` (new, 7 cases), `tests/e2e/analytics.test.ts` (TC-OBS-30).

## Choices

- `withUsage` takes a store (design said `withUsage(fn)`) so a throw still leaves the spent tokens readable by the emitter.
- The MOCK_AI seam bypasses `createMessage`, so TC-OBS-30 seeds events through the seam; summing is proven by the unit test.
- No schema change, no new call sites, no CLI change.
