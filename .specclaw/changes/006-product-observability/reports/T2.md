## Design ambiguities and choices

1. **`GenerationActor.source`.** Making `source` required on `GenerationActor` itself would have forced it onto the refine route, regenerate-design, Path A/B, background.ts and many test literals, none of which emit. I added `GenerationRunActor` (identity plus `source`) and required it only on the two generation lifecycles. Every caller of those still must state its source, which is the intent.
2. **Settle result.** The design says "emit only after a successful settle write" and "no event if the settle lost its claim". `releaseDraftAction`/`completeDraftAction` returned void, so both now return a boolean (additive; the three other callers ignore it).
3. **No trace, no event.** `startDraftAction` emits only when a `trace` is passed (the three routes always do; the existing unit tests that call it bare are unaffected).
4. **Emission outside the failure branches.** In `runGenerationForDraft`, `jobRunner` and `generationRunner` the emission sits after the try/catch, not inside the success path, because under the test seams `track` throws on an invalid payload and a throw inside the try would have re-entered the failure branch (a finished draft marked FAILED; a published post retried). In production `track` never throws, so this only affects tests. The web retry route's success emission is inside its try (a seam-only 500 at worst, no domain write follows it).
5. **Retry route.** Only a PublishError outcome emits (the row is written FAILED); an unexpected throw is rethrown with no row write and no event, as before.
6. **`generation.swept`** needs `teamId`; `DraftRecoveryRow` gained `teamId` (the loaded draft already carries it). `ageMs` is `now - updatedAt`.
7. **`appliedArchetype`** is passed from the stamp as is. An archetype key outside the dataset would fail the catalogue enum (a throw under test seams, a `rejected` count in production); the stamp only ever holds dataset keys or `classic`.
8. **`captionRoute`** is passed only when the stamp string is one of the four known values, else null, so an unexpected stamp can never reject the whole event.
9. **Scheduler publish `retryCount`** is the post's count before this attempt for published and terminal failed, and the next count for `retry-scheduled`.
10. **Verifier literal.** `tests/unit/heroPrompts.test.ts` ("no other prompt, draft or route file carries a version string literal") listed exactly caption.ts and shared.ts. The verifier's own version now lives in `src/lib/drafts/refineVerify.ts` as the design requires, so the expected list gained that file, with a comment (a verifier stamp is not a `PROMPT_VERSION`).
11. **Seam rows** are validated by a loose zod schema and inserted with `createMany`, bypassing the catalogue on purpose (E2E needs to seed old and odd history).
12. **Review NOTE-1** (verdict as a free string) left as is: the pure constant would need to come out of `revisions.ts`, which imports prisma; `verdict` carries the four known values from the diagnostics enum.
