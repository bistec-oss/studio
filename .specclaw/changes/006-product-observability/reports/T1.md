## Design ambiguities and choices

1. `ARCHETYPE_KEYS` does not exist in `@/lib/designData`. The catalogue derives it as `Object.keys(archetypes)` (the dataset itself), plus `classic`. `FALLBACK_REASONS` (stamp.ts) is imported for the fallback reason.
2. `CaptionRoute` stamp strings: route.ts exports types only, so the catalogue lists `SERVER_KEY`/`OTHER` with a `satisfies readonly Exclude<CaptionRouteStamp, RouteSetting>[]` compile-time check, unioned with `z.nativeEnum(CaptionRoute)`.
3. Refine attempt `verdict` is `z.string().max(20)`, not an enum: the only enum lives in `drafts/revisions.ts`, which imports prisma, and the catalogue must stay pure. Instruction classes are imported (`INSTRUCTION_CLASS_KEYS`, a pure module).
4. Model ids (`modelId`, `substitutedFrom`) are bounded strings (stamps may hold retired ids); keys use `z.enum(MODEL_KEYS)`.
5. `track` also validates source and outcome against the entry (an outcome on an outcome-less event, or a value outside the list, is invalid), which the design implied through `source`/`outcomes` fields.
6. The coverage guard is a source scan: any quoted string in `catalogue.ts` (comments stripped) equal to a value of an owned vocabulary fails; a planted copy is asserted on a fixture string.
7. The counter write has its own 500 ms bound so a dead database cannot stall an action twice over (worst case 2.5 s).
8. `payload` unknown keys are stripped (plain `z.object`), which also enforces NFR-04.

## Orchestrator follow-up (review WARN)

The review (`reviews/T1.md`) found that after an insert timeout, `track` awaited the counter write (up to 500 ms more), so the worst case was about 2.5 s against AC-02's 2.1 s. Fix: `track.ts` no longer awaits the counter write on the insert-failure path (`void count(...)`; `count` never rejects and has its own bound). New unit case: "returns within the bound when the insert and the counter both hang".
