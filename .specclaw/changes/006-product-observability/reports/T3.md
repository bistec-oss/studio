## Design ambiguities and choices

1. **Applied rate** = `ok / (ok + not-applied)` (AC-12), with conflict and failed shown beside it (FR-10 says "ok ÷ settled REFINE"; AC-12 is the checkable one).
2. **Per class** uses the union of `classes` (not `effectiveClasses`) over a refine's attempts, so a refine counts once per class it carries; only `ok` and `not-applied` events.
3. **Durations** are successful (`ok`) events only; model is the design model for generation and the action's model for actions; route is `captionRoute` (generation only).
4. **Styles**: missing `requestedArchetype` reads as `classic`; "applied as requested" is over succeeded generations, and `classic` counts as applied; mean refines is over succeeded generations with a draft id, counting every REFINE settle on that draft (any date).
5. **Retention loop state** (page): online when the newest of tick start/end is within 180 s (023's rule), else stale; no row is `never`. It reuses `OFFLINE_THRESHOLD_MS` only; no 023 file changed.
6. **Week buckets** are UTC ISO weeks (`YYYY-MM-DD` of the Monday), so E2E sums rows per verifier instead of assuming one week.
7. **"No session is 401"**: the proxy redirects a cookie-less API call to /login (as TC-HB-06 notes), so E2E asserts the redirect for no cookie and 401 for a bogus session cookie.
8. **Purge script near-miss, fixed.** My first version imported `@prisma/client` statically; that import loads `.env` into `process.env`, so with no `DATABASE_URL` the guard saw the shared database from `.env` and ran a `count` against it (read only; the table does not exist there, so it errored; nothing was written). The guard now runs before a dynamic `import('@prisma/client')`, and the URL is passed as `datasourceUrl`. Re-run: exit 2.
9. **E2E campaigns**: `exportedDraft` creates no campaign (the first draft of this suite did, and a suite run five times pushed `team-isolation`'s seeded "Bistec Campaign" out of `GET /api/campaigns` (newest 200)). Test DB was recreated and everything re-run.
