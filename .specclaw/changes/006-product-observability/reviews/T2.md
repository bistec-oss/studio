## Findings

### [NOTE] src/lib/agent/generateDraft.ts:~293 (generateDraftForBrief wrapper) - Correctness

**Problem:** `catch (err) { await emitGenerationFinished(...); throw err }`: if the emit throws, the original error is replaced. In production `track` never throws, so this only affects the test seams (failNext/invalid payload). Same shape at publishDraft.ts failed branch and posts/[id]/publish/route.ts success emit inside the try (a seam-only 500 after the row is PUBLISHED).
**Suggestion:** none required; if wanted, `.catch(() => {})` on the emit in the catch block.

### [NOTE] src/app/api/drafts/[id]/revisions/[rev]/restore/route.ts:~85 - Correctness

**Problem:** `from` is read before the restore, so a concurrent action can make it stale. Analytics-grade only.

### [NOTE] src/app/api/drafts/[id]/route.ts:~336 - Design adherence

**Problem:** the draft-delete transaction now includes `analyticsEvent.updateMany`, so a missing analytics table would fail a draft delete. Matches the design's explicit delete rule; noted only.
