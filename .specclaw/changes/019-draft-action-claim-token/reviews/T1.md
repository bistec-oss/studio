### [NOTE] prisma/rollback/019-draft-action-claim-token.down.sql:10-15 — Correctness (atomicity)

**Problem:** The down script runs its `DROP` and its `DELETE` as separate statements with no `BEGIN`/`COMMIT`. If the `DELETE` fails after the `DROP` has run, the column is gone but the migration row is still recorded. The 016 down script has the same shape, so this follows precedent.
**Suggestion:** Optional: wrap both statements in `BEGIN; … COMMIT;`. Re-running the script is already safe, since `DROP COLUMN IF EXISTS` and the `DELETE` are both idempotent, so the risk is low.
