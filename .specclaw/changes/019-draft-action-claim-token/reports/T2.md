# T2 report: the claim mints a token; lifecycle writes, caption settles and the sweep are guarded on it

Status: done, not committed (per instruction). OQ-1 and OQ-2 both included (OQ-2 here; OQ-1 is T3's).

## What changed, per file

Source

- `src/lib/drafts/claim.ts` (new): `DraftClaim { action, claimId }`, `newClaimId()` (`crypto.randomUUID`), `claimWhere(claim)`, `claimData(claim)` (the write side of a claim), `CLAIM_RELEASED` (`{ pendingAction: null, pendingActionClaimId: null }`) and `logLostClaim(draftId, claim)` (logs the action and draft ID, never the token). Imports only `crypto` and a Prisma type, so no cycle with draftActions, revisions or captions/store.
- `src/lib/drafts/draftActions.ts`: `claimDraftAction` returns `DraftClaim | null` (WHERE still `{ id, pendingAction: null }`, data via `claimData`). `touchDraftAction`, `releaseDraftAction`, `completeDraftAction` and `startDraftAction` take the claim and guard on `claimWhere`; release and complete null the token. `logLostClaim` moved to `claim.ts` (so `store.ts` can use it without importing draftActions).
- `src/lib/drafts/revisions.ts`: only `discardNotAppliedRender`'s optional filter, now `claim?: DraftClaim` via `claimWhere` (the action-only filter is gone). The type import of `DraftAction` was replaced by the claim helpers.
- `src/lib/captions/store.ts`: `claimCaptionAction` returns `DraftClaim | null` and writes the token. `settleCaptionAction(draftId, claim, targets, fields, stamp?, db?)` opens with a claim-guarded draft-row `updateMany` (touching `updatedAt`) inside the same transaction, before any caption row; on a miss it logs once and returns. The headline write is guarded on `claimWhere(claim)` instead of the hard-coded `'REGENERATE_COPY'`. `settlePendingCaptions` and `saveGenerationCaptions` untouched.
- `src/app/api/drafts/[id]/route.ts`: `DraftRecoveryRow` gains `pendingActionClaimId`; the sweep's clear is `where { id, pendingAction, pendingActionClaimId }` (observed values; null matches IS NULL) and also nulls the token. The response is explicitly built, so the token is not in it. `recovery.ts` is unchanged.
- `refine/route.ts`, `regenerate-design/route.ts`, `regenerate-copy/route.ts`: hold the `claim` value (null answers 409 as before), pass it to every touch, `startDraftAction`, all three caption settles and the unstarted-run release. Content writes (commitDraftRevision, recordRejectedRender, the conflict write, regenerate-design's revision write) are left unguarded for T3.

Tests (existing cases adapted, none deleted)

- `draftActions.test.ts`: fixtures moved to claims; shared stateful `statefulRow` (guards on action and token); the existing "settling is guarded on the claimed action" block kept and extended; new "late settle from a swept run does not touch a new claim of the SAME action" block (AC-02: touch, release-with-error, complete, start success, start throw, not-applied completion, the discard filter, log has no token); claim tests (token minted, two claims differ, WHERE unchanged).
- `captionStore.test.ts`: claim returns/token cases; settle cases take the claim and assert the guard write comes first; new stateful late-settle block (AC-03: success and failure fields from the superseded run leave rows PENDING with R2's text and the headline; live claim settles).
- `captionRoutes.test.ts`: claim fixture; new case that the claim reaches `startDraftAction`, the unstarted settle and its release; 409 on a null claim; settle arity 4.
- `draftDetailGet.test.ts`: `updateMany` on the Prisma fake; sweep cases (WHERE carries observed action and token, data nulls the token; null token swept via IS NULL; mismatched observed token writes nothing; the token never appears in the response).
- `captionWriters`, `draftActionModels`, `modelRequests`, `renderStamps`: only fixture updates (claim objects instead of `true`, widened fake arg type). `actionHeartbeats` needed nothing.

## Design choices

- `claimData` and `logLostClaim` live in `claim.ts`, so `pendingActionClaimId` appears in `src` only in `claim.ts` and the sweep (AC-06's grep) and `store.ts` does not import `draftActions`.
- The caption settle's guard write is a plain `updatedAt` touch on the draft row: it takes the row lock first (NFR-04) and doubles as the claim check.
- Lost claim is logged per settle; the heartbeat stays silent as before.
