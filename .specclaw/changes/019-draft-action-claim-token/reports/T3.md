# T3 report: the content writes from a claimed run are guarded on the claim

Status: done, not committed (per instruction). OQ-1 is included (user ruling 2026-10-20).

## What changed, per file

Source

- `src/lib/drafts/claim.ts`: adds `DraftClaimLostError`.
- `src/lib/drafts/revisions.ts`:
  - `commitDraftRevision` gains optional `claim?: DraftClaim`. Combined with `expectedRevisionNumber` or `adoptRejectedRevisionId` it throws a programming error before anything is rendered or uploaded. With a claim, the plain-commit branch is skipped and the existing guarded final `tx.draft.updateMany` takes `claimWhere(claim)` in place of `pendingAction: null`; a miss throws `DraftClaimLostError` (no extra read). The write stays last (LOCK ORDER comment untouched; a comment bullet for the claimed run was added).
  - The existing CAS-miss cleanup condition is extended to `RevisionConflictError || DraftClaimLostError`, and its body moved into a small `removeUnusedExport(key, why)` helper (same best-effort delete and log as before).
  - `recordRejectedRender` takes a required `claim`. `discardNotAppliedRender(tx, draftId, claim)` and the final draft write (now `updateMany` where `{ id, ...claimWhere(claim) }`) are guarded; 0 rows throws `DraftClaimLostError`, which rolls the transaction back. The transaction is wrapped in a try/catch that removes the render it uploaded on a lost claim, through the same helper.
- `src/app/api/drafts/[id]/refine/route.ts`: the verified commit and `recordRejectedRender` pass `claim`; the conflict write is a claim-guarded `updateMany`, and on a miss it calls `logLostClaim` and returns (never throws).
- `src/app/api/drafts/[id]/regenerate-design/route.ts`: the final `tx.draft` write is a claim-guarded `updateMany`; a miss throws `DraftClaimLostError`, rolling back the revision insert.
- `prisma/schema.prisma`: not changed. The T1 review NOTE (comment described the target state) is accurate now that T2 and T3 landed (settles and sweep null the token, every run write is guarded), so no edit was needed.

## Design choices

- Claim rather than `pendingAction: null` in the same final write, so no leading draft touch and no new lock order (NFR-04).
- One `removeUnusedExport` helper serves both uploaders. The commit path still uses the single extended condition; recordRejectedRender needs its own catch because it uploads before its transaction, but it calls the same helper.
- Regenerate design does not remove its orphaned export (spec edge case: out of scope).
- The conflict write logs on a miss instead of throwing, so `startDraftAction`'s complete then misses too, as specified.
