## Findings

### [WARN] src/components/dashboard/RecentDraftsCard.tsx:136-141 — a11y: scrollable region is not keyboard-reachable

**Quoted:** `<div className={\`border-t-2 border-fg ${expanded ? 'max-h-96 overflow-y-auto overflow-x-auto' : 'overflow-x-auto'}\`}>`wrapping`<table className="w-full min-w-[600px] ...">`.
**Problem:**

- At 375 px the table is forced to 600 px, so this div is a scroll container.
- It has no `tabIndex` and no name. A keyboard user can reach the Created column and the Resume/Discard controls only by tabbing into them (Chromium may scroll on focus). They cannot scroll to read the cells.
- This is WCAG 2.1.1 and the axe rule scrollable-region-focusable.
- T7 introduced `min-w-[600px]`, so it is new.
  **Fix:** add `tabIndex={0} role="region" aria-label="Recent drafts"` to that div. The focus ring comes from `FOCUS` (`focus-visible:outline`). Add `focus-visible:outline-offset-[-2px]` so it is not clipped by the scroll box.

### [NOTE] RecentDraftsCard.tsx:148-154 — table header semantics

**Problem:** the `<th>` cells have no `scope="col"`. Browsers infer it for a simple table, so this is low risk. Setting it explicitly costs nothing.
**Fix:** `<th scope="col" ...>` on the six header cells.

### [NOTE] tests/e2e/surfaces.test.ts:274-277 — focus helper still counts any box-shadow as a ring

**Quoted:** `const ring = cs.boxShadow !== 'none'`
**Problem:**

- Tailwind's composed shadow variables compute to a non-`none` transparent shadow on elements that carry ring or shadow utilities, even when unfocused.
- That can produce a false "visible".
- Pre-existing, but the T7 edit touched the neighbouring line.
  **Fix:** apply the same non-transparent test to the shadow colour, or require `outlineWidth > 0` or a shadow whose spread is greater than 0.

### [NOTE] tests/e2e/surfaces.test.ts:965-967 — conditional expand

**Quoted:** `if (await expand.isVisible()) await expand.click()`
**Problem:** the expanded state is not guaranteed, so the "Recent Drafts expanded" label can silently be untrue. The seed likely holds fewer than 8 drafts.
**Fix:** either seed more than 8 drafts, or rename the assertion to "Recent Drafts (expanded when available)". The core overflow check stays valid either way.

### [NOTE] src/components/library/PostCard.tsx:~105-112 — truncated meta line

**Problem:** `truncate` on "channels · brand kit" hides long kit names with no `title`. Before, channels were wrapped pills.
**Fix:** add `title` with the full string.

### [NOTE] src/components/library/PublishHistoryDrawer.tsx:~113 — new tint combination

**Quoted:** `text-status-failed bg-status-failed/10`
**Problem:**

- It is the same combination StatusChip uses, but it sits on the drawer surface rather than the canvas.
- I could not confirm that `tests/unit/designTokens.test.ts` computes it against the drawer's background.
  **Fix:** if the contrast test only checks the failed chip on the canvas, add the surface case. `status-failed` on the 10% tint is the combination to compute.

### [NOTE] RecentDraftsCard.tsx Expand and Discard — small targets

**Problem:**

- Expand and the Discard trash are about 15-16 px tall.
- They pass WCAG 2.5.8 only through the spacing exception.
- Adding `p-1.5` on the icon button would make this robust.
