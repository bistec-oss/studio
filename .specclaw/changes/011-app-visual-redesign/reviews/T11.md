## Findings

### [WARN] tests/e2e/surfaces.test.ts mintBrandKitFixture (~line 1-45 of the added block)

Problem: the fixture creates a kit (plus logo, doc, template and source document) in each of 4 tests (AC-17, AC-12, and 2 themes) and never removes it. Every E2E run leaves 4 more kits, and the brand kits page lists all of them. Repeated local runs on a reused DB will slow the kit list and push the AC-17 tab stops onto whichever kit sorts first (the test tolerates that, but it is fragile). The same pollution class was already hit by the campaign 200-cap.
Fix: have the fixture return the kit id and delete the kit in `afterEach` (`DELETE /api/admin/brandkits/${kit.id}`, the same call the page's delete uses), or track created ids in an array and clean them up there. Cleanup should also run when an assertion fails.

### [NOTE] src/components/admin/brandkits/KitDetail.tsx ~line 1070 and 1093 (template form)

Problem: `<label className={fieldLabelClasses}>Size</label>` and `<label ...>HTML/CSS</label>` are not tied to a control (no `htmlFor`). The Size group has an `aria-label`, but the HTML/CSS textarea has no accessible name. This matches HEAD, so it is not a regression.
Fix: `htmlFor` plus `id` on the textarea, and `<span>` instead of `<label>` for Size.

### [NOTE] src/components/admin/brandkits/ColorEditor.tsx:44 (the `#1A2B3C` input)

Problem: the add-colour input has no label or aria-label, only a placeholder. It is unchanged from HEAD, but in the assistant the former `<label>` over it is now a `<p>`, so the palette caption no longer labels anything.
Fix: `aria-label="Add color"` on the input.

### [NOTE] src/components/admin/brandkits/ColorEditor.tsx:~34 and FontEditor.tsx:~88

Problem: the remove "×" targets are 24 px (`h-6 w-6`). The rest of the screen uses the 30 px `ICON_BUTTON`. This is acceptable for dense chips, but it is below the system's 30 px target.
Fix: use `h-[30px] w-[30px]`, or leave as is and note it.

### [NOTE] src/components/admin/brandkits/BrandKitAssistantPanel.tsx ~line 303

Problem: the "Conversation" region gets `role`, `tabIndex` and `aria-label` only once messages exist, so the attributes appear and disappear. This is fine for AT, but the empty state is not scrollable, so confirm that long docs lists never push it into overflow.
