## Findings

- [NOTE] src/components/brief/SizeDesignStep.tsx:72, :117, :136 (also TemplateCard.tsx:21, CampaignRow.tsx:19, CampaignStep.tsx:~104) — aria-pressed on exclusive single-selects. A radiogroup would be the exact semantics, but FR-12 freezes roles, and aria-pressed is a correct non-role-changing way to expose selection. Keep; revisit if a later change allows role changes.
- [NOTE] src/components/brief/Stepper.tsx:~50 — not-done steps stay focusable, with a no-op onClick, so keyboard users tab onto dead stops. This is identical to HEAD, but the new AC-17 test (surfaces.test.ts:1244, expects '2Size & Design') now cements it. Fix later: `aria-disabled={!done && !active}`, and still assert the first three stops.
- [NOTE] src/components/brief/ReviewStep.tsx:~828 — the submitting notice uses `status-exported` (purple). Contrast is fine (the pair is checked in §3.3), but the colour names an unrelated state. Use a neutral/ink notice or accent for in-progress.
- [NOTE] tests/e2e/surfaces.test.ts:1231-1236 — cleanup is correct (diffs against a pre-test id set, matches the `{drafts:[{id}]}` response shape in the route). Two small risks. (a) The 5-row per-user cap can evict a pre-existing draft during the walk, and the cleanup can't restore it. (b) A late debounced autosave PUT could land after the listing. Both are unlikely, since the first PUT happens many steps earlier. Optionally `await page.waitForTimeout`-free: poll `briefDraftIds` until the id set is stable before deleting.
- [NOTE] tests/e2e/surfaces.test.ts:1268 — `getByRole('combobox')` with no name relies on the Brand Kit select being the only one on step 2. Give it `{ name: /brand kit/i }` if the Select exposes a name; otherwise fine.
