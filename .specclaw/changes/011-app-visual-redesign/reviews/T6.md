## Findings

### [WARN] src/components/theme/ThemeToggle.tsx:18 — a11y (label in name)

**Problem:** The button shows the visible text "Light" / "Dark" but `aria-label="Switch to dark mode"` replaces it. For a speech-input user, saying "Light" or "Dark" does not match the name (WCAG 2.5.3 Label in Name). The aria-label also keys on React `theme`, which starts as `'light'` and is only set in a mount effect (`ThemeProvider.tsx`). The visual highlight keys on the `.dark` class, so for one frame a dark-theme user sees "Dark" highlighted while the name says "Switch to dark mode" (the wrong action). There is no hydration mismatch, but the two states can disagree.
**Fix:** Keep the single button but make the name contain the visible text, e.g. `aria-label="Theme: switch to dark"`. Or drop the aria-label and use `<span className="sr-only">Theme</span>` plus the segments, with `aria-pressed={theme==='dark'}`. The E2E assertions at tests/e2e/surfaces.test.ts:358/383/385 would change with it.

### [NOTE] src/components/layout/CreatePostButton.tsx:~33 — hard-coded colour

**Problem:** `active:shadow-[2px_2px_0_0_rgb(0_0_0/0.2)]` is an off-token literal and does not follow the dark-theme shadow token.
**Suggestion:** Use a shadow token (e.g. `--shadow-raised`) or leave it and note it.

### [NOTE] src/app/(auth)/login/page.tsx:43 — heading structure

**Problem:** The login page now has no `h1`. The wordmark is `role="img"` and the old page had none either, so this is not a regression. T13 or an a11y pass could still add a visually hidden `h1`.

### [NOTE] tests/e2e/surfaces.test.ts (hover test) — reduced-motion coverage

**Problem:** The "lifts 1px" and "does not move" hover tests are decent: they poll the real computed `transform`. Relying on `motion-reduce:hover:transform-none` winning over `hover:-translate-x-px` depends on Tailwind's variant order. The reduced-motion test (computed transform is `none`) does guard that, so it is fine.

### [NOTE] src/components/layout/AppShell.tsx — NavLink active match

`pathname.startsWith(item.href)` is unchanged from before. It would mark `/team` active for any `/team…` path, which is pre-existing and not for T6.
