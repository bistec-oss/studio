## Quality

Opacity is enforced at the source. `.surface*`, `.glass` and `.glass-popover` are all `background-color` with no `backdrop-filter`. No hex, rgba, `dark:` variant or legacy colour token is left in `ui/*` or `ToastProvider` (grep is clean). Only `bg-scrim/*` is translucent, which is intended.

### [NOTE] src/components/layout/AppShell.tsx:208 — leftover blur on a scrim

The mobile sidebar `Dialog.Overlay` still has `bg-black/30 backdrop-blur-sm`. It is a scrim, so AC-09 does not apply, but it conflicts with FR-08's "no blur". Fix in T6: `bg-scrim/30`, drop the blur.

### [NOTE] src/app/globals.css:374-380 — reduced-motion fade on toasts uses `both` fill

`animation: fade 150ms linear both !important` on `[data-sonner-toast]` holds `opacity:1` after the end of the animation. That overrides Sonner's `data-removed` opacity transition. Under reduced motion, a dismissed toast therefore vanishes abruptly at unmount instead of fading. This is cosmetic. Fix: use `backwards` (or `none`) fill on the toast selector, or accept it.

The `.surface-raised` selector would also fade any future in-flow `.surface-raised` on mount. Nothing uses it that way today. The Create post button, Panel and Input use neither the class nor `bg-surface-raised`, so they do not animate.

### [NOTE] tests/e2e/surfaces.test.ts:~262 — fixed `waitForTimeout(300)`

The reduced-motion centring test settles with a fixed sleep. It is low flake risk, but it can be replaced with `await expect.poll(async () => Math.abs((await dialog.boundingBox())!.x + ... - vp.width/2)).toBeLessThanOrEqual(2)`.

The `<=150` duration assertion would also pass at 1 ms, so it does not prove the modal animation survived. That is acceptable, because the centring assertion is the real guard.

### [NOTE] tests/e2e/surfaces.test.ts — AC-19 check is weak

The first-paint test asserts `html.dark` at the moment `<body>` is inserted, plus a null localStorage. It does not assert a painted colour. This is sufficient for the stated AC, but it is a proxy.

`alphaOf` throws on `color(srgb ...)`. That fails loudly, which is correct.

### [NOTE] src/components/ui/Button.tsx:7 — `ink` variant not in the brief

It is documented in the code comment as the refine Send button, and it is a tiny addition. The ring offset is `canvas`, so on `surface-overlay` (surface-2) the offset gap shows a slightly different colour inside modals. This is minor.

### Checks that passed

- Sonner `unstyled`: the stacking-hide rule is restored, the close button is absolutely positioned with a visible focus ring, and the toast keeps role and aria-live from Sonner. T1's offsets are kept.
- Focus rings are present on Button, Input, Select, SegmentedToggle (inset, so overflow-hidden does not clip it), and the Modal and lightbox close buttons. All use `ring-focus` and the tokens switch per theme.
- `Modal` keeps `animate-modal-in`, so the centring is intact. The lightbox's `animate-drop` is on an `inset-0` flex container, not a transform-centred one, so it is safe.
- `StatusChip` uses 0.10 alpha in both themes, with the label always present.
- The E2E covers both themes for the header, desktop and mobile sidebars, the team menu, the toast, the publish modal, the confirm dialog, the lightbox chrome and the Create post button. The tests assert on the computed style rather than classes, and the draft is cached per worker. No outside-the-diff risk worth a BLOCK.
