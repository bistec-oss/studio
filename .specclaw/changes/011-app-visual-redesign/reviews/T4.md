## Findings

### [WARN] src/app/globals.css (reduced-motion block, `animation-iteration-count: 1 !important`)

Problem: this turns every infinite loop into a single 1 ms run. `animate-spin` (18 files use spin or pulse) ends on rotate(360deg), which is the start frame. With no fill, it then snaps to the base state. A loading spinner or skeleton pulse becomes static and stops signalling activity. The modalIn centring is kept, because that animation uses `fill: both` and still ends on its final frame, so that part is correct.
Fix: leave infinite loops running slowly, or give them a reduced-motion form that still shows activity. For example:
`[class*="animate-spin"], .animate-pulse { animation-iteration-count: infinite !important; animation-duration: 1.5s !important; }`, or an opacity-only pulse at 1.5 s. Doing this in T5 is acceptable if T5 is named as the owner. Today nothing owns it, and the test pins the current behaviour.

### [NOTE] tests/unit/designTokens.test.ts:121

The reduced-motion regex only matches if the block is the last thing in globals.css (`\}\s*$`). Appending any CSS after it breaks the test with a misleading "block is falsy". Anchor on `@media (prefers-reduced-motion: reduce)` and balance the braces instead.

### [NOTE] src/app/layout.tsx:13-41

The layout now loads and preloads Fraunces (normal and italic, with opsz) and Instrument Sans on every page, but nothing renders with them until T5. That costs a font download for no visible gain. This was a deliberate choice in the brief, but note it for the T5 or T13 perf check, because the font weight shows up before the benefit does.

### [NOTE] scripts/capture-ui.mjs:32

`CAPTURE_USERNAME` defaults to the email `admin@bisteccare.lk`, but the field is the Username input. The seeded username is `adminBTG` (seed-admin.mjs:27). Confirm that login accepts the email. If it does not, the default is wrong. The credentials are the fixed seeded test fixture and are overridable through env, so there is no secret leak.

### [NOTE] tailwind.config.ts (status-*.dark)

`dark` and `DEFAULT` point at the same var, so the StatusChip `dark:` classes are harmless. This does change the colour of unmigrated StatusChips: scheduled goes from sky to amber, and every status changes. That is per the brief, but it is a visible AC-08 deviation for unmigrated screens. T5 should re-capture.
