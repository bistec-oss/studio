## Findings

### [WARN] `src/app/(app)/drafts/[id]/page.tsx:296-297` and `:394` (heading outline)

The proof column comes first in the DOM. "Revision History" is an `<h3>` and the sections are `<h2>`, but the page `<h1>` (`:394`) comes after it. Reading order is therefore h3, h1, h2, h2, so the outline is incoherent. A screen-reader heading list starts at a level-3 heading with no parent.

Fix: make "Revision History" an `<h2>` (pass the level through `SUB_HEAD`). Better, also give it a numeral-less h2 role consistent with the copy-desk sections. As a lighter alternative, put `aria-labelledby` on a `<section>` and drop the heading level.

### [WARN] `src/app/(app)/drafts/[id]/page.tsx:356-358, 374` (version instruction nearly unreadable)

The contact-sheet cell is about 65-110 px wide, and the instruction is `line-clamp-2` in it. At 375 px (4 columns) that is about 10 characters, so a non-current version's instruction is effectively lost.

- HEAD showed the full instruction, `line-clamp-2` at roughly 280 px.
- `aria-label` and `title` ("Switch to vN") replace the visible text as the name.

Fix: put the instruction in the button's `title`, for example ``title={`Switch to v${n}: ${r.instruction}`}``, and keep `aria-label` as is. Consider `grid-cols-3` or `grid-cols-2` below `sm`, or drop the date line on mobile.

### [WARN] `src/components/drafts/RefinementPanel.tsx:336-346` (second primary)

Send is hand-rolled as a filled ink button (`bg-fg text-canvas`) while Publish is the primary. That is two filled primaries on one view, against "one primary per view".

- The plain `<button>` also skips the Button primitive's shared disabled and focus handling.

Fix: either make Send an outline button (`border-l border-line text-fg`, with an ink hover) or record the exception in the report. Keep the label "Send".

### [NOTE] `src/components/drafts/RefinementPanel.tsx:~246` (status colour semantics)

A log row's "Not applied" was red at HEAD and is now `text-status-scheduled` (amber). The NotAppliedCard directly below it is red (`status-failed`), so the two disagree for the same event. Fix: use `text-status-failed` on that row.

### [NOTE] `RefinementPanel.tsx:~210` (a tab stop that may not be needed)

The refine log is `role="region"` with `tabIndex=0` whenever it has any message, not only when it overflows `max-h-72`. That adds a tab stop on every short log, whereas the T7 rule was "overflowing scroll containers". Fix: set `tabIndex` only when `scrollHeight > clientHeight` (a ResizeObserver or an effect on `messages`). Low priority.

### [NOTE] `CopyEditor.tsx:~141`, `RefinementPanel.tsx:~207` and `page.tsx` copy skeleton (numerals hard-coded)

`numeral="i."`, `numeral="ii."` and the page skeleton's `"i."` are hard-coded inside the "separable" components. 012 will turn the caption into three panels and 008 may add sections, so they will need a `numeral` prop or numbering owned by the page. Props were unchanged as required, so this is only a hint for 012/008. The skeleton and CopyEditor must stay in step.

### [NOTE] `page.tsx:76` (`ratioShort`)

`ASPECT_LABELS[...].split(' ')[0]` depends on the label format ("1:1 Square"). It works today, but the dependency is silent. Fix: a `ratioLabel` export beside `ASPECT_LABELS`, or add a unit assert.

### [NOTE] `ElementEditPanel.tsx:~181` (icon style)

The notice icon still uses `size={14}` rather than `ICON` (15 / 1.4). Trivial.

### [NOTE] `tests/e2e/surfaces.test.ts` (E2E robustness)

- `mintExportedDraft` keeps the same caching semantics. The cache is set only after `status === 'EXPORTED'`, and the mutating test mints a fresh draft, so it does not pollute the shared one.
- The AC-17 test hard-codes the stops `['Library', 'View full screen', 'Regenerate design']`. That is fine only with a single version, which the comment says. If any earlier case ever mutated the cached draft it would flip to "Switch to v1". It is currently safe because the mutating case uses its own draft.
- `[aria-current="true"]` is unique today, but would collide if a nav link ever used `true`.
