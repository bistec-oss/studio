## Decisions

- **The Sonner prop shape was checked against the installed version** (`node_modules/sonner` 2.0.7, `dist/index.d.ts`): `Offset = { top?, right?, bottom?, left? } | string | number`, used for both `offset` and `mobileOffset`. An object key you leave out falls back to Sonner's default, which is 24 px on desktop and 16 px on mobile (`assignOffset`). The toaster switches to full width at `max-width: 600px`, so the mobile offset needs the same 96 px bottom clearance. That clearance is the button's 56 px height plus its 24 px inset, plus a 16 px gap.
- **`title` is set at every width.** A `title` attribute can't be scoped to a breakpoint without JS media-query state, so it is always present: the tooltip is available below `md` as A2 asks, and above `md` it only repeats the visible label. `aria-label` keeps the accessible name identical at both widths.
- **The `/brief` check is `pathname !== '/brief'`.** `usePathname()` drops the query string, so `/brief?resume=…` hides the button too. The test covers this.
- **The button is placed in the DOM after `<main>`,** so keyboard users reach it after the page content, in the normal tab order. No `tabIndex` is used.
- **The button sits below the dialogs.** At `z-30` it is under the header (`z-40`) and under the mobile sidebar overlay and Radix modals (`z-50`). The Sonner toaster's own z-index is far higher.

## Concerns

1. **Contrast.** White on `primary` (`#0284c7`) is about 4.1:1, under the 4.5:1 that NFR-01 asks for at the 14 px semibold label size. This is the same pairing the existing primary `Button` uses in light mode, and the task said "solid bg-primary, white text". NFR-01 is enforced from the token task on (AC-16), so the token or primitives task should pick the button's fill when it restyles `CreatePostButton` (design §6).
2. **Entry animation.** Sonner slides each new toast in from `translateY(100%)` at opacity 0. For about 400 ms, a fading-in toast's box passes below its resting place, which could brush the top of the button. Once the toasts settle they never overlap, and the AC-03 test asserts the settled state.
3. **A parallel task's files.** An untracked `docs/ui-reference/direction-studies/` appeared in the working tree during this task. It is not mine, probably from a parallel T2, and I left it alone.
4. **Process cleanup.** A stray `test:e2e:serve` from an earlier session was still listening on :3001 at the start, and I stopped it. After the run I stopped every node process not belonging to chrome-devtools-mcp. At that point the only ones left were the E2E server's tree.
5. **Screenshots** were saved to the session scratchpad and are not in the repo. Their paths are in the orchestrator hand-off.
