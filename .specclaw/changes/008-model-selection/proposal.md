# Proposal: Model selection per surface (Haiku / Sonnet / Opus)

**Created:** 2026-09-23
**Status:** 🟡 Draft

## Problem

**Every Claude model in the product is hard-coded, and users cannot choose one.** A marketer who wants a richer design, a sharper caption, or a stronger assistant has no control. The only lever is the `CLAUDE_CLI_MODEL` env var, a deploy-time global that forces one model onto every call.

Where the models are fixed today:

| Surface                                                   | Model today                       | Where it's fixed                                                                        |
| --------------------------------------------------------- | --------------------------------- | --------------------------------------------------------------------------------------- |
| Caption                                                   | Haiku                             | `claudeCli.ts:25` fallback (CLI); `providers/implementations/copy/anthropic.ts:8` (API) |
| Design, template fill (Path A)                            | Haiku                             | `agent/config.ts:24,28`                                                                 |
| Design, freeform (Path B) + regenerate-design             | Sonnet 4.6                        | `agent/config.ts:25,29`                                                                 |
| Refine                                                    | Haiku / Sonnet by design mode     | `api/drafts/[id]/refine/route.ts:160,170`                                               |
| Campaign briefing chat (incl. schedule planning), Enhance | Sonnet                            | `campaign/briefingAssistant.ts:49,56,201`                                               |
| Brand-kit assistant (vision extraction)                   | Sonnet                            | `brandkit/assistant.ts:221` → `agent/vision.ts:78,128`                                  |
| Image → template (vision)                                 | Sonnet                            | `brandkit/templateFromImage.ts:45` → `agent/vision.ts`                                  |
| Brand voice draft                                         | Sonnet 4.6, separately hard-coded | `brandkit/voiceDraft.ts:7` (bypasses `modelFor` entirely)                               |

Four further problems sit alongside that:

1. **The pinned IDs are a generation behind.** The API path pins `claude-sonnet-4-6`. The current family (checked 2026-10-12) is Haiku 4.5 (`claude-haiku-4-5-20251001`), Sonnet 5.5 (`claude-sonnet-5-5`), Opus 5.5 (`claude-opus-5-5`) and Fable 5.1 (`claude-fable-5-1`).
2. **CLI and API mode can run different model versions.** CLI mode passes short aliases (`haiku`, `sonnet`), which the CLI resolves to whatever version it maps them to. API mode pins full IDs. The same brief can therefore be generated by different models depending on deploy mode, and nothing records which.
3. **`CLAUDE_CLI_MODEL` would silently override any user choice.** It is applied as `override || explicitModel` (`claudeCli.ts:25`). Build a picker on top of that and the env var wins every time without telling anyone.
4. **Opus was the historical cause of Path B timeouts.** CLAUDE.md (2026-07-01) records that the old Path B timeouts were "the **Opus default**, not Sonnet". The CLI design call is capped at 300s (`designAgentCli.ts:38`), and both the generation sweep and the `pendingAction` sweep fail anything older than **15 minutes**. Adding Opus without revisiting both limits brings that failure straight back.

## Proposed Solution

One model catalogue, one resolver, three places to choose.

1. **Model catalogue** in `src/lib/agent/config.ts`: Haiku 4.5, Sonnet 5.5 and Opus 5.5. Fable 5.1 is left out by user decision (2026-10-12) and can be added later as one entry. Each entry carries its full API ID, a display name, a relative cost/speed label, and a per-surface timeout. The **full ID is passed in both modes** (`claude -p --model` accepts full IDs; see the `claudeCli.ts:20` comment), so CLI and API always run the same version.
2. **Named surfaces.** Every model call declares one:
   - `caption` (named `caption`, not `copy`, to match **012**'s rename). **012 is built (2026-10-11):** one caption call writes the on-image **headline** and the Instagram, LinkedIn and WhatsApp captions as one JSON object (`writeCaptions` with `GENERATION_TARGETS`, `src/lib/captions/generate.ts`). So the headline sits **under** the `caption` surface, not beside it, and the same surface covers `regenerate-copy` in all three forms: "Regenerate all" (`{}`), one channel (`{channel}`) and the headline (`{headline:true}`). The `COPY` provider slot and the `regenerate-copy` / `generate/copy` route names are unchanged.
   - `design.template`
   - `design.freeform`
   - `refine`
   - `assistant.briefing` (campaign chat + schedule planning + both Enhance flows)
   - `assistant.brandkit` (vision extraction + image → template + voice draft)

   Internal steps stay fixed and are not user-facing: the background-image decision (Haiku, `modelForBackground`), the token-validation ping (`userToken.ts:127`), and **004's refine verifier** (pinned to Haiku by user decision 2026-09-23 — the retry, not the check, uses the user's refine model).

3. **One resolver**: `resolveModel(surface, { requested, userId, teamId })`. Precedence:
   1. explicit request, validated against the team allow-list;
   2. the user's remembered choice for that surface;
   3. the team default;
   4. the system default (today's split).

   `CLAUDE_CLI_MODEL` moves from override to system-default fallback.

4. **Where users choose (decided 2026-09-23: per post/chat, remembered):**
   - **Brief wizard:** Caption model + Design model pickers on the Review step.
   - **Refine box:** a model picker beside the instruction.
   - **Each assistant chat header** (campaign briefing, brand-kit assistant): a model menu. Each turn is a stateless call with history, so switching mid-conversation is safe.
   - The last pick per surface is remembered per user.
5. **Team defaults + allow-list at `/team`** (team admins). **Decided 2026-09-23: Opus is allowed for everyone by default**; admins can remove any model from their team's list. The server always validates against the allow-list and never trusts the client.
6. **Non-interactive callers use the team default:** the scheduler, MCP and ACP have no acting user (they pass `null` to `withClaudeAuth`). A `ScheduledGeneration` may optionally pin models at plan time.
7. **Stamp what ran.** **Decided 2026-10-12:** the caption stamp is **per row**, as `DraftCaption.model` plus `Draft.headlineModel`. 012 regenerates each channel and the headline separately, so one per-draft stamp would go wrong. `Draft.designModel` and `DraftRevision.model` sit beside `promptVersion`. Output can then be compared by model, and proposal **006**'s traces can read the field instead of re-deriving it.
8. **Timeouts scale with the model.** A per-model design timeout, e.g. Opus ~600s against today's 300s, **kept strictly under the 15-minute stale sweeps**, or those sweeps become model-aware. A generation must never be marked FAILED by the sweep while its model call is still legitimately running.

## Scope

### In Scope

- Model catalogue + `resolveModel` + migrating every call site in the table above onto it (including `voiceDraft.ts`)
- Upgrading pinned IDs to the current family
- `TeamModelPolicy` (defaults per surface + allow-list) and per-user remembered choice — schema + migration
- Pickers: brief wizard, refine, assistant chat headers; `/team` admin section
- `Brief` carries the chosen caption/design model so async generation, retry and regenerate reuse it
- `Draft` / `DraftRevision` model stamps
- Per-model timeouts reconciled with the 15-minute generation and `pendingAction` sweeps
- `CLAUDE_CLI_MODEL` demoted from override to fallback
- Unit tests for the pure resolver (precedence + allow-list); E2E: disallowed model → 400, stamp recorded, remembered choice restored

### Out of Scope

- Choosing the **provider or credential route** for captions (OAuth CLI vs a registered API key). That is proposal **005** item 2. This proposal picks **which Claude model** runs on whichever route 005 selects; the two compose and must not duplicate UI.
- Non-Claude text models (OpenAI, Gemini) for captions or design
- Image-model selection (gpt-image vs Gemini is **005** item 4)
- Per-user spend caps or budgets; cost visibility belongs to **006**
- Letting users pick the model for internal steps (background decision, token ping)

## Impact

- **Files affected:** ~25–35 (estimated) — `agent/config.ts`, `claudeCli.ts`, every call site in the table, copy providers, `/team` + wizard + refine + chat UI, schema + one migration, tests
- **Complexity:** medium
- **Risk:** medium. Model resolution sits on every generation's critical path. A wrong precedence or an unvalidated request could route every call to Opus, with a cost and limit impact. Mitigated by the pure, unit-tested resolver, server-side allow-list validation, and stamping so a bad routing is visible per draft.

## Decisions

- **Choice location — decided 2026-09-23:** per post / per chat, remembered per user, with team defaults.
- **Opus availability — decided 2026-09-23:** allowed for everyone by default; admins may remove it.
- **Catalogue — decided 2026-10-12:** Haiku 4.5, Sonnet 5.5 and Opus 5.5. Fable 5.1 is not offered for now.
- **Cost label — decided 2026-10-12:** relative tiers (`$ / $$ / $$$`) plus a speed hint. They are derived from current published pricing at design time, not from memory.
- **Template fill (`design.template`, Path A) — decided 2026-10-12:** offers Haiku and Sonnet only. Freeform design, refine and the assistants offer all three models.
- **Caption stamp — decided 2026-10-12:** one stamp per `DraftCaption` row, plus one for the headline. This replaces the single `Draft.captionModel`.

- **Team-token warning — decided 2026-10-12:** in CLI mode, when Opus is picked and the run would use the **team** Claude token (no personal token connected), the picker shows a small non-blocking notice that the run uses the team's allowance.
- **Regenerate default — decided 2026-10-12:** the picker defaults to the draft's **stamped** model, so a regenerate is like for like unless the user changes it.

### Panel rulings (user, 2026-10-12)

These answer the deep panel's verdict, CHANGES_REQUESTED (`party-report.md`). They override the Proposed Solution text above where the two conflict.

- **Two waves, both in 008.**
  - **Wave 1**, independently shippable: the catalogue, `resolveModel`, current IDs in both modes, team defaults at `/team`, the stamps, the timeout/sweep reconciliation, and `voiceDraft.ts` plus the internal steps on the catalogue.
  - **Wave 2:** the pickers (brief wizard, refine, regenerate, assistant chat headers) and the team-token notice.
- **No per-user remembered choice.** There is no per-user table and no resolver tier for it. New posts and chats pre-select the team default; regenerate pre-selects the draft's stamped model.
- **No `ScheduledGeneration` model pin.** Scheduled, MCP and ACP runs use the team default at run time.
- **Team-token protection:** a single `/team` switch, "Opus requires a personal token". Scheduled runs also classify usage-limit failures explicitly in `errorReason`. The 2026-10-12 notice stays. There is no per-credential allow-list.

### Panel resolutions (orchestrator, 2026-10-12)

These are technical answers to the panel's BLOCK and WARN findings. Each has one sensible answer, and planning carries them into `spec.md`.

- **A closed catalogue.** Model choices are stored only as catalogue **keys**, a closed enum validated at every write boundary. Full API IDs live only in the "what ran" stamps. The resolver returns a catalogue entry, and the spawn/SDK site passes only `entry.apiId`.
- **The allow-list is checked at every tier, at call time.**
  - A stored value (team default or stamp) that is no longer allowed, or no longer in the catalogue, falls through to the team default, then to the system default. The substitution is recorded on the stamp and logged on non-interactive runs.
  - Only an explicit request returns 400.
  - `/team` rejects a policy that leaves any surface with no allowed model.
- **One owner for regenerate.** The draft's stamps are the server-side default for regenerate. "Regenerate all" with mixed row stamps uses the team default, and a null stamp falls through to the team default. `Brief`'s model fields mean "the initial request" only.
- **The regenerate pickers and a `model` body field** on `regenerate-copy` (all three forms) and `regenerate-design` are in wave 2.
- **Timeouts are bounded per action, not per call.** Each action's worst-case chain (generation; refine + verify + retry) is computed from the catalogue and must stay under both 15-minute sweeps, enforced by a unit test. Per-model timeouts are measured placeholders until a real Opus 5.5 run measures them.
- **`resolveModel` replaces `modelFor` and `modelForBackground`.** `claudeCli.ts` stops reading `CLAUDE_CLI_MODEL`. When set, the variable must be a catalogue key or ID (otherwise it is a boot error), and it acts as the system default. A boot log notes the changed meaning.
- **Internal steps get fixed, non-selectable catalogue surfaces:** the background decision, the refine verifier and the token ping. A guard test fails on any model literal outside `config.ts`.
- **Each catalogue entry carries numeric per-MTok prices, with a dated source.** The `$ / $$ / $$$` tier is computed from them.
- **A boundary seam records the model argument** at the CLI spawn and the SDK call. Tests assert on it for every surface.
- **The full-ID behaviour of the pinned CLI (2.1.287) is verified** in planning or build, before it is relied on.
