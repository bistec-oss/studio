## Decisions

- **AC-27 asserts the exact message,** not just the code, on all 9 requests. A wrong refusal (e.g. the template-fill rule firing instead of the allow-list) would fail it, which answers the wave-1 review's NOTE 1 for this AC.
- **The wizard cases walk the real UI** rather than posting to `/api/briefs`: AC-28 is about what the Review step sends, and only a walk proves the untouched pickers omit both fields.
- **The resume uses the wizard's own autosave,** not a seeded `PUT`. The case waits for the autosave response whose payload carries `designModel: 'OPUS'` (and, the second time, `designMode: 'GENERATE'`), so it doesn't depend on the 1.5 s debounce timing.
- **The draft-page case seeds one Sonnet stamp on LinkedIn.** With the generated stamps (all Haiku), the LinkedIn pre-selection would equal the system default, and the case could not tell the stamp tier from the default. The seed also makes "Regenerate all" see mixed stamps, so its "Default" hint is asserted.
- **"Generated with" is scoped to its panel** through the picker's nearest ancestor `div` holding an `h3`, and counted page-wide on `<p>` only. The Versions cells put the same sentence on a `<span>` (title and sr-only text), so a page-wide text match would double-count.
- **The brand-kit chat is driven through its drawer too** (AC-30 names only the briefing one). FR-21 puts a picker in both headers, and the extra turn costs about a second.
- **TC-MODEL-20 fakes `/api/me` as well as `/api/models`,** as AC-31 states, although only `/api/models` feeds the picker. With `cliMode: true`, the shell behaves as in CLI mode too.
