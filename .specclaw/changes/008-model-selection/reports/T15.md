## Summary

- **`src/lib/brief/modelPicks.ts` (new)** is pure and client-safe. It imports the catalogue, the resolver, `pickerState` and `requests.ts` only, and adds no rule of its own.
  - **`designSurface(mode)` / `designPath(mode)`:** `TEMPLATE` → `DESIGN_TEMPLATE` / `'A'`, `GENERATE` → `DESIGN_FREEFORM` / `'B'`. This is the same mapping as `POST /api/briefs`.
  - **`designPickForPath(pick, mode)`** applies FR-19's reset. A pick the new path can't run (Opus → template fill) becomes `undefined`. The note is the resolver's own refusal text, "Opus 5.5 isn't available for template fill", which `decideModel` produces with every model allowed and no gate. An eligible pick, or no pick, is kept with no note. Only eligibility depends on the path, so a pick the policy refuses is left to the picker's own stale-pick reset (T14 NOTE 1).
  - **`reviewModelName(surface, models, context, pick)`** gives the Review summary row: the pick while it is offered, otherwise the pre-selection the server will run. It is null when the picker is hidden.
  - **`refusedModelField(field)`** decides which picker a `400 MODEL_NOT_ALLOWED` belongs to. It reads the body's own `field` (review NOTE 1), returning `'captionModel'` or `'designModel'`, or null when the field is absent or unknown.
- **`src/lib/apiFetch.ts` (departure, additive):** failures now throw `ApiError extends Error`, which carries `status` and the body's `code` and `field` (each null when the body has none). `e.message` and `instanceof Error` are unchanged for every existing caller. `apiFetch` used to drop the `code`, which the wizard needs to tell a `MODEL_NOT_ALLOWED` apart. T16's regenerate and refine controls can use the same `e.code` check.
- **`useBriefWizard.ts`:**
  - **New state:** `captionModel`, `designModel` (`ModelKey | undefined`, where undefined means untouched, A5), `designModelNote`, and `modelErrors` (`{ captionModel?, designModel? }`).
  - **`setCaptionModel` / `setDesignModel`** (`useCallback`) also clear that picker's refusal; the design setter also clears the path note. The picker's own stale-pick reset goes through the same setters.
  - **`setDesignMode`** is now a wrapper; its type changed from a `Dispatch` to `(mode) => void`, which `SizeDesignStep` already declares. On a real change it applies `designPickForPath` and sets the note when one is returned. Re-clicking the current path does nothing.
  - **Autosave:** the payload gains `captionModel` and `designModel`, and both join the debounce deps. An undefined pick is dropped by `JSON.stringify`, so an untouched wizard's payload is byte-identical to before.
  - **Resume:** rehydrates both picks through the raw state setters. `designMode` is also restored through its raw setter, so the reset does not fire against a half-restored state.
  - **Submit:** `captionModel` and `designModel` go into the `POST /api/briefs` body. Undefined is omitted by `JSON.stringify`, the same mechanism as the body's `campaignId: … || undefined`. `modelErrors` is cleared at the start of each submit. On failure, an `ApiError` with code `MODEL_NOT_ALLOWED` and a known `field` sets that picker's error. Anything else, including an unplaceable refusal, goes to the existing step error `Notice` as before.
- **`ReviewStep.tsx`:**
  - **Two `ModelPicker`s** sit in a `grid gap-4 sm:grid-cols-2` under the summary `<dl>`:
    - `id="brief-caption-model"`, label "Caption model", `surface="CAPTION"`;
    - `id="brief-design-model"`, label "Design model", `surface={designSurface(designMode)}`, `context={{ designPath }}`, `note={designModelNote}`.
    - Each gets its `error` from `modelErrors` and is `disabled` while submitting.
  - **Two summary rows,** "Caption model" and "Design model", follow "Template". Each shows `reviewModelName`, and is left out while `/api/models` loads or when the picker is hidden.
- **`src/app/(app)/brief/page.tsx`** passes the six new props through.
- **`types.ts` and `ReviewRow.tsx` are unchanged.** `ReviewRowProps` already fits, and `DesignMode` is reused. The lib module declares its own `BriefDesignMode`, so `lib/` doesn't import from `components/`.

## Decisions

- **The reset happens in `setDesignMode`, not in an effect.** The path changes on step 1, while the picker only mounts on Review. Waiting for the picker's own stale reset would leave the stale pick in the autosave until the user reached Review, and would show no note. An effect would also add a `set-state-in-effect` lint warning.
- **The note is the resolver's own refusal message** (`decideModel` with `requested`), so it can't drift from the server's "…isn't available for template fill" text.
- **Field attribution comes from the server** (review NOTE 1). `POST /api/briefs` sets `field` at every refusal site. A body without `field` (every other route, or an older server) falls back to the step's error `Notice`, so a refusal is never silently dropped. The first version inferred the field from the route's order plus the model name in the message; that string matching is gone.
- **No `/api/models` invalidation after a refusal.** Refetching would let the picker's stale reset clear the error the user hasn't read yet. The next 60 s refetch (`staleTime`) or a focus refetch still updates the view.
- **The caption picker uses the view's `captionProviderIsClaude`** (the team's default provider). The wizard's `pickDefault` sends the same provider whenever one is flagged default. If they ever disagree, the server's 400 lands on the caption picker.
