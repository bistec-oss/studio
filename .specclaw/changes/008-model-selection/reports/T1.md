# T1 — The catalogue and the pure resolver

**Status:** done, not committed (the orchestrator commits after review). No real model call was made.

## What was built

- **`src/lib/models/catalogue.ts`** (new). It is pure and has **no imports**.
  - `MODEL_KEYS`, `USER_SURFACES` and `INTERNAL_SURFACES` are `as const` arrays, ready for zod enums. `ModelKey`, `UserSurface`, `InternalSurface` and `Surface` are derived from them.
  - `CATALOGUE` is exactly spec FR-01's table, ordered cheapest first. Its IDs, `previousApiIds`, prices, speed, gating and the 16000 floor all match. `cliArg = apiId` everywhere, and the timeouts are design §5's table.
  - `SYSTEM_DEFAULTS`, `REFINE_PATH_A_SYSTEM_DEFAULT` and `tableDefault(surface, designPath?)` implement FR-04's table and A8.
  - `SURFACE_LABELS` holds the FR-14 plain names plus an in-sentence phrase.
  - Helpers: `familyName`, `isModelKey`, `isUserSurface`, `entryFor`, `isEligible`.
  - `modelTier()` uses FR-01's formula.
  - `entryForStamp()` returns `{ entry, previous }` or null, by exact match.
  - `catalogueProblems(catalogue)` checks the invariants.
  - The header comment holds design §2's add-a-model procedure, the family-upgrade note and FR-02's surface-split procedure.
- **`src/lib/models/resolve.ts`** (new). It is pure and imports the catalogue only.
  - `effectiveSet()`, `systemDefaultFor()` and `decideModel()` implement the five tiers. Tier 1 refuses with `UNKNOWN_MODEL`, `NOT_ELIGIBLE`, `NOT_ALLOWED` or `NEEDS_PERSONAL_TOKEN`, using FR-17's messages. Tiers 2–4 fall through, and `substitutedFrom` keeps the first refused value. A `previousApiIds` stamp counts as a substitution. An empty set gives `NO_ALLOWED_MODEL`.
  - `ResolvedModel` carries `arg` (apiId or cliArg, by mode) and `timeoutMs`.
  - `internalModel(surface, mode)` returns the single eligible entry, Haiku, with source `system`, and never reads a policy.
  - `regenerateStampTier(targets, { captions, headlineModel })` implements FR-09.
- **`src/lib/models/policyRules.ts`** (new). It is pure.
  - `DEFAULT_POLICY` and `defaultPolicy(catalogue)` give the A2 no-row reading.
  - `validatePolicy(input)` applies FR-05 rules 1–4 (first failure wins) and returns the normalized `ModelPolicy`: allowed in catalogue order and deduplicated, null defaults dropped.

None of the three modules does I/O or reads a clock, the environment or Prisma. A grep shows that `resolve.ts` and `policyRules.ts` contain no model ID and no quoted bare family or key name, so T10's literal guard will pass them.

## Departures and assumptions

1. **`regenerateStampTier` takes the parsed targets, not the raw body.** Its input is `parseRegenerateBody`'s `CaptionTarget[]` (`['HEADLINE']`, `[channel]` or every channel), which is what the route holds after parsing.
   - One rule covers all three forms: the common non-null stamp across the target rows. A single channel trivially gives that row's stamp.
   - A missing row, or an empty target list, gives null.
   - It is generic over the channel type, so the module needs no Prisma import.
2. **The `envDefault` meaning on an ineligible surface.** `CLAUDE_CLI_MODEL=opus` on `DESIGN_TEMPLATE` is treated as _not applicable_: the surface keeps its table default, and **no substitution is recorded**. This follows FR-04's wording ("OPUS leaves DESIGN_TEMPLATE on its table default").
   - An env model that is eligible but excluded by the team (not allowed, or gated) **is** a skip. It records `substitutedFrom`, then goes to the fallback.
   - The system tier is a single value: env if it applies, otherwise the table default. A refused env model does not retry the table default. This matches FR-03's "tier 4 → fall through" literally.
3. **REFINE with no `designPath`** reads as Path B (Sonnet). This matches today's `designMode === 'TEMPLATE' ? haiku : sonnet`.
4. **Invariants added to `catalogueProblems` beyond FR-01's five**, because the resolver relies on them:
   - a `cliArg` that equals another family's ID;
   - a `priceSource` without a date (AC-01(d));
   - an invalid timeout;
   - an internal surface that is not Haiku alone (A14);
   - an entry order that is not cheapest first (the fallback tier takes `set[0]`).
5. **`SURFACE_LABELS.phrase` wording** is my own choice: "caption writing", "template fill", "freeform design", "refine", "the campaign briefing assistant", "the brand-kit assistant".
   - These give "Template fill needs Haiku or Sonnet allowed" and "Opus 5.5 isn't available for template fill", both exact.
   - Rule 3 names _families_ ("Haiku", not "Haiku 4.5"), per the FR-05 example. `familyName(key)` derives them from the key.
   - Other rule messages: "Allow at least one model"; `Unknown model "<v>"`; `Unknown surface "<v>"`; `The <surface name> default, <displayName>, isn't in the allowed models`; and `No model is allowed for <phrase> on this team. A team admin can allow one at /team → Models.` T4 and T16 may reword them.
6. **The `UNKNOWN_MODEL` message** from `decideModel` is `Unknown model "<v>"`. Per FR-17, the route answers that case with zod's message before the resolver is reached.
7. **Where the pure validation tests live.** They are in `modelResolve.test.ts`, because the task's file list has no policy test file; `modelPolicy.test.ts` is T4's. T4 may move them.
8. **An optional trailing `catalogue` parameter** on `decideModel`, `effectiveSet`, `internalModel`, `modelTier`, `entryForStamp` and `defaultPolicy`/`validatePolicy`, so planted catalogues can be tested. Callers omit it.

## Fix round 1 (after reviews/T1.md)

1. **The system tier is now two steps** (orchestrator ruling on the open question).
   - Tier 4 first tries an _applicable_ `CLAUDE_CLI_MODEL`: CLI mode, and only where the model is eligible for the surface. Then it tries the surface's `tableDefault(surface, designPath)`. Both carry source `system`.
   - An env model that is eligible but refused is recorded as `substitutedFrom`, unless an earlier tier already set it.
   - An env model equal to the table default is tried once.
   - An env model that isn't eligible for the surface is still "not applicable": the surface keeps its table default, and no substitution is recorded.
   - Example: `envDefault: 'OPUS'` on a team without Opus → `DESIGN_FREEFORM` is Sonnet, source `system`, `substitutedFrom: 'OPUS'`.
2. **`systemDefaultFor` is no longer exported.** Its logic is now the private `applicableEnvDefault` plus the inline tier-4 loop in `decideModel`. Wave 2's pre-selection calls `decideModel` without `requested`, so it can't diverge from the server.
3. **`defaultPolicy()` is dropped.** Only `DEFAULT_POLICY` remains, as T4's no-row default. Its test now checks it against the catalogue's `defaultAllowed` entries.
4. **Tests.**
   - The AC-03 oracle uses the same two-step system tier.
   - New explicit cases:
     - an Opus env with no Opus on the team → Sonnet / system / `'OPUS'`;
     - the gated variant (switch on, team credential, CLI);
     - env refused and the table default refused → Haiku / fallback / `'OPUS'`;
     - an env model equal to the table default is tried once.
   - The `defaultPolicy(c)` test is replaced.
   - `modelResolve.test.ts` now has 38 tests (was 35). The unit total is **2099**.
5. **Falsifiability.** With tier 4 put back to the single-step version, AC-03's exhaustive test and the new env-refused case both go red. Restoring the two-step version makes them green again.
