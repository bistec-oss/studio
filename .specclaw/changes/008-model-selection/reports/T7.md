## Decisions

- **A failed caption field writes no stamp field; it does not write null.** That covers both failure shapes:
  - with text kept (READY + "Regenerate failed"), the stamp must stay with the text (FR-08, A7);
  - with no text (FAILED), leaving the column alone is also what keeps "the stale sweep / onError / unstarted settle never touch stamps" true.
  - **Edge:** a row whose text a user cleared by hand (A6 keeps its stamp) and whose regenerate then fails becomes FAILED with no text but keeps that stamp. It is rare, and it matches "left unchanged by" more closely than nulling would. Generation and retry still write null on a FAILED row (T6's `captionRowsFromFields`).
- **regenerate-copy now loads the rows before resolving.** The rows carry the stamps the tier needs, and materializing a legacy draft is idempotent, so doing it before a possible 422 is harmless; it is the same write any GET makes. Resolution still precedes the claim.
- **refine's resolution failure** uses regenerate-design's 422 `{ code, message }` with the resolver's code, not regenerate-copy's `COPY_ERROR`. Both design-side actions now answer alike.
- **`commitDraftRevision`'s `model` is optional.** Omitted means "unknown", the 004 rule, so the many existing test call sites and the adopt path need no meaningless value. Every `src/` caller that commits fresh HTML now passes one: refine, Override, both inline-edit modes.
- **Override and a pre-008 conflict:** "no model recorded" is detected as `pending.model === undefined`, the key being absent. A conflict that recorded `null` keeps `null` rather than borrowing the draft's.
- **The verifier client keeps `timeout: model.timeoutMs`** as well as `createMessage`'s abort signal. That is belt and braces; both are 60 s.
