## Summary

- **`BriefingAssistantPanel.tsx`** and **`BrandKitAssistantPanel.tsx`** each get a `ModelPicker` as the first block of the drawer body, directly under the drawer's title bar (the chat header):

  | Panel     | `id`                       | `surface`            | Label (accessible name)     |
  | --------- | -------------------------- | -------------------- | --------------------------- |
  | Briefing  | `briefing-assistant-model` | `ASSISTANT_BRIEFING` | "Briefing assistant model"  |
  | Brand kit | `brandkit-assistant-model` | `ASSISTANT_BRANDKIT` | "Brand kit assistant model" |
  - No `context`: the assistants have no stamp and no design path, so the pre-selection is the team default, else the system default (Sonnet 5.5), through `decideModel` (FR-18, FR-21).
  - `disabled={pending}`, like the Send button beside the prompt.
  - The strip's border and padding (`flex-shrink-0 border-b border-line-subtle px-5 py-4`) are passed as `ModelPicker`'s `className`, so they sit on the picker's own wrapper. While `/api/models` loads, or when the picker is hidden, nothing renders, not even an empty padded strip.

- **The pick is client state for the open chat** (`useState<ModelKey | undefined>`, beside the transcript). Nothing is stored or remembered, and a reload resets it. Closing and reopening the drawer keeps it for as long as the page keeps the transcript, because both live in the same component.
- **The send rule (A5):** the chat body is `{ messages, model }`. `model` is undefined until the user picks something other than the pre-selection, and `JSON.stringify` drops it then, so an untouched picker sends today's body byte for byte. Once a different model is picked, every turn sends it until the user changes it back or reloads (AC-30's second turn).
- **A refused pick** (`ApiError` with `code === 'MODEL_NOT_ALLOWED'`, the chat routes' FR-17 400, sent before anything runs) sets the picker's `error`, which `Select` shows as the field error with `aria-invalid` and `aria-describedby` (T14). It does not toast. Any other failure still toasts. In both cases the turn rolls back as it did before: the transcript returns to its previous state and **the typed message goes back into the input**, so nothing is lost.
  - The error clears when the user changes the pick (`pickModel`) and at the start of each send.
- **FR-22's team-token notice** is `ModelPicker`'s own `Notice tone="warning" role="status"`. Nothing is duplicated in the panels.
- **Out of scope by the spec (A7, FR-17):** the briefing editor's "Enhance with AI", the brand-voice draft and image → template get no picker and send no `model`. T13 added no `model` field to those routes. The only calls in these two panels that accept `model` are the two chat POSTs.

## E2E risks (not edited — for T18)

- **`surfaces.test.ts:829-850`** (AC-12 + FR-12, the briefing assistant at 375 × 812 with a reply and a schedule plan) and **`surfaces.test.ts:967-985`** (the brand-kit assistant at 375 px with a proposal). Both run `expectNoHorizontalScroll` with the drawer open. The picker strip adds about 90 px of height above the documents block, which shrinks the `flex-1` Conversation region. The select is full width inside the `max-w-md` drawer, and its option text is short. Low risk for horizontal scroll; the cases to watch.
- **`a11y.test.ts:968-992`** (AC-16: both drawers hold a focusable "Conversation" region with no turns). `expectStaticRegion` checks that region only. The picker isn't a scroll region and adds no `overflow` class. Low risk.
- **`a11y.test.ts:468-474` and `:640-669`** (rows 17, 18 and 19: the drawers' "Message" input). They use `getByLabel('Message', { exact: true })` and `expectLabelled(drawer, 'Message', …)`. The new labels, "Briefing assistant model" and "Brand kit assistant model", don't equal "Message". No collision.
- **`surfaces.test.ts:788`** (`page.getByRole('combobox')).toHaveCount(2)` on the campaign page) and **`:759`** (project page): both run with the drawer closed, and a closed Radix drawer is unmounted, so the picker isn't counted. **`surfaces.test.ts:951-954`** scopes `getByRole('combobox')` to the kit panel region; the drawer is portalled outside it.
- **Focus:** the drawer's first tabbable is still the title bar's "Close" button, which Radix focuses on open. The picker is the next stop, before "Add document". No suite tabs through the drawers.
- **No axe scan runs with a drawer open** (`a11y.test.ts:1088+` scans `/campaigns/[id]` with the drawer closed).
- **Request bodies:** `campaign-scheduling.test.ts:391`, `briefing-assistant.test.ts`, `brandkit-assistant.test.ts` and `model-selection.test.ts:536-616` call the chat routes over the API, not through the panels, so the client body change can't reach them. An untouched panel's body is unchanged anyway.
- **`getByRole('status')`:** no drawer case queries it. The team-token notice appears only in CLI mode with a team credential, which mock API mode never is.
- **Policy state:** `model-selection.test.ts` restores the team policy in `afterEach`. A UI case that leaves `ASSISTANT_BRIEFING` set to `HAIKU` would make AC-30's pick a no-op (see the AC-30 row above).

## Decisions

- **The picker sits at the top of the drawer body, not inside the drawer's title bar.** The title bar belongs to `Drawer` (`src/components/ui/Modal.tsx`), which is outside T17's file list and has no header slot. The first strip under it reads as the chat header and keeps the change to the two panels.
- **Labels "Briefing assistant model" and "Brand kit assistant model".** FR-21 names no label. FR-18 asks for a surface-specific suffix where pickers share a screen; each drawer holds one picker, but distinct names keep E2E selectors and screen-reader announcements unambiguous. (`/team` → Models names the rows "Campaign briefing assistant" and "Brand-kit assistant"; the picker labels are shorter, and no screen shows both.)
- **No pure helper fell out.** The body is `JSON.stringify({ messages, model })`, the same mechanism T15 and T16 use, and the refusal check is the one-line `ApiError` test T16 inlines. Unit coverage for the rules (pre-selection, send rule, notice, gated state, stale reset) is T14's `modelPicker` and `uiPrimitives` suites.
- **The refusal clears at the start of each send and on any pick change,** like T15 and T16. No `/api/models` invalidation after a refusal (T15's reason: a refetch could reset the pick and clear the error before it is read).
- **The message input stays enabled while a turn is pending,** as before. Only the Send button and the picker are disabled.
