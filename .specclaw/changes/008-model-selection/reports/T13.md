## Summary

- **`src/lib/models/requests.ts` (new)** is pure and client-safe (zod and the catalogue only). It exports:
  - `modelKeySchema = z.enum(MODEL_KEYS)`. It is closed and case-sensitive, with the message `model must be HAIKU, SONNET or OPUS`.
  - `modelError(failure)` → `{ error: failure.message, code: 'MODEL_NOT_ALLOWED' }`, which routes send with status 400. The messages are `decideModel`'s own (`resolve.ts` `refuseRequest`), and they already match FR-17 word for word:
    - "Opus 5.5 isn't allowed on this team";
    - "Opus 5.5 isn't available for template fill";
    - "Your team requires a personal Claude token for Opus 5.5 — connect one in Settings".
  - `parseModelField(value, field)`:
    - absent → no pick;
    - a key → that key;
    - anything else, `null` included → the 400 body, with the field named (for example `captionModel must be HAIKU, SONNET or OPUS`).
  - `parseRegenerateDesignBody(raw)` → `{}` or `{ model }`, strict.
- **The route order everywhere is parse → resolve → claim.**
  - The pick goes to `resolveModel` as `requested` (tier 1, above the stamp).
  - An `ok: false` **with a pick** returns `400 modelError(...)` before the claim.
  - **Without a pick, the wave-1 answer is unchanged:**
    - refine, regenerate-design and both chats return 422 `{ code, message }`;
    - regenerate-copy returns 422 `COPY_ERROR`.
  - With a pick, `decideModel` fails only at tier 1, so "a pick was sent" and "the failure is a refusal" are the same condition.
- **The routes:**
  - **`regenerate-copy`:** `parseRegenerateBody` returns `{ targets, model? }`. All three forms take `model`, and the schema stays `.strict()`. `{ channel, headline: true, model }` is still a 400 (`REGENERATE_BOTH_MESSAGE`), and so is an unknown extra key. A bad `model` value carries `code: 'MODEL_NOT_ALLOWED'`; other shape errors keep `{ error }`. The 400 on resolution is inside the existing pre-claim `try`, before `claimCaptionAction`.
  - **`regenerate-design`:** the route now reads its body. An absent or empty body is `{}` and stays valid; malformed JSON → 400 `Invalid JSON body`; any key other than `model` → 400 `Send {} or { model }`.
  - **`refine`:** `model` sits beside `instruction`. A malformed value is a 400 on either path. The Override path ignores a valid pick and resolves nothing, so it makes no model call (FR-17 table).
  - **The two chats:** `chatSchema` gains `model: z.unknown().optional()`, which `parseModelField` checks. `runBriefingChat` / `runBrandKitChat` and `resolveAssistantModel` gain an optional `requested?: ModelKey` (last parameter). The routes map `AssistantModelError` to a 400 when a pick was sent, and to the existing 422 otherwise.
  - **`POST /api/briefs`:**
    - `captionModel` / `designModel` are shape-checked with the other field validation.
    - Just before `brief.create`, each pick present is resolved against the caller's effective set: `CAPTION`, and `DESIGN_TEMPLATE` or `DESIGN_FREEFORM` by `designMode`. A refusal is a 400 and nothing is written.
    - Both are written as `?? null`. With no pick, nothing is resolved at brief time (FR-10: null means "no explicit request").
  - **`briefDraftPayload.ts`:** `captionModel: modelKeySchema.optional()` and `designModel: modelKeySchema.optional()`. A resumed brief restores the picks, and a payload saved before 008 (or with untouched pickers) still parses.
- **Unchanged:** MCP, ACP, the scheduler, the two Enhance routes, image → template and the voice draft. None of them pass `requested` (A7, FR-11).

## Spec open question 1: a caption pick needs a Claude caption provider

This is the approved default. It is a plan gap that no task owns, and FR-18 relies on it (the CAPTION picker is hidden "when the COPY provider isn't Claude").

- **`copyProviderIsClaude(teamId, providerKey?)`** is new in `src/providers/registry.ts`. It uses **the same lookup the caption run uses**:
  - `resolveCopyProvider`'s two row queries are extracted into `findCopyProviderRecord`: the brief's `providerKey` (team-scoped, enabled), else the team's enabled default. `resolveCopyProvider` now calls the extracted function, with the same queries in the same order (`copyProviderCliMode.test.ts` is unchanged and still passes, 5/5).
  - A row decides by its `providerName`, through `COPY_PROVIDER_FAMILY` (`cli` and `anthropic` → Claude; `openai` → other). The table sits beside `instantiateCopyProvider`, which it must stay in step with.
  - **No row → Claude:** CLI mode runs `claude -p`, and API mode falls back to `ANTHROPIC_API_KEY`. With no provider at all, the run fails on its own, which is the right error.
  - **An unknown `providerName` is not treated as "not Claude".** It can't run at all (`instantiateCopyProvider` throws "Unsupported provider"), and the E2E registers placeholder names (`provA`, `copyB`, …) as team defaults under `MOCK_AI`. Refusing them would make the shared test team's caption picker vanish.
  - **`MOCK_AI` is deliberately not consulted.** The mock provider stands in for whichever provider the team really has.
- **`src/lib/models/requests.ts`:** `CAPTION_PROVIDER_NOT_CLAUDE_MESSAGE` ("This team's caption provider is not Claude, so the caption model can't be chosen") and `captionProviderNotClaudeError()` → `{ error, code: 'MODEL_NOT_ALLOWED' }`.
- **`regenerate-copy`:** with a `model`, it checks `copyProviderIsClaude(draft.brief.teamId, draft.brief.copyProviderKey)`. The check sits in the pre-claim block, before the resolution, and a miss returns the 400.
- **`POST /api/briefs`:** with a `captionModel`, it checks `copyProviderIsClaude(user.teamId, resolvedCopyKey)`. That is the key the brief stores and the generation will use: `'cli'` in CLI mode without a key, which matches no row and falls to the team default as at generation. The check runs before the resolution and before `brief.create`. A `designModel` alone is unaffected.
- **No pick → no check:** an OpenAI team's regenerates and briefs behave exactly as before.
- **The view (for T14/T16):** `ModelsView.captionProviderIsClaude: boolean` is additive (`src/lib/api-types.ts`). `loadModelsView` computes it for the team's **default** caption provider (`copyProviderIsClaude(teamId)`, no key), in parallel with the policy and credential queries.

## Decisions

- **Spec open question 1 is built,** per the coordinator's follow-up (it was first left out because FR-17's message list doesn't name it). See its section above. Three choices in it:
  - "is Claude" is decided from the registered row, not from the instance class: under `MOCK_AI` the instance is always the mock;
  - an unknown provider name counts as Claude;
  - the check runs **before** the model resolution, so an OpenAI team gets the provider message rather than a policy message.
- **`UNKNOWN_MODEL` 400s carry `code: 'MODEL_NOT_ALLOWED'` too.** FR-17 puts `UNKNOWN_MODEL` under the 400 `{ error, code }` shape, so every model-field rejection carries the code, and the T16 client can tell a refused pick from a bad shape. The message is the schema's enum message, naming the field.
- **`modelError` returns the body, not a `NextResponse`.** `requests.ts` stays client-safe, because `briefDraftPayload.ts`, which the wizard imports, reuses `modelKeySchema`. Routes send it with `{ status: 400 }`.
- **regenerate-design's body is strict** (`Send {} or { model }`), like regenerate-copy's. Every caller sends `{}` or no body: the draft page, and every E2E case (`agui-refinement`, `async-actions`, `background-notice`, `captions`, `rejected-revisions`). Strict rejects a typo such as `{ modle }`, which would otherwise be silently ignored.
- **refine validates `model` on the Override path too.** A malformed body is a malformed request on either path, and a valid pick is ignored there (no model call).
- **POST /api/briefs resolves each pick just before the write,** after the 404 checks. Its "claim" is the `Brief` row. A stored pick is never re-checked as tier 1 later: the generation reads it as `storedRequest`, which substitutes and never fails (FR-10, T6).
- **The brief-draft picks are strict enum values,** consistent with the payload's other enums. A drifted payload is swept, which is the module's documented rule.
