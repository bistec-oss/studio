## Departures (each small and deliberate)

1. **`setTimeout` + `AbortController` instead of `AbortSignal.timeout(ms)`.**
   - Node's `AbortSignal.timeout` runs on internal timers that `vi.useFakeTimers` cannot drive, and AC-13 requires a fake-timer abort with no wall clock.
   - The timer is cleared in `finally`. A test asserts `vi.getTimerCount() === 0` after a finished call.
2. **An abort at the deadline is rethrown as `Error("Claude API request timed out after <ms>ms", { cause })`.**
   - The SDK otherwise surfaces it as `APIUserAbortError` ("Request was aborted.").
   - The new wording mirrors the CLI's "Claude CLI timed out after…", so `humanizeGenerationError`'s existing timeout message still applies. Any error that is not an abort is rethrown unchanged.
3. **`isClaudeUsageLimit`: a structured status decides, as it does in `isClaudeAuthFailure`.**
   - When `apiErrorStatus` is set, only 429 counts. A 529 "Overloaded" result is not misread as a usage limit because of a phrase in its text.
   - With no status, the regex runs over `stderr`/`stdout`. Exit 0 → false, and an auth failure → false (checked first).
   - Design §8 lists the three true cases without saying which wins. This reading is the conservative one (A11).
4. **The extra helper `modelCallFor(model, mode, label)`.** Both boundaries use it, and T6's `MOCK_AI` branches will too. `recordModelCall` keeps the spec's object signature, with `at` set by the recorder.
5. **`modelCalls.ts` reads `process.env.MOCK_AI` directly** instead of importing `testHooks.ts`. T6 edits `testHooks.ts`, and its mock branches will record through this module, so the import would become a cycle. The definition is identical (`=== 'true'`).
