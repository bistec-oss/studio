## Summary

- **`src/lib/models/budget.ts` (new)** implements design §5.
  - **`STEP_BUDGETS`** holds only the fixed steps, each imported from its home:
    - `imageMs` = `IMAGE_GENERATION_TIMEOUT_MS`;
    - `renderMs` = `SET_CONTENT_TIMEOUT_MS` + `RENDER_ALLOWANCE_MS` (30 s);
    - `txMs` = `TX_MAX_WAIT_MS`;
    - the two API tool tails: image + render for design, image only for refine;
    - `postActionMs: 0`, per the design §5 decision;
    - `marginMs` = `MARGIN_MS` (60 s).
  - **The background decision and the verifier are not steps.** They are model terms, read from the catalogue that is passed in (`INTERNAL_BACKGROUND`, `INTERNAL_VERIFIER`). This settles the T7 review's interim note: no copied verifier literal exists anywhere.
  - **`actionSegments()`** lists every row of the §5 segments table. Each segment has an API term list and a CLI term list, and its limit (`STUCK_GENERATION_MS` or `GENERATION_LEASE_MS`) is imported from `recovery.ts` / `generationRunner.ts`.
  - **`segmentWorstCase()`** returns the worst case: the larger of the two modes, with each model term at the largest timeout of any eligible model.
  - **`actionBudgetViolations(catalogue, steps, segments = actionSegments())`** is pure. It returns each segment where `worst + margin > limit`, with its action, segment, mode, worst case, margin, limit and a message.
- **Exported constants:**
  - `SET_CONTENT_TIMEOUT_MS` (`puppeteer.ts`): export only.
  - `GENERATION_LEASE_MS` (`generationRunner.ts`): exported, and its comment is rewritten (the old "copy ≤120 + … + design ≤300" arithmetic was stale).
  - `IMAGE_GENERATION_TIMEOUT_MS = 120_000` (`providers/imageCapabilities.ts`, new).
- **The image timeout:**
  - The OpenAI image provider is now `new OpenAI({ apiKey, timeout: IMAGE_GENERATION_TIMEOUT_MS, maxRetries: 0 })`. It used the SDK default before: 10 minutes with 2 retries.
  - Gemini's local `TIMEOUT_MS = 120_000` is replaced by the shared constant.
- **The hooks** (design §5):
  - `runPathBDesign(…, model, opts?: { onBeforeDesign })` awaits the hook after the background step, immediately before the design-agent call.
  - `produceDesign(…, model, onBeforeDesign?)` passes it to Path B. For Path A, which has no background step, it awaits the hook right before `runPathADesign`.
  - `generateDraftForBrief(brief, actor, opts?: { templateId?, onBeforeDesign? })` passes it through.
  - `runGenerationForDraft` passes `() => touchGeneration(draftId)`.
  - **`touchGeneration(draftId)`** is new in `draftActions.ts`: `updateMany where { id, status: 'IN_PROGRESS' }` sets `updatedAt`.
  - **regenerate-design** passes `{ onBeforeDesign: () => touchDraftAction(draft.id, 'REGENERATE_DESIGN') }`.
  - **refine** calls `touchDraftAction(draft.id, 'REFINE')` in `commit`, before `commitDraftRevision`. It also does so in `reject`, before `recordRejectedRender` (see Decisions). The stale "300 s / 60 s" arithmetic comment now points at `budget.ts` and the budget test.
  - **The scheduler:**
    - `renewGenerationLease(id)` is `updateMany where { id, status: 'RUNNING' }` setting `nextRetryAt = now + GENERATION_LEASE_MS`;
    - it runs first in each entry's `try`, and again as the entry's `onBeforeDesign`.
- **The usage-limit prefix:** in the runner's catch, `isClaudeUsageLimit(err)` prepends `Claude usage limit reached on the team's credential — ` to the reason. The retry count, the backoff and the FAILED path are unchanged; a FAILED reason gets the prefix too.

## Decisions

- **Refine's attempt row is listed once per attempt:**
  - "attempt-1 touch → attempt-2 touch";
  - "attempt-2 touch → pre-commit touch".

  These are the same steps, but they are two real segments, so AC-09's "a planted REFINE of 800 s returns both refine attempt segments" holds literally. Each segment reports one worst case (the worse mode), not one violation per mode.

- **The pre-settle touch is in `reject` as well as `commit`.** `recordRejectedRender` also renders and runs a transaction. Without the touch, an API-mode not-applied refine at Opus would run 540 + 120 + 90 + 60 + 90 + 10 = 910 s between bumps, past the sweep even before the margin. The design's "pre-commit touch → settle" row now covers both settles.
- **Path A gets the pre-design hook too**, directly before `runPathADesign`. With no background step, "immediately before the design call" is the same point. This makes the generation's design segment cover both design surfaces from one write. The segment's model term is `[DESIGN_TEMPLATE, DESIGN_FREEFORM]`; regenerate-design's is `DESIGN_FREEFORM` only.
- **`runGenerationForDraft` builds its hook itself** (`() => touchGeneration(draftId)`) and takes no new parameter. No caller needs a different one (`backgroundGeneration` and retry both want this heartbeat), and AC-10 reads "runGenerationForDraft calls touchGeneration".
- **The scheduler's last segment is 830 s, not the table's "≈ 840".** It is design 600 + API tool tail 210 + the draft-create transaction 10 + post-action 0 + the completing write 10. The test pins 830 and its comment says so. A test also shows that exactly-at-limit passes: a post-action of 10 s gives 840 + 60 = 900, while 10.001 s fails.
- **The renewal runs inside the entry's `try`.** A DB failure on it lands in the normal retry path, like any other failure in the entry.
- **The prefix constant stays private** to `generationRunner.ts`. The tests assert the spec's literal sentence, so a typo in the constant fails them.
- **The interim states are left for T10:** `ResolvedModel | string` on the refine runners and `pinModel`.
