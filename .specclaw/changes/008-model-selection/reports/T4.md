# T4: the server resolver, the team policy store and the two APIs

**Status:** built, not committed (the orchestrator commits).
**Covers:** FR-03 (the I/O wrapper), FR-04 (the boot line), FR-05, FR-13. **ACs:** AC-04 (the boot-line half), AC-05 (the I/O half).

## What was built

- **`src/lib/models/policy.ts` (new, server-only).** The repo has no `server-only` package, so there is no import guard, only a header comment.
  - **`loadTeamPolicy(teamId)`** returns `{ allowed, defaults, gateOn, saved }`.
    - With no row it returns `DEFAULT_POLICY` and `saved: false`.
    - A stored `allowedModels` that is NULL or `[]` reads as `[]`, so the resolver fails closed with `NO_ALLOWED_MODEL`. This is tested.
    - Stored values outside the closed vocabularies are dropped. `allowed` comes back in catalogue order.
  - **`saveTeamPolicy(teamId, input)`** runs `validatePolicy` first. On a failure it returns `{ ok: false, message }` and writes nothing. Otherwise it runs one interactive `$transaction`: upsert the `TeamModelPolicy` row, `deleteMany` its defaults, then `createMany` the non-null defaults (skipped when there are none).
  - **`policyInfo(policy)`** builds the GET shape, with `defaults` covering every user surface (null for unset). `newModels` is non-empty only for a saved list (A2).
  - **`credentialTier(userId, mode = pipelineMode())`**:
    - API mode returns `'n/a'` with no query.
    - A null `userId` returns `'team'` with no query.
    - Otherwise it runs one `userClaudeToken.findFirst({ where: { userId, status: 'ACTIVE', user: { disabled: false } } })` and returns `personal` or `team`.
  - **`resolveModel(surface, { requested?, stamp?, userId, teamId, designPath? })`** loads the policy and the credential in parallel, then calls `decideModel`. `envDefault` is `env.CLAUDE_CLI_MODEL`, in CLI mode only. The `DecideResult` comes back unchanged.
    - **Substitution log:** each substitution logs `[models] <surface>: <JSON-quoted substitutedFrom, capped at 80> not available (<reason>) → <key> (<source>)`. It logs at `warn` when `userId` is null and at `info` otherwise.
    - **Reasons, most specific first:** `unknown model`, `not eligible for this surface`, `not allowed on this team`, `needs a personal token`, `retired ID of <displayName>`.
  - **The FR-04 boot line** uses a module-level once-flag and fires on the first `resolveModel` call:
    - CLI mode logs at `info`: `[models] CLAUDE_CLI_MODEL=<KEY> is the system default (below team defaults and explicit picks); it no longer overrides them`.
    - API mode logs at `warn`: `[models] CLAUDE_CLI_MODEL is set but ignored in API mode`.
    - When the variable is unset, nothing is logged.
  - **`loadModelsView({ userId, teamId })`** builds the `GET /api/models` payload, shared with later tasks.
- **`src/app/api/team/model-policy/route.ts` (new).** `GET` and `PUT` under `withTeamAdmin`.
  - The PUT body is strict zod: `allowed: z.array(z.enum(MODEL_KEYS)).max(3)`, `defaults: z.object({<each USER_SURFACE>: key.nullable().optional()}).strict()`, and `requirePersonalTokenForGated: z.boolean()`. The outer object is `.strict()` too, and all three fields are required.
  - A `validatePolicy` failure returns 400 `{ error: message }`. Success returns the GET shape.
- **`src/app/api/models/route.ts` (new).** `GET` under `withTeamAuth`.
- **`src/lib/api-types.ts`.** Adds `TeamModelPolicyInfo` and `ModelsView` in a new "Models (008)" section. These are type-only imports from `catalogue.ts` and `resolve.ts`, so they stay client-safe.

## Decisions and departures

- **The boot line prints the parsed key** (`CLAUDE_CLI_MODEL=OPUS`), not the raw env string. `env.CLAUDE_CLI_MODEL` is a `ModelKey` since T3, and the parsed value is safe to log.
- **The once-flag is set on the first call even when the variable is unset.** `env` is parsed once per process, so a later call can't see a different value.
- **`ModelsView.envDefault` is `null` in API mode.** The variable is ignored there (A4), and `decideModel` ignores it anyway, so the client and server agree either way.
- **PUT requires all three body fields.** The PUT replaces the whole policy, so a body that omits `defaults` would wipe them silently. `allowed` is capped at the catalogue size, so a duplicate-padded array is a 400.
- **`credentialTier` takes an optional `mode`.** `resolveModel` and `loadModelsView` read `pipelineMode()` once and pass it in, so one call never mixes modes.
- **Not moved:** T1's pure FR-05 validation tests stay in `modelResolve.test.ts`. The move was optional.
- **Failures (`ok: false`) are not logged here.** Callers decide between a 400 and failing closed, per the brief.

## Tests

- **`tests/unit/modelPolicy.test.ts` (new, 39 cases).** Prisma, `@/lib/env` and `@/lib/agent/config` are mocked, and so is the route wrapper. The mock wrapper's `parseBody` runs each route's real zod schema.
  - **`loadTeamPolicy`:**
    - with no row it reads as all three allowed, `{}` defaults, `gateOn` false and not saved (AC-05);
    - a stored row is read correctly;
    - a NULL or empty `allowedModels` reads as `[]`, which leads to `NO_ALLOWED_MODEL`;
    - unknown values are dropped.
  - **`saveTeamPolicy`:**
    - a validation failure surfaces as "Template fill needs Haiku or Sonnet allowed", and no transaction runs;
    - the exact upsert, `deleteMany` and `createMany` arguments are checked, with delete before create;
    - a null default writes no row;
    - a policy round-trips through save and then load.
  - **`policyInfo`:** the shape and `newModels`.
  - **`credentialTier`:**
    - an ACTIVE token returns `personal` in one query, and the where clause is asserted;
    - an INVALID token or a disabled user (no row) returns `team`;
    - a null `userId` returns `team` with no query;
    - API mode returns `'n/a'` with no query;
    - the default mode is used when none is passed.
  - **`resolveModel`:**
    - `arg` depends on the mode;
    - `envDefault` is used in CLI mode only;
    - the team default and the gate are read from the stored policy and the credential (the null-user scheduler is gated out of Opus);
    - an explicit refusal comes back unchanged;
    - REFINE on path A uses Haiku;
    - a substitution logs at `warn` for a null user and at `info` for a user;
    - a hostile stamp is JSON-quoted and capped, with no raw newline;
    - a retired-ID reason is logged;
    - nothing is logged when there is no substitution.
  - **`loadModelsView`:**
    - the catalogue entries carry exactly `key`, `displayName`, `tier`, `speed`, `surfaces` and `personalTokenGated`, with no `claude-` or price in the JSON;
    - Opus has no `DESIGN_TEMPLATE`, and internal surfaces are not listed;
    - API mode returns `'n/a'` with a null `envDefault`.
  - **Routes:**
    - GET returns the session team's policy;
    - PUT saves and returns the GET shape;
    - `allowed: ['OPUS']` returns 400 with the FR-05 message;
    - a default outside `allowed` returns 400;
    - an unknown key, an unknown surface, an unknown field (`teamId`), a missing field or a lowercase key each return 400 with nothing written;
    - GET `/api/models` returns the session user's view.
- **`tests/unit/envModel.test.ts`** gains three boot-line cases (AC-04), each on fresh modules with the real `env.ts`:
  - in CLI mode the line is logged once across two `resolveModel` calls;
  - in API mode a different line is logged at `warn`, also once;
  - when the variable is unset, no line is logged.
