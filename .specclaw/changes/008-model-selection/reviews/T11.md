## Findings

### NOTE 1 - `src/components/team/ModelsCard.tsx:~84` (cliMode source)

`cliMode` comes from `useCurrentUser()` and defaults to `false` while `/api/me` loads, so the switch can flash disabled with "Only applies in CLI mode." in a CLI deployment. `view.mode` from `/api/models` (already awaited before the form mounts) is the same fact and would avoid the flash and a third source of truth. Suggestion: `const cliMode = view.mode === 'cli'`.

### NOTE 2 - `src/lib/models/policyForm.ts` `systemDefaultName` (Refine label)

For REFINE the label is the Path B name only; a team on Haiku-only Path A drafts sees "Sonnet 5.5" as the system default though template drafts refine on Haiku. Declared in the report; a copy tweak could address it later.

### NOTE 3 - `tests/unit/modelPolicyForm.test.ts` (test quality)

Good: expectations come from the catalogue/server rules (`validatePolicy`, `decideModel` outputs), cases cover order, reset-only-the-named-default, env default CLI-only/eligible-only, null name, body shape, and the AC-22 400 message. Gaps, minor: nothing asserts a re-tick does not restore a cleared default (declared behaviour), and the component (checkbox names, disabled switch, inline 400) has no unit coverage, deferred to T12's E2E.

No BLOCK or WARN findings.
