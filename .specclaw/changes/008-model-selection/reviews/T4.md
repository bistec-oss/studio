## Focus points

1. Tenancy/authz: OK. `teamId` is only `user.teamId` from the session (withTeamAuth resolves it from a membership-validated cookie); the body schema is `.strict()`, so a `teamId` field is a 400. PUT is `withTeamAdmin` (403 for editors, super-admin passes). `/api/models` returns catalogue fields key/displayName/tier/speed/surfaces/personalTokenGated: no price, no apiId. Every Prisma read/write is keyed on the session teamId.
2. loadTeamPolicy: OK. No row gives the defaults; a NULL/empty array gives `[]` (fail closed); unknown values and surfaces are dropped; output is in catalogue order.
3. saveTeamPolicy: validation first, one interactive transaction, defaults replaced via deleteMany + createMany. Acceptable. Minor: two concurrent PUTs for the same team at READ COMMITTED can both pass deleteMany and the second createMany then hits the (teamId, surface) PK, so the loser gets a 500 instead of a clean last-writer-wins. Admin-only, rare, not data-corrupting. Optional: catch P2002 and retry once. [NOTE]
4. credentialTier vs resolveClaudeAuth: consistent. Both require status ACTIVE and `!user.disabled`; both treat null userId as team; `pipelineMode()` and `isCliMode()` derive from the same `env.DESIGN_PROVIDER`. findFirst on a unique userId is equivalent to findUnique. Residual divergence, by design: resolveClaudeAuth falls back to the team token _mid-run_ if the personal token is rejected (marks it INVALID, retries). A call the gate admitted as "personal" can then run Opus on the team token once. This cannot be fixed in T4 (it happens inside the CLI), but it is worth one line in the gate's doc or the T5 boundary notes. Named risk, not a block. A decrypt failure in resolveClaudeAuth would also throw where credentialTier doesn't; irrelevant to the gate.
5. Logging: substitution line JSON-quotes and caps at 80 chars (test asserts no raw newline); warn for null user, info otherwise. The boot line prints the parsed ModelKey, not raw env. Once-flag is per module instance and set on the first call even when unset, which is correct since env is parsed once.
6. Tests: meaningful. They assert exact Prisma args (where clause, delete-before-create ordering, no transaction on a validation failure), real zod schemas through a mock wrapper, the fail-closed read, the no-query paths, and the JSON for no `claude-` strings. The envModel boot-line tests use fresh modules plus a real env.ts parse, so they are falsifiable. The role gate (editor 403) is exercised only via the mocked wrapper, so it is not tested here; the real withTeamAdmin is covered by existing team-settings E2E, and a model-policy 403 case should be added at the E2E stage (T12).
