## Findings

### NOTE 1 - `src/components/ui/ModelPicker.tsx:58-60` (stale pick shows a different model than is sent)

`const shown = value && state.options.some(...) ? value : preselected`. If the policy changes under an open picker and the user's pick leaves the effective set, the select displays the pre-selection while `value` is still the stale key. The caller would send it and get a 400. The pre-selection hint is also suppressed, since `value !== undefined`. The comment says the caller resets, but nothing tells it to. Suggestion: an effect that calls `onChange(undefined)` when `value` is set and not in `state.options`, or state this duty explicitly in T15/T16/T17. Rare, since it needs a policy change mid-session.

### NOTE 2 - `ModelPicker.tsx:79-90` + `Select.tsx` (error not described)

Passing `aria-describedby` for the hint, together with Select's `error` paragraph (which has no id), means the error is not announced as a description. `aria-invalid` is not set either. This is Select's existing behaviour, so it is not a T14 regression, but the picker is where a refused pick is shown. Suggestion: give Select's error an id and include it in `describedby`, as a small follow-up on the primitive.

### NOTE 3 - `tests/unit/modelPicker.test.ts` (AC-26 oracle)

The 20 seeded combinations are compared against `decideModel` with the same inputs. That is what AC-26 literally asks, since the pre-selection must equal `decideModel`. It is still near-tautological for the rule itself. Rule correctness lives in modelResolve.test.ts, and the hint tests here cover each source. Two small gaps: the PRNG sample does not assert that every source tier (stamp/team/system/fallback) or the `!ok` hidden branch actually occurs, and the "20 distinct" check only guards duplicates. A cheap guard would be to assert the set of observed sources in SEEDED. It is deterministic, so it only needs checking once. Non-blocking.

### NOTE 4 - `pickerState.ts` `hintText` default branch

`'system'` and any unknown source fall to "Default". That is correct for the spec. `source: 'request'` is unreachable from the picker, since there is no `requested`.

No BLOCK or WARN findings.
