## Findings

### NOTE 1 - `tests/unit/modelLiteralGuard.test.ts:44` (comment-line skipping)

A line whose trimmed text starts with `*`, `/*` or `//` is skipped, so a literal on such a line inside a template string (for example a prompt line beginning `* claude-opus-5-5 ...`) would escape the guard. It also scans only the first model ID per line. Low risk: a prompt naming a model would be unusual, and the guard's purpose is code paths that reach a boundary. Acceptable; no action.

### NOTE 2 - `src/lib/agent/claudeCli.ts:~403-410` (orphaned comment)

After `resolvedSpawnOpts` was deleted, the "Known edge case" paragraph (personal-to-team fallback after resolution) now sits above the stream-json section header with no function beneath it. It is still accurate and worth keeping, but it should be anchored to `withAuthRetry` or `runClaudeCliOnce`. Cosmetic.

### NOTE 3 - `tests/unit/modelLiteralGuard.test.ts:30` (pattern coverage)

`MODEL_ID` is FR-15's regex and so misses legacy-order IDs such as `claude-3-5-sonnet-...`. Not a spec gap; mention only so nobody assumes the guard covers them.
