## Findings

### NOTE 1 - `src/lib/api-types.ts:268` / `src/lib/models/policy.ts` (design, for T14/T16)

`ModelsView.captionProviderIsClaude` reflects the team DEFAULT COPY row only. The server checks the draft's own `brief.copyProviderKey` (regenerate-copy) and the brief's chosen key (briefs). If a team's default is Claude but a brief uses an OpenAI key (or the reverse), the picker state and the server answer disagree, and the user sees a 400. Narrow, since API mode lets a team register OpenAI beside Claude. The client should handle `MODEL_NOT_ALLOWED` gracefully (it will, per the code), and T16 should hide the picker from the brief's selected provider where it knows it.

### NOTE 2 - `src/lib/models/policy.ts:14` (coupling)

`policy.ts` now imports `@/providers/registry` (prisma, crypto, provider SDKs) only for a boolean. It is server-only already, and the tests show no import cycle, so this is acceptable. Watch it if `policy.ts` is ever imported client-side.

### NOTE 3 - `src/app/api/briefs/route.ts:104` (cost)
