The "default outside `allowed`" case asserts only `error` is truthy. The spec says 400 and the status is asserted, so this is adequate, but it would not notice the wrong rule firing (e.g. the template-fill rule instead of rule 4). Suggestion: assert the message text, or match `/allowed/`.

### NOTE 2 - `tests/e2e/model-selection.test.ts:611` (flake surface)

TC-10 asserts the recorder holds exactly one record after each route, and TC-01/02/06 assert on all records of a surface. Under `workers: 1` this holds, but an earlier spec's fire-and-forget draft action that is still running (an async action started and not awaited) would write into the same global buffer. Passing 12/12 twice with `--retries=0` suggests it does not happen today. Suggestion: if it ever flakes in CI, filter records by `at >= <clear time>` or tag by label rather than loosening assertions.

### NOTE 3 - `tests/e2e/model-selection.test.ts:741` (DB targeting)

`testDbUrl()` guards only TC-12. The policy reset (`prisma.teamModelPolicy.deleteMany`) and the seeds in the other cases go through the shared `prisma` helper, which falls back to `process.env.DATABASE_URL` (the dev value, per the helper's own comment) if `.env.test` is missing. That is the pre-existing helper behaviour shared with every suite, so it is not new here, and no new risk is added by T12.
