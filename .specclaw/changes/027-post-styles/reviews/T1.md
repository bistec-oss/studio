## Findings

### [NOTE] tests/unit/postStylesDataset.test.ts:~228 (retired-style case) - Test quality

**Problem:** "a retired style stays resolvable but is hidden from pickers" is tautological. It builds a fixture and filters it inside the test (`Object.values(dataset).filter((s) => s.status === 'active')`), so it never calls the real `activeStyles` or `getStyle`. It would pass if both were broken.
**Suggestion:** T2 already plans the real retired-key resolver case. Until then, either drop the case or give `activeStyles`/`getStyle` a dataset parameter, as `revisionOf` has. Nothing is broken today.

### [NOTE] tests/unit/postStylesDataset.test.ts:hashOf - Design

**Problem:** the hash covers only the `StyleVersion` content (and depends on JSON key order as written). `label`, `summary`, `status` and `current` are unguarded. That fits "a released version is never edited", but the key rule's "never renamed or reused" is only partly guarded, by the key-list subset test. This is acceptable as built.

### [NOTE] src/lib/postStyles/styles.ts (end of file) - Correctness

**Problem:** the module-load `defaultImageStyleProblems` throw runs only when `NODE_ENV !== 'production'`. A bad default would reach production unnoticed, but the unit test covers it at CI. Intended per the task. No change needed.

### [NOTE] tests/unit/designDataBoundary.test.ts (new describe) and tests/unit/postStylesBoundary.test.ts - Duplication

**Problem:** both files assert "designData never imports postStyles" and both carry a purity walk. The two copies can drift. Neither plants a violating fixture for the one-way edge itself, although the matcher self-checks cover the specifier extraction.
**Suggestion:** keep one copy when T3 adds `factsCheck`.

## Verdict rationale

The migration is purely additive and reversible, and it agrees with the schema. The dataset text is verbatim, deep-frozen and hash-guarded, and the guard is proved on doctored copies. The lookups are prototype-safe and the index hides the raw record. The only findings are minor test-quality notes.
