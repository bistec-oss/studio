## Findings

### [WARN] src/lib/factsCheck/compare.ts:223-225 — Correctness (false negative; unspecified widening)

`set.amounts.add(String(v.day)); if (v.year) set.amounts.add(v.year)` means a source "15 March 2027" supports an invented bare `num:2027` or `num:15`. Verified: text "Only 2027 seats, 15 March" against source "intake 15 March 2027" is `clear`, and "2027 seats" alone would also be clear. The spec's support rule has exactly one widening (num supported by cur/pct/num). The report's reason is sound (consuming a date leaves no `num:2027` source key, so "Join us in 2027" would otherwise be a false positive), but it opens a false-negative path on the exact class the feature prevents ("2027 places", "15 spots"). Narrower fix: add only the year (not the day) to amounts, and only supports a checked `num` in 1900-2099 range; or record it explicitly as a spec amendment (it is a design change, so the user should know). Day numbers 11-31 as invented counts ("20 seats" vs source "20 June") are the more likely real-world slip.

### [WARN] tests/unit/factsCheckCorpus.test.ts:82 and :92 — Test quality (CI flake risk)

Measured 47-55 ms locally on the maximum case; the bound is 150 ms, only ~3x headroom, and one `performance.now()` sample on a shared runner (this repo's CI already hit a Chromium launch timeout) can see GC or scheduler pauses of 100 ms. The per-pattern loop (line 92) makes 22 single samples. Recommend: take the minimum of 3 runs for each measurement (a GC spike rarely hits all three) and raise to 250 ms; the linearity risk it guards (quadratic is ~250 ms at 20k per the report, and far worse at 200k sources) still fails clearly. Keep the 50 ms figure only as a recorded measurement.

### [NOTE] src/lib/factsCheck/extract.ts:103-106 — Correctness (tel catches plain 7-digit numbers)

`\d{7,15}` makes "1234567 views" a `tel`, and kind-strictness means a caption "1,234,567 users" against source "1234567" is flagged (verified), and the reverse. Safe direction (false positive), rare. Accept; mention in the handoff limits.

### [NOTE] src/lib/factsCheck/extract.ts:163 — Correctness (false negatives by design)

Not extracted: "3x faster", "10x", "5ms" (number attached to letters, spec L1), "half price", "fifty percent", "twenty thousand rupees" (L6), bare 0-10 ("9 years" is L4 but "10 free seats" too). "10x faster" is a plausible invented claim; consider a `\d+x` pattern later. Within spec; no action for T3.

### [NOTE] src/lib/factsCheck/extract.ts:28,136 — Correctness (minor mis-keys, all fail safe)

"1.299,00 €" yields `num:1.299` and `num:0` (European format not parsed; flagged unless the source is written identically). "1 299 EUR" yields `num:1` + `cur:299`. "20/11" gives two nums, not a date. "10–12 May" flags `num:10` (range start) unless sourced. Cross-script: checked "Rs 5000" (cur) vs source "රු. 5000" (num) is flagged because cur is kind-strict. All are false positives, not misses; fine.

### [NOTE] src/lib/factsCheck/sources.ts:29 — Security/defence in depth

`getActiveCampaignBriefing(campaignId)` is not team-scoped. Safe today since `campaignId` comes from the brief row of the same team, and `documents` does scope by team. No change needed.
