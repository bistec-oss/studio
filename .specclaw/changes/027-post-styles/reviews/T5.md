## Findings

### [WARN] src/app/api/campaigns/[id]/queue/[gid]/route.ts:63-74 and src/lib/campaign/queue.ts `resolveEntryStyle` — edit resets the stored style

**Problem:** PATCH with `postStyle` omitted (an API client, or any caller that sends the entry without the new field) resolves to the campaign default / General and overwrites the stored `postStyle`, goal and tone (`data: { postStyle: style.style.postStyle, ... }`). An entry created as `hiring` and edited by a pre-027 client silently becomes `general`; a null-key legacy entry gains a style and so a checklist. The schema comment says PATCH "sends the full entry", so T6's modal will be fine, but the API contract is lossy.
**Fix:** on PATCH, when `entry.postStyle` is undefined and no legacy goal is sent, keep the stored key (pass `existing.postStyle` as `style`). Add one E2E assertion.

### [WARN] tests/e2e/post-styles.test.ts:520-534 (TC-PS-21) / rerun route — AC-12 "re-run clears heldReason" is only tested through a DB-faked state

**Problem:** a held entry is COMPLETED, and the rerun route accepts only FAILED/CANCELLED, so a held entry cannot be re-run through the product. The test forces `status: 'FAILED', heldReason: ...` via Prisma, which cannot occur naturally. The clear in the rerun route is therefore near-dead code and the user's only recourse for a held entry is publishing by hand (which the held text says). The report discloses this; flag for the verify step so AC-12's wording is judged against this reality.
**Fix:** none required now; note in the verify report, or have the spec say "a held entry is published by hand".

### [NOTE] src/app/api/briefs/route.ts:235 and :245 — `explicit.imageStyle` passed to the resolver and then discarded

**Problem:** `imageStyle` is passed into `resolvePostStyle` and `imageStyle` is recomputed on the next lines from `body.imageStyle == null ? resolved.imageStyle : style.value`. The resolver input is redundant (its output is only used when absent, when the input is null anyway).
**Suggestion:** drop `imageStyle` from `explicit`.

### [NOTE] tests/e2e/post-styles.test.ts:216 (TC-PS-05) — mutates a shared per-suite campaign

**Problem:** sets `campA` default to `event`, while TC-PS-17 expects `postStyle.key === 'general'` on an entry in `campA`. It passed on four runs, so a later case must reset it, but the order dependence is implicit.
**Suggestion:** reset the default at the end of TC-PS-05, or use `campB` for the default-setting case.
