## Findings

### [WARN] src/lib/postStyles/resolve.ts:57 — Correctness (declared choice a)

`input.style ?? legacyGoalStyle(...) ?? ...` treats `""` as an explicit key, so it fails with `UNKNOWN_POST_STYLE` (400). A blank form value, an old client sending `style: ""`, or an MCP caller passing an empty string would be rejected. It also skips the legacy goal, so a pre-027 client sending `style: ""` with `goal: "hiring"` loses its mapping. This is inconsistent with the same function's own treatment of `explicit.tone` and `explicit.imageStyle` (line 80 `explicitTone ||`, line 85 `imageStyle ||`), where blank means absent.
**Fix:** `const explicitStyle = input.style?.trim() || undefined` and use it in the chain. A non-blank unknown key stays a 400, and `"  "` and `""` mean absent. Add a unit case for `""`, `"  "` and `""` plus `legacyGoal: 'hiring'`. Put the rule here, not at each caller, so T4/T5 cannot diverge.
