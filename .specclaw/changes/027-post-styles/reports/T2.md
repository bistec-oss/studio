## Ambiguities and choices

- Fixture dataset access: `resolvePostStyle`, `getStyle`, `activeStyles`, `rulesAtStamp` and `checklistPromptText` take an optional trailing `source` param. Production callers never pass it. It is the only way to run the retired-key case through the real resolver.
- The tautological retired-style case (T1 review NOTE 1) is replaced, not deleted: it now calls the real `activeStyles(dataset)` and `getStyle(key, dataset)`. The resolver retired-key cases are in `postStylesResolve.test.ts`.
- `style` of `''` is not treated as absent (design uses `??`): it is an unknown key. Callers must send null/undefined for "none".
- `rulesAtStamp` returns `null` (not `[]`) when the stamp does not resolve, so T4 can warn once and pass no rules.
- The resolver's `key` is typed `string` (the dataset key may be a fixture key), not `PostStyleKey`.
- Size-support uses `imageStyleOptions(aspectRatio)`; a key absent from that list gives `default-unavailable`, a listed but unsupported one gives `size-classic`.
- One-resolver guard: import check was already in T1; T2 adds the key-literal check (`case 'x':`, a quoted key, or two or more bare style keys as properties in one file). It passes on all of `src/` outside `postStyles`. Planted-fixture assertions prove it can fail.

## Orchestrator follow-up (review WARN)

`reviews/T2.md` WARN (a): an empty-string `style` was an unknown key (400), so a blank form value or an old client sending `""` would break, and it skipped the legacy-goal mapping. Fixed in `resolve.ts`: `const explicitStyle = input.style?.trim() || undefined`, so a blank or whitespace style is absent (like a blank tone or image style) and a non-blank unknown key is still `UNKNOWN_POST_STYLE`. New unit case per surface: `''` and `'   '` resolve to `general`; `''` with `legacyGoal: 'hiring'` resolves to `hiring`. The orchestrator's gate re-run is in the commit (tsc, lint, unit).
